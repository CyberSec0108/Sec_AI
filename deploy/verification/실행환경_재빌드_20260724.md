## 1. 재빌드 사유와 조치

IMP-048에서 가이드 검색 저장소를 Milvus가 아닌 PostgreSQL+pgvector로 확정했다. 실행 중인 PostgreSQL image와 기존 migration 상태가 새 source 정의와 달라질 수 있으므로 전체 Core image를 다시 빌드하고 9개 서비스를 재생성했다.

PostgreSQL wrapper는 `pgvector/pgvector:0.8.2-pg18-bookworm`의 잠긴 linux/amd64 digest를 사용한다. 기존 named volume은 삭제하거나 초기화하지 않았고 `0006_imp048` migration만 전진 적용했다.

재기동 후 합성자료 2개 chunk를 실제 runtime role로 검색해 조직·가이드·version·scope 필터, raw vector 직접 조회 차단과 실제 KISA 원문 미적재 상태를 확인했다.

추가 감사에서 사용하지 않는 PyMilvus가 `ingestion.in`과 개발 잠금 파일에 남아 있음을 확인했다. 직접 의존성을 제거하고 Python 3.14.6 잠긴 builder에서 `ingestion.lock`·`dev.lock`과 SHA-256 기준선을 재생성한 뒤 개발 검증 image도 다시 빌드했다.
