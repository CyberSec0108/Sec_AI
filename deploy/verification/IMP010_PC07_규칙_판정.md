## 1. 이번 단계에서 결정하는 것

PC-07은 단순히 컴퓨터에서 보이는 모든 파일시스템 문자열을 `NTFS`와 비교하면 안 된다. Windows 11의 정상 EFI System Partition은 FAT32이고, DVD는 UDF일 수 있으며, 이동식·복구용 매체도 함께 열거될 수 있기 때문이다.

이번 단계는 다음 질문에 대한 기준을 먼저 고정한다.

1. 어떤 volume을 실제 점검 대상으로 볼 것인가?
2. 어떤 partition과 장치를 정상적인 제외 대상으로 볼 것인가?
3. ReFS, VHD/VHDX, Storage Spaces와 BitLocker를 어떻게 처리할 것인가?
4. 수집 실패와 비-NTFS 위반을 어떻게 구분할 것인가?
5. 이후 Audit Pack과 Fixture가 어떤 결과를 반환해야 하는가?

이 문서는 판정 규칙의 승인 기록이다. 실제 Audit Pack source는 `IMP-011`, 합성 Fixture는 `IMP-012`, pure rule operator는 그 이후 단계에서 구현한다.

> 평가 대상으로 선정된 고정 volume이 모두 NTFS이면 PASS, 하나라도 비-NTFS이면 FAIL

IMP-010은 이 기존 승인 방향을 유지하되, 정상 EFI·복구·광학·이동식 장치를 평가 집합에서 먼저 제외해 오탐을 방지한다.

## 3. 쉬운 판정 요약

PC-07은 건물에 있는 모든 문을 검사하는 것이 아니라, 사람이 실제 자료를 보관하는 방의 문만 검사하는 것과 같다.

- EFI와 복구 partition은 건물의 기계실에 해당하므로 일반 자료실 검사에서 제외한다.
- Windows가 설치된 `C:`와 실제 고정 데이터 volume은 자료실이므로 검사한다.
- 검사 대상 자료실이 모두 NTFS이면 `PASS`다.
- 검사 대상 중 하나라도 FAT32, exFAT, ReFS 등 NTFS가 아닌 것으로 확인되면 `FAIL`이다.
- 파일시스템을 읽지 못했다면 위반으로 추측하지 않고 `ERROR`다.

## 4. 평가 집합 결정

규칙은 수집된 전체 volume을 먼저 분류한 뒤 `evaluated_volumes`와 `excluded_volumes`를 별도로 만든다. 제외 사유도 증적에 남겨야 한다.

### 4.1 기본 포함 대상

| 대상 | 처리 | 이유 |
|---|---|---|
| Windows OS volume | 포함 | PC-07의 핵심 대상 |
| online 로컬 고정 데이터 volume | 포함 | 사용자·업무 파일을 지속적으로 저장할 수 있음 |
| 드라이브 문자가 없고 폴더 경로에 mount된 고정 volume | 포함 | 드라이브 문자가 없다는 이유만으로 데이터 volume을 누락하면 안 됨 |
| attached·online VHD/VHDX의 사용 가능한 volume | 포함 | Windows에서 물리 디스크처럼 사용 가능한 활성 데이터 위치 |
| Storage Spaces 위에 만들어진 논리 volume | 포함 | 파일은 물리 pool disk가 아니라 논리 volume에 저장됨 |
| BitLocker 적용 volume | 포함 | 암호화 사용 여부와 NTFS 여부는 별개의 점검 조건 |
| 외장 장치이지만 Windows가 고정·비이동식으로 식별한 online volume | 포함 | USB bus라는 이유만으로 자동 제외하지 않음 |

### 4.2 기본 제외 대상

| 대상 | 제외 판별 기준 | 제외 사유 코드 |
|---|---|---|
| EFI System Partition | GPT partition type 등 신뢰 가능한 시스템 partition 식별값 | `EXCLUDED_EFI_SYSTEM_PARTITION` |
| Microsoft Reserved Partition | GPT MSR type | `EXCLUDED_MICROSOFT_RESERVED` |
| Windows Recovery/WinRE partition | Recovery GPT type와 Windows recovery 식별정보 | `EXCLUDED_WINDOWS_RECOVERY` |
| 승인된 OEM 진단·복구 utility partition | partition role·type으로 입증된 경우만 | `EXCLUDED_OEM_UTILITY` |
| 광학 매체 | `DriveType`이 CD-ROM/DVD 계열 | `EXCLUDED_OPTICAL` |
| 이동식 매체 | Windows가 removable media로 명시한 경우 | `EXCLUDED_REMOVABLE` |
| network drive | 로컬 disk volume이 아닌 network drive | `EXCLUDED_NETWORK` |
| detached VHD/VHDX 파일 | 현재 attach되지 않아 활성 volume이 아님 | `EXCLUDED_DETACHED_DISK_IMAGE` |
| 명시적으로 식별된 RAM disk | 재부팅 후 유지되는 고정 저장소가 아님 | `EXCLUDED_VOLATILE_RAM_DISK` |

다음 값 하나만으로는 제외하지 않는다.

- 드라이브 문자가 없음
- volume label에 `Recovery`, `System` 같은 단어가 있음
- partition이 숨김 상태임
- bus type이 단순히 `USB`임
- volume 크기가 작음

이런 휴리스틱만으로 제외하면 실제 데이터 volume을 숨겨 `PASS`로 만드는 문제가 생길 수 있다. 신뢰 가능한 partition role을 확인하지 못한 후보가 판정 결과에 영향을 주면 `EVIDENCE_INCOMPLETE`인 `ERROR`로 처리한다.

## 5. 파일시스템 판정 규칙

평가 집합이 완전하게 만들어진 뒤에만 다음 규칙을 실행한다.

```text
IF 필수 수집 오류 또는 분류 불능 후보가 존재
    THEN ERROR
ELSE IF evaluated_volumes가 비어 있음
    THEN ERROR
ELSE IF 모든 evaluated_volumes.file_system == "NTFS"
    THEN PASS
ELSE
    THEN FAIL
```

비교 전 파일시스템 이름은 앞뒤 공백 제거와 대소문자 정규화만 수행한다. 의미가 다른 문자열을 NTFS로 치환하지 않는다.

| 관찰값 | 결과 | 대표 result code |
|---|---|---|
| 모든 평가 volume이 `NTFS` | `PASS` | `ALL_EVALUATED_VOLUMES_NTFS` |
| `FAT`, `FAT32`, `exFAT`, `UDF` 등 명시된 비-NTFS 존재 | `FAIL` | `NON_NTFS_VOLUME_FOUND` |
| `ReFS` 존재 | `FAIL` | `NON_NTFS_REFS_FOUND` |
| 데이터 volume이 명시적으로 `RAW` 상태 | `FAIL` | `NON_NTFS_RAW_VOLUME_FOUND` |
| 파일시스템 값 누락·조회 불능 | `ERROR` | `VOLUME_FILESYSTEM_UNAVAILABLE` |
| 후보 volume의 포함·제외 분류에 필요한 값 누락 | `ERROR` | `VOLUME_CLASSIFICATION_INCOMPLETE` |
| 평가 volume이 0개 | `ERROR` | `NO_EVALUATED_VOLUME` |
| Probe timeout·권한 부족·파싱 실패 | `ERROR` | `VOLUME_COLLECTION_FAILED` |

`result_code`는 규칙의 상세 원인이고, Finding의 `error_codes`는 현재 공통 Schema가 허용한 `EVIDENCE_INCOMPLETE`, `PERMISSION_DENIED`, `PROBE_TIMEOUT`, `PARSE_FAILED` 등을 사용한다.

## 6. Edge case 확정안

### 6.1 ReFS

Microsoft는 ReFS를 데이터 무결성·복원력·대규모 저장과 가상화 같은 용도를 위한 현대적 파일시스템으로 설명하며 ACL과 BitLocker 등 여러 보안 기능을 지원한다. 따라서 ReFS 자체를 오래되거나 취약한 파일시스템이라고 표현하면 안 된다.

그러나 KISA PC-07은 양호 조건을 `NTFS`로 특정하고, 이미 승인된 MVP Control Matrix도 하나 이상의 비-NTFS를 `FAIL`로 정했다. 따라서 MVP 기본 규칙에서는 ReFS를 `FAIL`로 처리한다.

이 결과의 뜻은 **ReFS에 보안 취약점이 있다는 뜻이 아니라 KISA PC-07의 NTFS 일치 조건을 충족하지 않았다는 뜻**이다. 기관이 특정 ReFS 사용을 허용하더라도 Finding은 임의로 `PASS`로 바꾸지 않고 별도 위험 수용 또는 향후 versioned 적용성 정책으로 기록한다.

### 6.2 VHD/VHDX

Microsoft 문서상 attached VHD는 Disk Management에서 물리 디스크처럼 보이고 사용할 수 있다. 따라서 다음처럼 처리한다.

- attached, online이고 사용 가능한 논리 volume이면 기본 평가 대상이다.
- NTFS이면 다른 고정 volume과 동일하게 평가한다.
- ReFS·FAT32 등 비-NTFS이면 `FAIL`에 기여한다.
- detached VHD/VHDX 파일은 현재 활성 volume이 아니므로 열거나 mount하지 않고 제외한다.
- Collector는 VHD 파일 경로 전체를 불필요하게 수집하지 않는다. `is_virtual`, disk image type과 안정 식별자만 정규화한다.

### 6.3 Storage Spaces

Storage Spaces는 여러 physical disk를 pool로 묶고 그 위에 virtual disk와 volume을 만든다. PC-07은 파일이 저장되는 최상위 논리 volume을 한 번만 평가한다.

- pool을 구성하는 physical disk 각각을 중복 평가하지 않는다.
- 논리 volume이 NTFS이면 `PASS` 조건을 충족한다.
- 논리 volume이 ReFS 또는 다른 비-NTFS이면 `FAIL`에 기여한다.
- 논리 volume metadata를 얻지 못하면 underlying physical disk의 값으로 추측하지 않고 `ERROR`다.

### 6.4 BitLocker

BitLocker는 volume 암호화이고 NTFS는 파일시스템이므로 서로 대체하지 않는다.

- BitLocker가 켜져 있어도 해당 volume을 제외하지 않는다.
- 신뢰 가능한 metadata로 underlying filesystem이 NTFS임을 확인할 수 있으면 정상 평가한다.
- locked 상태 등으로 filesystem을 확인할 수 없으면 `PASS`나 `FAIL`로 추측하지 않고 `ERROR`다.

### 6.5 정상 EFI FAT32

Microsoft의 Windows 11 UEFI/GPT partition 지침은 EFI System Partition을 FAT32로 포맷하도록 요구한다. 따라서 EFI FAT32는 PC-07 실패 volume이 아니라 제외 대상이다.

다만 이름이나 크기만 보고 EFI로 추정해서는 안 된다. GPT type 등 partition identity로 확인돼야 한다.

## 7. 판정 단위와 출력 계약

MVP PC-07은 자산마다 평가 대상 volume 집합을 한 번에 판정한다.

| 필드 | 값 |
|---|---|
| `subject.scope` | `VOLUME` |
| `subject.subject_key` | `pc07:evaluated-volume-set` |
| applicability | `APPLICABLE` |
| PASS 조건 | 평가 대상 전부 NTFS, 필수 증적 완전 |
| FAIL 조건 | 평가 대상 중 명시된 비-NTFS 하나 이상 |
| ERROR 조건 | 필수 수집·파싱·분류·filesystem 확인 실패 |

개별 volume의 판정 근거는 aggregate 출력 안에 안정적인 volume ID 순으로 정렬해 남긴다. 이후 UI는 위반 volume 목록을 보여줄 수 있지만 공식 aggregate Finding을 임의로 다시 계산하지 않는다.

PC-07에서는 `평가 volume이 없다`는 이유로 `N/A`를 만들지 않는다. Windows 11 자산인데 평가할 OS·고정 volume이 하나도 확인되지 않았다면 수집 또는 분류가 불완전한 것이므로 `ERROR`다. `REVIEW`도 기본 규칙에 사용하지 않는다. 조직 예외는 Finding 상태 변경이 아니라 별도 승인 record로 관리한다.

## 8. 최소 정규화 증적

Collector와 normalizer는 최소한 다음 정보를 제공해야 한다. 정확한 JSON field 이름과 Schema는 `IMP-011`에서 고정한다.

| 구분 | 최소 정보 |
|---|---|
| volume identity | 안정적인 volume ID, object/unique ID |
| mount | drive letter 또는 mount path 존재 여부 |
| filesystem | filesystem 이름, 조회 성공 여부 |
| volume state | drive type, health·operational state, read-only·offline 여부 |
| partition identity | disk·partition 번호, GPT/MBR type, system·boot·hidden flag |
| disk identity | local/virtual 구분, bus type, removable 여부 |
| special role | EFI, MSR, Recovery, OEM utility, Storage Spaces logical volume, attached VHD 여부 |
| collection | Probe ID·version, 실행 권한, 시작·종료 시각, 오류 코드 |

개인정보와 경로 과수집을 막기 위해 volume label, 파일 목록과 VHD 원본 경로는 PC-07 필수 증적에 포함하지 않는다. 전체 파일 내용도 읽지 않는다.

## 9. 수집 권한 결정

PC-07의 기본 권한은 기존 Control Matrix대로 일반 사용자다. Collector는 읽기 전용 Windows Storage/CIM 정보를 먼저 수집한다.

- 관리자 권한 없이 필수 정보가 모두 수집되면 추가 상승을 요청하지 않는다.
- 권한 부족은 `FAIL`이 아니라 `ERROR(PERMISSION_DENIED)`다.
- 관리자 fallback이 필요하다는 이유로 Collector가 자동으로 권한 상승하거나 설정을 변경하지 않는다.
- 실제 Windows 11 기준 이미지에서 일반 사용자와 별도 상승 실행을 비교하는 권한 시험은 `IMP-012` 이후 Collector 단계에서 고정한다.

## 10. 필수 Fixture 기대값

| Fixture ID | 구성 | 기대 결과 |
|---|---|---|
| `pc07-pass` | OS NTFS + 고정 데이터 NTFS | `PASS` |
| `pc07-fail-fat32` | 평가 대상 고정 데이터 FAT32 포함 | `FAIL` |
| `pc07-fail-exfat` | 평가 대상 고정 데이터 exFAT 포함 | `FAIL` |

| `pc07-error-filesystem-unknown` | 평가 후보 filesystem 조회 불능 | `ERROR` |
| `pc07-error-no-evaluated-volume` | 완전한 평가 집합을 만들지 못함 | `ERROR` |
| `pc07-excluded-efi` | OS NTFS + EFI FAT32 | `PASS`, EFI 제외 근거 포함 |
| `pc07-excluded-recovery` | OS NTFS + Recovery partition | `PASS`, Recovery 제외 근거 포함 |
| `pc07-edge-refs` | 평가 대상 ReFS volume | `FAIL` |
| `pc07-edge-vhd-ntfs` | attached online VHDX의 NTFS volume | `PASS` |
| `pc07-edge-vhd-fat32` | attached online VHDX의 FAT32 volume | `FAIL` |
| `pc07-edge-vhd-detached` | detached VHDX 파일만 존재 | 기존 평가 volume 결과 유지, 파일을 열지 않음 |
| `pc07-edge-storage-spaces-ntfs` | Storage Spaces 논리 NTFS volume | `PASS` |
| `pc07-edge-storage-spaces-refs` | Storage Spaces 논리 ReFS volume | `FAIL` |
| `pc07-edge-bitlocker-ntfs` | filesystem 확인 가능한 BitLocker NTFS | `PASS` |
| `pc07-edge-bitlocker-locked` | filesystem 확인 불가 | `ERROR` |
| `pc07-edge-mounted-folder` | drive letter 없이 폴더에 mount된 NTFS | `PASS` |

각 Fixture는 평가 대상 목록, 제외 목록, 제외 사유, 결과 코드와 deterministic output hash를 검증한다.

## 11. 결정론·안전 요구사항

- volume 순서는 입력 순서가 아니라 안정 ID 기준으로 정렬한다.
- 동일 정규화 입력과 동일 Audit Pack version은 byte-equivalent canonical 결과를 만든다.
- 제외된 volume도 ID, 관찰된 종류와 제외 reason code를 남겨 감사자가 누락 여부를 확인할 수 있게 한다.
- 파일시스템을 변경하는 `convert`, `format`, ACL 수정 명령은 실행하지 않는다.
- `FAIL`은 자동 조치 명령이 아니다.
- AI 설명은 결과를 바꿀 수 없다.
- 부분 증적으로 `PASS`를 생성하지 않는다.

## 12. 구현 시 필요한 식별 상수

최소한 다음 Windows 식별값은 이름 문자열이 아니라 상수로 시험한다.

| 역할 | 식별값 |
|---|---|
| EFI System Partition | GPT type `C12A7328-F81F-11D2-BA4B-00A0C93EC93B` |
| Microsoft Reserved | GPT type `E3C9E316-0B5C-4DB8-817D-F92DF00215AE` |
| Windows Recovery | GPT type `DE94BBA4-06D1-4D40-A16A-BFD50179D6AC` |

MBR·OEM 특수 partition은 별도 명시 상수와 Fixture가 없으면 임의 제외하지 않는다. 알려지지 않은 type을 자동으로 안전하다고 간주하지 않는다.

## 15. 승인 결과와 후속 구현

사용자는 `IMP-011 단계까지 진행` 지시로 위 `PC07-D01`~`PC07-D09` 권장안을 승인했다.

1. `IMP-011`에서 PC-07 Audit Pack source와 정규화 evidence 요구사항을 작성한다.
2. `IMP-012`에서 위 17개 Fixture와 기대 결과를 실행 가능한 JSON으로 만든다.
3. Schema가 현재 결정을 표현하지 못하면 code 작성 전에 최소 versioned Schema 변경안을 낸다.

이 결정 기록의 승인은 Audit Pack release 승인이 아니다. PC-07 개발 Pack은 `DRAFT`로 만들며 PC-01~18 전체, Fixture, 검토자와 서명 Gate를 통과하기 전에는 `APPROVED` Pack으로 배포하지 않는다.
