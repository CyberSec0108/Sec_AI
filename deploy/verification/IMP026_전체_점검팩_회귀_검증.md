## 1. 구현 결과

최종 `pack-0.6.0.json`은 PC-01부터 PC-18까지 숫자 순서로 정확히 한 번씩 포함한다. IMP-026은 단계별 Pack을 다시 합치거나 기존 기준을 변경하지 않고, 이 최종 DRAFT Pack을 단일 실행 기준으로 고정했다.

`fixtures/full_pack/coverage.json`은 계정·서비스·PC-07·패치·Endpoint 보호·사용자/미디어/원격지원 Fixture 위치, 기대 Control과 사례 수, 상태 분포와 100회 반복 횟수를 고정한다. 통합 실행기는 다음을 모두 확인한다.

- Pack 버전과 승인 상태가 정확히 `0.6.0 DRAFT`
- PC-01~18 누락·중복·순서 변경 없음
- 92개 case ID가 전역에서 중복되지 않음
- 각 Control에 적어도 한 개 이상의 합성 사례가 있음
- Pack의 `pass`, `fail`, `error`, 선택적인 `review`, `not_applicable` 참조가 실제 사례와 상태에 일치
- 92개 사례의 규칙 결과 status·result code가 기존 기대 oracle과 일치

## 2. 결정론 회귀

92개 결과를 Control 번호와 case ID 순으로 고정하고 RFC 8785 JSON canonicalization 후 SHA-256을 계산한다. 같은 입력을 100회 전부 다시 판정해 고유 지문이 하나인지 검사한다. 실행 시각, DB, Queue와 외부 네트워크는 입력에 포함하지 않는다.

이 회귀는 “같은 기준과 같은 자료면 항상 같은 결과”를 확인한다. 보안 기준이 옳다는 운영 승인이나 실제 PC 상태가 양호하다는 의미는 아니다.

## 4. Fail-closed 경계

- 중복 Control, 누락 Control, 숫자 순서 차이를 허용하지 않는다.
- 존재하지 않거나 다른 Control·상태를 가리키는 Fixture 참조를 허용하지 않는다.
- PC-07 input과 expected 파일명이 정확히 짝을 이루지 않으면 거부한다.
- 기존 기대값과 실제 status 또는 result code가 다르면 통합 회귀를 실패시킨다.
- 100회 중 한 번이라도 전체 결과 지문이 달라지면 실패시킨다.
- 수집 실패 `ERROR`, 조직 기준 보류 `REVIEW`, 적용 제외 `N/A`를 임의의 PASS/FAIL로 합치지 않는다.
- Pack은 계속 `DRAFT`이며 운영 공식 Finding에 사용할 수 없다.
