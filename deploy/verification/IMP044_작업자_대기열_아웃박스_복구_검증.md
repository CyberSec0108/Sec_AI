## 1. 구현 범위

IMP-044는 Redis와 Celery의 내부 상태를 업무 정본으로 사용하지 않는다. 다음 네 상태를 PostgreSQL에 보존한다.

| 테이블 | 역할 |
|---|---|
| `workflow_steps` | Job의 현재 처리 단계와 최종 상태 |
| `outbox_events` | DB 저장 뒤 Redis에 보내야 하는 이벤트 |
| `task_executions` | 실행 시도, Worker 손실과 기존 결과 반환 이력 |
| `workflow_results` | 논리 작업별 하나만 허용하는 최종 결과 |

Queue message는 Job·Asset·단계·입력 version·멱등 key·상관 ID처럼 서버가 다시 조회하는 데 필요한 식별자만 담는다. 원본 증적, 레지스트리 값, PowerShell 출력, 비밀번호, token과 공식 Finding은 싣지 않는다.

## 2. 실제 장애·복구 시나리오

검증은 오류를 흉내 내는 상태값만 바꾸지 않고, 실행 중인 유지보수 Worker의 정확한 자식 프로세스를 실제로 종료했다.

```text
PostgreSQL에 Job·Step·Outbox를 한 transaction으로 기록
  → Redis에는 발행했지만 Outbox 발행 완료 표시는 하지 않음
  → Maintenance Worker가 첫 번째 시도 시작
  → 그 작업을 수행 중인 자식 PID만 SIGKILL
  → late ACK·reject_on_worker_lost에 따라 같은 작업 재전달
  → PENDING Outbox를 다시 발행
  → 이미 완료된 중복 전달은 기존 결과를 반환
```

최종 관측값은 다음과 같다.

```text
Outbox 발행 시도: 2
Task 실행 시도: 3
Worker 손실 기록: 1
논리 결과: 1
중복 결과: 0
공식 Finding 변화: 0
```

동일 Celery delivery ID가 Worker 손실 뒤 재전달될 수 있으므로 delivery ID 자체에는 고유 제약을 두지 않는다. 중복 방지는 논리 작업의 `idempotency_key`와 PostgreSQL 결과 고유 제약이 담당한다.

## 3. Outbox와 멱등성 경계

- Job·Step·Outbox 생성은 한 PostgreSQL transaction에서 처리한다.
- Redis 발행 후 Outbox 상태 기록 전에 중단되어도 PENDING event를 다시 찾을 수 있다.
- 재발행은 중복 delivery를 만들 수 있으므로 “정확히 한 번 전달”을 주장하지 않는다.
- Worker는 시작할 때 Job·Asset·단계·입력 version의 exact binding을 다시 검사한다.
- 이미 최종 결과가 있으면 업무 부작용을 반복하지 않고 `RETURN_EXISTING`으로 기록한다.
- `workflow_results`는 논리 작업별 결과 한 건만 허용한다.
- Task 오류·Worker 손실·복구 시험 결과를 보안 취약 `FAIL`이나 공식 Finding으로 바꾸지 않는다.

## 5. 공개 화면과 내부 도구

개발 환경에서만 `/ui/queue-recovery`와 읽기 전용 `/api/v1/queue-recovery/status`를 제공한다. 공개 응답은 다음만 보여준다.

- 쉬운 복구 상태
- 전체 처리 시도 횟수
- Worker 손실 횟수
- 최종 결과와 중복 결과 개수
- 설정 변경·공식 Finding·원본 message 노출 여부

Job ID, Outbox ID, delivery ID, Worker PID, 원본 payload와 오류 stack은 공개 응답에 포함하지 않는다. 작업 준비·발행·자식 종료 명령은 HTTP로 공개하지 않고 컨테이너 내부 검증 CLI에만 둔다.

실제 HTTP 응답:

```json
{
  "status": "SUCCEEDED",
  "status_label": "복구 확인 완료",
  "outbox_status": "PUBLISHED",
  "attempt_count": 3,
  "worker_lost_count": 1,
  "result_count": 1,
  "duplicate_result_count": 0,
  "settings_modified": false,
  "official_finding_created": false,
  "raw_payload_exposed": false
}
```

앱 브라우저 연결 목록이 비어 있어 스크린샷 기반 시각 검증은 수행하지 못했다. 다른 브라우저 자동화로 우회하지 않았고 UI 계약 시험, CSS 계약과 실제 HTTP 200 응답을 검증했다.
