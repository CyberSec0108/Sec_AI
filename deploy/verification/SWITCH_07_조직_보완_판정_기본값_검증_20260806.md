# SWITCH-07 조직 보완 판정 기본값 검증

> 후속 `SWITCH-08`에서 장비 직접 수집을 18개 고정 GET으로 확대했다. 현재 조직 보완
> 판정은 N-12·N-17 두 개만 유지하며 benchmark는 `0.4.0-DRAFT`다. 이 문서의 11개 입력과
> `0.3.0-DRAFT` 수치는 당시 검증 이력으로 보존한다.

## 1. 목적

AOS-CX REST만으로 확정하지 못하는 11개 N 항목에 회사·기관이 사용할 기본 판정값을
제공하고, 사용자가 점검 전에 변경할 수 있게 한다. 장비에서 읽지 않은 값을 REST 수집값으로
표현하거나 기존 확인값을 덮어쓰지 않는다.

## 2. 대상 항목과 기본값

다음 항목에 닫힌 구조의 `조직 보완 판정값`을 추가했다.

- 조직·운영 증적: N-04, N-05, N-12, N-13, N-17, N-23
- 추가 Adapter 대상: N-10, N-16, N-21, N-25
- SNMP 접근 제한: N-19

11개 기본값은 모두 `PASS(충족)`이며 사용자는 `PASS/FAIL/REVIEW/N/A` 중 하나로 변경할 수
있다. 이 기본값은 실제 장비 증적이 아니라 개발용 조직 입력값이다. 명령·정규식·자유형
문장·JSON·SQL은 입력할 수 없다.

## 3. 판정 경계

- 장비 REST 규칙이 PASS·FAIL·N/A를 확정한 항목에는 조직 입력값을 적용하지 않는다.
- 장비값만으로 REVIEW인 11개 항목에만 선택한 조직 보완 판정값을 적용한다.
- Criteria Profile이 없는 내부 평가 경로는 기존처럼 REVIEW를 유지한다.
- `observed_summary`와 REST Evidence는 조직 입력 전후 동일하다.
- 조직 입력 적용 결과는 result code의 `_ORGANIZATION_INPUT`으로 내부 추적하고,
  결과 화면 상단 안내와 판정 이유에서 장비 수집값이 아님을 설명한다. 사용자 후속
  지시에 따라 항목 카드의 별도 `판정 출처` 행은 표시하지 않는다.
- 결과에는 11개 입력 snapshot, 실제 적용 개수·항목, criteria SHA-256을 함께 저장한다.
- 기존 append-only 결과는 변경하지 않는다.

따라서 안전 합성 projection은 장비값만 평가하면 PASS 19·REVIEW 11·N/A 8이고, 기본 조직
입력을 함께 실행하면 PASS 30·REVIEW 0·N/A 8이다. 이는 30개 장비 설정을 직접 확인했다는
뜻이 아니며 11개는 조직 입력 판정이다.

## 4. UI

- 기존 26개 `안전 기준`과 별도로 11개 `조직 보완 판정값` 영역을 제공한다.
- 기본값은 모두 충족으로 표시하되 장비 수집값이 아니라는 경고를 함께 표시한다.
- 회사·기관 증적에 맞게 점검 전에 수정하거나 기본값으로 되돌릴 수 있다.
- 브라우저 보존 key를 v2로 분리하고 실행 요청의 exact 37개 값으로 서버에서 재검증한다.
- 결과 상단에는 저장한 조직 판정 11개와 실제 적용 개수를 표시한다.
- 각 결과 카드는 장비 REST 확인값과 판정 이유를 표시한다. 별도 `판정 출처` 행은
  제거했지만 조직 입력 적용 여부는 상단 안내·판정 이유·내부 결과 코드에 보존한다.

## 7. 남은 작업

- 기존 화면 결과에는 소급 적용하지 않는다. 현재 credential로 새 점검을 실행해야
  `0.3.0-DRAFT` 결과가 생성된다.
- 현재 브라우저 기본값은 승인된 조직 Profile이나 공식 증적이 아니다.
- 운영 승격 시에는 조직 승인자·유효기간·첨부 증적 hash·변경 감사와 서명이 추가로 필요하다.
