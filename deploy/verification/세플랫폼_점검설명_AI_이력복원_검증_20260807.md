# 세 플랫폼 점검 설명·AI 이력 복원 검증 — 2026-08-07

## 1. 검증 범위

- Windows PC-01~18 공식 표시 설명과 실제 AI 설명 입력의 기본 snapshot 포함
- Windows 관리자 결과와 AI 완성 화면의 append-only PostgreSQL version 저장
- 같은 organization·owner login에서 서버 우선 복원, 다른 로그인 차단
- Linux 중앙·one-shot U-01~U-67 공식 설명·AI 입력의 결과 hash 포함
- Switch N-01~N-38 공식 설명·AI 입력의 결과 hash 포함
- Linux `V4`, Switch `V2` 기존 AI output의 통합 상세 복원
- 제한 Markdown과 비식별 projection 유지, 규칙 상태·공식 Finding 불변

## 2. 변경 계약

`0033_windows_presentations`는 `windows_audit_presentations`를 추가한다. 한 Windows 기본
snapshot 아래 `ADMINISTRATOR`, `AI_COMPLETED` 종류별 version과 payload hash를 저장한다.
동일 payload replay는 기존 row를 반환하고 내용이 달라질 때만 새 version을 추가한다.

Table은 organization·owner user RLS를 강제하고 runtime role에 `SELECT`, `INSERT`만 부여한다.
UPDATE·DELETE·TRUNCATE는 trigger가 거부한다. Presentation은 composite foreign key로 같은
owner의 Windows snapshot에만 연결된다.

Linux·Switch는 별도 중복 table을 만들지 않는다. 새 run의 불변 `result_json` 안에
`official_explanations`, `ai_explanation_inputs`를 포함한 뒤 `result_sha256`을 다시 계산한다.
기존 run은 append-only 원본을 바꾸지 않고 상세 조회 시 같은 projection을 구성한다.

비로그인 presentation GET은 HTTP `401`로 차단됐다.

## 4. 유지한 경계

- 공식 설명은 해당 규칙 엔진 상태의 표시 정본이지 운영 승인 Pack이나 공식 Finding이 아니다.
- AI 입력에는 비식별 projection만 들어가며 원시 출력·credential·비밀번호는 저장하지 않는다.
- AI 출력이 규칙 상태, 실제 확인값, 기준 hash, Finding을 변경하지 않는다.
- Windows `localStorage`는 서버 저장 실패 시 현재 브라우저 fallback일 뿐 정본이 아니다.
- 동일 조직의 관리자도 다른 owner user 결과를 자동 열람하지 않는다.
