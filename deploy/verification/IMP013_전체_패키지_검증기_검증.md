## 1. 구현 결과

`IMP-009`의 ZIP 안전검사와 hash inventory 비교를 그대로 재사용하고 다음 Gate를 하나의 fail-closed 순서로 결합했다.

1. descriptor strict UTF-8 JSON·Audit Package Schema
2. 서버 발급 Manifest Schema·RFC 8785 content hash·서명 검증 증명
3. Manifest 유효시간·Job·Asset·endpoint·nonce reservation
4. Manifest가 줄인 archive size·해제 size·file count 제한
5. staging object의 organization·asset·job·exact SHA-256·size binding
6. exact archive SHA-256에 연결된 ClamAV 결과와 secret·과수집 검사 결과
7. ZIP path·type·compression·resource와 archive/file/content-set hash 전수 비교
8. embedded Manifest 전체 문서와 서버 발급본의 canonical 일치
9. submission profile·인증 종류·Collector version/release channel
10. Manifest가 허용한 Probe version·Control과 evidence/error inventory binding

성공 결과는 `ValidatedPackage`이며 original 승격 후보라는 의미만 가진다. 이 모듈은 공식 Finding을 생성하지 않는다. 실패·확인 불가·digest/scope 불일치는 모두 `PackageValidationError`로 접수를 중단한다.

## 3. 외부 제품 책임 경계

이 단계는 DB·Queue·network 없는 pure validator다. 다음 기능을 흉내 내거나 성공으로 가정하지 않는다.

- 실제 인증서 chain·전자서명 검증
- PostgreSQL의 nonce 원자적 예약·재사용 차단
- 실제 ClamAV scan
- 금지 secret·과수집 detector
- AIStor staging HEAD·original PUT·Object Lock

각 Adapter는 상태뿐 아니라 검증한 nonce 또는 SHA-256과 scope가 포함된 immutable verification을 전달해야 한다. `FAILED`, `UNAVAILABLE` 또는 다른 digest에 대한 결과는 모두 거부한다. 실제 제품 연동은 후속 application E2E와 integration Gate에서 검증한다.

## 4. 안정 오류 분류

| 분류 | 대표 코드 |
|---|---|
| Schema·의미 | `DESCRIPTOR_SCHEMA_INVALID`, `MANIFEST_SCHEMA_INVALID`, `MANIFEST_SEMANTIC_INVALID` |
| Manifest·scope | `MANIFEST_HASH_MISMATCH`, `MANIFEST_EXPIRED`, `MANIFEST_SCOPE_MISMATCH` |
| nonce·인증 | `NONCE_REPLAYED`, `NONCE_CHECK_UNAVAILABLE`, `PACKAGE_AUTHENTICATION_INVALID` |
| staging·scan | `STAGING_UNAVAILABLE`, `MALWARE_DETECTED`, `MALWARE_SCAN_UNAVAILABLE` |
| content policy | `CONTENT_POLICY_FAILED`, `CONTENT_POLICY_UNAVAILABLE` |
| binding | `ATTESTATION_BINDING_MISMATCH`, `EVIDENCE_SCOPE_MISMATCH` |
| archive·inventory | IMP-009의 `PATH_TRAVERSAL`, `HASH_MISMATCH`, `FILE_MISSING` 등 |

Package 거부는 PC-07의 `FAIL`이나 `ERROR` Finding으로 바꾸지 않는다. 공식 판정은 Package가 모든 Gate를 통과한 뒤 후속 규칙 엔진에서만 시작한다.
