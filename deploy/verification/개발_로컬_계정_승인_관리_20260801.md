# DEV-LOCAL 계정 생성 승인·계정 관리 검증

| 항목 | 결과 |
|---|---|
| 검증일 | 2026-08-01 |
| 범위 | 로그인 전 계정 생성 요청, 관리자 승인·상태 관리, 사용자 password 변경, 개발용 두 번째 인증 코드 재발급 |
| 판정 | PASS — DEV-LOCAL 한정 |
| 운영 경계 | Pilot WebAuthn/OIDC 인수 전 운영 사용 금지 |

## 1. 현재 흐름

- 계정 생성 요청은 `PENDING_APPROVAL`만 만들고 승인 전 role·session을 만들지 않는다.
- password는 Argon2id encoded hash로만 저장하며 관리자 화면에 원문·hash를 표시하지 않는다.
- 같은 organization의 `ADMIN`만 승인할 수 있고 승인 시 기본 `USER` 역할을 부여한다.
- 관리자는 자신의 계정을 비활성화할 수 없다.
- 사용자가 password를 변경하면 credential version을 증가시키고 기존 session을 폐기한다.
- 관리자가 개발용 두 번째 인증 코드를 재발급하면 DB에는 keyed digest와 만료 시각만 저장하고 기존 session을 폐기한다.
- 코드 원문은 재발급 결과에서 한 번만 복사하도록 제한하고 일반 목록에는 마스킹한다.

## 2. 집중시험

잠긴 dev-tools container에서 다음을 실행했다.

```powershell
docker compose --project-directory . -f deploy\compose\compose.yml -f deploy\compose\compose.dev.yml run --rm dev-tools -m pytest tests/unit/test_account_approval_management.py -q
```

결과: `6 passed in 7.39s`

검증 항목:

1. 승인 대기 계정과 password 원문 미저장
2. ADMIN 전용 승인과 기본 USER 역할 부여
3. 관리자 자신의 계정 비활성화 차단
4. 현재 password 확인·변경과 전체 session 회수
5. 개발용 인증 코드 digest 저장·원문 미저장
6. 인증 코드 재발급 권한·상태·감사 경계

## 3. 남은 Gate

현재 6자리 코드는 자동시험과 localhost 개발 흐름을 위한 두 번째 인증이다. 관리자가 재발급 순간 원문을 알 수 있으므로 Pilot MFA로 승인하지 않는다. Pilot에서는 사용자가 최초 접속 때 WebAuthn 또는 TOTP를 직접 등록하고, 실제 hostname·TLS·RP ID·복구·조직 OIDC Gate를 통과해야 한다.
