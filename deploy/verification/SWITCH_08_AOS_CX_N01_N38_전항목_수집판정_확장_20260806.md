# SWITCH-08 AOS-CX N-01~N-38 전 항목 수집·판정 확장 검증

## 1. 목적

AOS-CX 장비에서 확인할 수 있는 기술 설정을 조직 기본 판정으로 대신하지 않고 직접
수집·판정한다. 장비 자체에 존재하지 않는 승인·운영 이력만 조직 보완 입력으로 남긴다.

## 2. 읽기 전용 수집 확대

인증서가 고정된 AOS-CX v10.13 REST 세션에서 로그인·로그아웃을 제외하고 다음 18개 고정
GET만 실행한다.

- 기존 구조화 GET 13개
- 추가 JSON GET: system status, 전체 사용자, hot patch, 최근 event log
- 추가 text GET: running-config

running-config는 로그인 배너 등 구조화 API에서 빠진 설정을 확인하기 위해 실행 중 메모리에서만
읽는다. 비밀번호 ciphertext·SNMP 비밀·배너 원문·전체 구성은 결과, 로그, Evidence,
canonical projection에 저장하지 않는다. 저장하는 값은 배너 설정 여부·식별정보 노출 여부 같은
비식별 boolean과 개수뿐이다.

## 3. 직접 판정으로 전환한 항목

- N-04: SSH 연결당 최대 인증 시도와 선택한 허용 상한 비교
- N-05: 전체 사용자 역할, 관리자/비관리자/역할 미확인 수, 기본 역할·RBAC 수집
- N-10: MOTD/EXEC 배너 존재와 명백한 IP·MAC·hostname·제품/버전 노출 여부
- N-16: 최근 event log의 timestamp 필드 존재 여부
- N-19: SNMP 활성 VRF, 관리망 외 노출, v3 전용, 인증·암호화 읽기 전용 사용자 비율
- N-23: 사용자 정의 또는 AOS-CX hardware-default CoPP의 유효 적용 여부

N-12는 실행 소프트웨어 버전과 hot patch 수를 장비에서 수집하지만 벤더 권고를 실제로
검토·승인한 이력은 장비 밖 조직 증적이다. N-17도 SNMP 활성 상태는 수집하지만 업무 사용
승인 여부는 조직 증적이다.

## 4. AOS-CX 적용성

다음 항목은 AOS-CX 10.13에서 Cisco식 전역 설정이나 상시 서버 기능이 없어 N/A로 분리한다.

- N-13: 사용자 조정형 로그 버퍼 크기
- N-21: 상시 TFTP 서버 서비스. AOS-CX의 TFTP는 파일 전송 client 경로다.
- N-25: 전역 TCP keepalive service 설정

기존 Finger, small service, BOOTP server, source routing, identd, PAD, mask reply N/A도 유지한다.

## 5. 조직 입력 축소

조직 보완 판정은 11개에서 다음 2개로 축소했다.

- N-12 보안 패치·벤더 권고 검토 이력
- N-17 SNMP 업무 사용 승인

26개 안전 기준과 2개 조직 판정의 총 28개 입력을 실행 snapshot/hash로 보존한다. 브라우저
저장 key는 `secai_switch_criteria_v3`로 갱신해 과거 37개 입력과 혼합하지 않는다. 장비 직접
PASS/FAIL/N/A가 있으면 조직 입력은 적용하지 않는다.

안전 합성 projection을 조직 입력 없이 평가하면 PASS 25·REVIEW 2·N/A 11이며, 기본 조직
입력을 적용하면 PASS 27·REVIEW 0·N/A 11이다. 조직 입력 적용 control은 N-12·N-17뿐이다.

## 8. 실제 장비 확인 상태

2026-08-06 최종 확인 시 AOS-CX VM `192.168.11.10:443`이 응답하지 않아 새 18개 GET의 실제
Simulator E2E는 실행하지 못했다. 서비스가 기동되고 Host-only 연결이 복구된 뒤 현재
credential을 다시 입력해 재점검해야 한다. 기존 append-only 결과는 소급 변경하지 않는다.
