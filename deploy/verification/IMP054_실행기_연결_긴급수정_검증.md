# IMP-054 Launcher 연결 차단 hotfix 검증 기록

| 항목 | 결과 |
|---|---|
| 검증일 | 2026-07-25 |
| 증상 | EXE 실행 중에도 `내 PC 점검하기` 비활성 |
| 직접 원인 | CSP가 `http://127.0.0.1:18481` 연결 차단 |
| 추가 원인 | 제품 주소와 로그인 기준 주소 불일치, 인증 redirect의 fragment 손실, 단발 연결 시도 |
| 결과 | PASS |

## 1. 수정 결과

- API와 Gateway CSP에 `connect-src 'self' http://127.0.0.1:18481`만 허용했다. 임의 port·외부 origin wildcard는 허용하지 않았다.
- Launcher가 여는 제품 주소를 인증 기준과 같은 `http://localhost:18480`으로 통일했다.
- `/ui/launcher-connect`가 로그인 전에 일회용 fragment 토큰을 브라우저 `sessionStorage`로 넘기고 제품 홈으로 이동한다.
- 연결이 잠시 늦어져도 토큰을 즉시 삭제하지 않고 500ms 간격, 최대 10초 동안 다시 연결한다.
- 같은 탭에서 새 fragment만 전달되는 경우도 `hashchange`로 다시 연결한다.
- Windows 소켓 주소 재사용을 끄고 같은 port의 중복 Launcher 실행을 차단한다.
- 브리지는 계속 `127.0.0.1:18481`에만 bind하고 256-bit 토큰·정확한 Origin·정확한 요청 header 검증을 유지한다.
