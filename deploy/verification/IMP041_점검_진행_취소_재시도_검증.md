## 1. 구현 범위

- `POST /v1/scan`은 점검 완료까지 HTTP 연결을 붙잡지 않고 `202`와 작업 상태를 즉시 반환한다.
- 제품 화면은 `GET /v1/status`를 주기적으로 조회해 진행률, 현재 확인 항목과 쉬운 설명을 표시한다. 새로고침해도 임시 런처 토큰이 유효한 동안 같은 작업 상태를 다시 읽는다.
- 실제 일반 권한 점검은 `준비 → 점검 전 안전 상태 → 계정·서비스·보호 설정 12개 → 저장 장치 3개 → 설정 변경 여부 → 결과 정리` 순서로 상태를 알린다.
- `POST /v1/cancel`은 실행 중인 PowerShell을 위험하게 강제 종료하지 않는다. 현재 수집 묶음이 끝난 안전 경계에서 중단하고 `CANCELLED`로 바꾼다.
- `POST /v1/retry`는 `CANCELLED` 또는 `FAILED`에서만 허용한다. 같은 `job_id`를 유지하고 `attempt`를 증가시켜 사용자가 같은 작업의 재시도임을 확인할 수 있게 했다.
- 새로고침·연속 클릭·취소 처리 중 재시도는 두 번째 실행을 만들지 않고 HTTP 409로 거부한다.

## 2. 사용자 화면

첫 화면의 실제 점검 영역에 다음 요소를 추가했다.

- 진행률 막대와 백분율
- `현재 확인 항목`과 쉬운 한국어 상태 설명
- 실행 중 `점검 취소`
- 취소·실패 뒤 `다시 시도`
- 실패 시 내부 예외 대신 임의 문의 번호

완료하면 기존 요약 화면으로 이동한다. 현재 단계에서는 전체·수집 완료·확인 필요 개수만 보여주며 원본 Windows 설정값과 공식 판정은 만들지 않는다.

## 3. 상태·중복 방지 계약

정본은 `collectors/one_shot/contracts/imp041_scan_lifecycle_policy.json`이다.

```text
READY
  └─ scan → RUNNING
               ├─ cancel → CANCELLING → CANCELLED ─ retry ─┐
               ├─ 오류   → FAILED ─────────────── retry ───┤
               └─ 완료   → COMPLETED                      │
                                                         └→ RUNNING
```

- 한 시점에 활성 worker thread는 최대 1개다.
- 실행 중 두 번째 `scan`과 취소 처리 중 `retry`는 409다.
- 취소 요청은 반복해도 새 실행이나 추가 부작용을 만들지 않는다.
- 실패 응답에 stack trace, 내부 경로와 예외 메시지를 노출하지 않는다.
- 재시도를 포함해 공식 Finding 생성은 0건이다.
