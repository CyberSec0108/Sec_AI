## 1. 구현 결과

PC-10은 승인된 월간 패치 기준과 수집된 Windows Edition·Version·Build·UBR, 자동 업데이트 정책, 최근 검색·설치 시각, 재시작 대기와 내부 패치 절차 확인을 결합한다. 단순 `Get-HotFix` 결과는 신뢰 가능한 전체 패치 재고로 인정하지 않는다.

PC-11은 Windows Edition 그룹과 Version별 제품 지원 종료일을 기준일과 비교한다. 같은 23H2라도 Home/Pro는 지원 종료, Enterprise/Education은 지원 중인 사례를 서로 다르게 판정한다.

화면은 [http://localhost:18480/ui/patch-lifecycle](http://localhost:18480/ui/patch-lifecycle), JSON 결과는 [http://localhost:18480/api/v1/demo/patch-lifecycle](http://localhost:18480/api/v1/demo/patch-lifecycle)에서 확인한다.

실제 Gateway에서 화면 제목 `Windows 패치와 지원 기간 점검 | Sec_AI`, PC-10·PC-11·DRAFT 표시와 API 결과 12건을 확인했다. 준비 상태는 `ready`였고 CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` 헤더가 유지됐다. 현재 Codex 실행 환경에는 인앱 브라우저가 제공되지 않아 브라우저 스크린샷 기반 시각 검증은 수행하지 못했으며, TestClient와 실제 HTTP 응답으로 렌더링 계약을 검증했다.

## 4. Fail-closed 경계

- Pack과 기준 스냅샷의 ID·version·content hash가 정확히 일치해야 한다.
- 기준 스냅샷이 누락·변조·만료되면 PASS를 만들지 않는다.
- 허용되지 않은 패치 재고 출처 또는 수집 실패는 ERROR다.
- 필수 업데이트 누락과 지원 종료는 FAIL이다.
- 내부 관리 절차 미확인, 알 수 없는 Edition과 재시작 대기는 REVIEW다.
- `DRAFT` 기준은 개발 화면과 합성시험에서만 명시적으로 허용한다.
