## 1. 구현 결과

### KNOWLEDGE-01 — 출처 등급과 권한

| Source class | Grade | 사용자 표시 | 공식 판정 권한 |
|---|---|---|---|
| `OBSERVED_VALUE` | `E1` | 내 PC 확인 증적 | 없음 — 규칙 입력 |
| `RULE_ENGINE` | `R1` | 공식 판정 규칙 | 있음 — 유일한 판정 주체 |
| `KISA_PRIMARY` | `G1` | KISA 원문 근거 | 없음 — 판정 근거 |
| `VENDOR_PRIMARY` | `G2` | 제조사 1차 문서 | 없음 — 보조 근거 |
| `APPROVED_PUBLIC` | `G3` | 승인 공개 보안자료 | 없음 — 보조 근거 |
| `MODEL_GENERAL_KNOWLEDGE` | `A1` | AI 일반 보안지식 | 없음 — 쉬운 설명만 허용 |

항목별 기본 인용은 다음과 같다.

- `[1]`: 내 PC에서 확인한 실제값
- `[2]`: PC 보안 점검 판정 규칙
- `[3]`: 승인된 KISA 원문
- `[4]`: AI 일반 보안지식

모델 일반지식은 위험 배경, 용어 풀이와 주의점 보충에 사용할 수 있지만 실제값, KISA 문구와 공식 상태를 생성하거나 변경할 수 없다.

### KNOWLEDGE-02 — 화면·PDF 표시

인라인에는 문장을 방해하지 않는 `[1]` 번호만 표시한다. 사용자가 번호를 선택하면 같은 항목 아래 출처로 이동하며 키보드 포커스와 강조가 적용된다. 등록되지 않은 `[9]`는 출처 버튼으로 만들지 않는다.

사용자용 출처 예시는 다음과 같다.

```text
[3] KISA PC 보안 가이드 2026 · 555쪽 · PC-01 비밀번호의 주기적 변경
    KISA 원문 근거(G1) · 승인된 원문 페이지와 세부 점검 항목
```

영문 내부 source ID, guide ID, chunk ID와 hash는 사용자 출처 제목에 표시하지 않는다. 재현성과 감사에 필요한 내부 식별자는 DTO와 기술 검증 자료에 계속 보존한다.

화면과 PDF는 다음 정보를 서로 다른 영역으로 표시한다.

1. 공식 판정 — 규칙 엔진 결과
2. 무엇을 확인했는가
3. 내 PC에서 확인한 값
4. 판정 기준과 KISA 근거
5. AI 보충 설명
6. 항목별 출처 등급과 한계

### KNOWLEDGE-03 — 생성 결과 평가

평가 계층은 다음 신호를 기록한다.

- 알 수 없는 인용 번호
- 필요한 출처 인용 누락
- 근거에 없는 연도·비율·CVE·제품 version 같은 정밀 주장
- 실제값·규칙·KISA 간 출처 충돌
- KISA 근거 부재와 최신성 미확인
- 답변 거부 또는 근거 부족에 따른 보류

평가 상태는 `SUPPORTED`, `REVIEW`, `DEFERRED`, `REFUSED`다. 이 평가는 설명의 한계를 사용자에게 알리는 비차단 계층이며 공식 규칙 상태를 재계산하거나 Finding을 수정하지 않는다.

## 5. 남은 Gate

- 전체 표준 Gate는 이번 집중 변경에서 반복하지 않았다. 기존 기준선은 유지하며 다음 공식 단계인 `IMP-055` clean Windows 11 VM 제품 회귀에서 전체 사용자 흐름과 함께 다시 실행한다.
- 제조사 `G2`와 승인 공개자료 `G3` 등급은 계약에 정의했지만 현재 Windows PC 결과의 기본 항목 출처는 실제값·규칙·KISA·AI 일반지식이다. 제조사 문서를 실제 연결할 때 문서 승인·version·effective date Gate가 추가로 필요하다.
- 결정론적 정밀 주장 검사는 명백한 위험 신호를 찾는 보조 검증이며 의미론적 사실 검증을 대체하지 않는다.
