## 1. 구현 결과

PC-12는 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon`의 `AutoAdminLogon` 상태를 판정한다. 값이 없거나 `0`이면 PASS, `1`이면 FAIL이며 수집 실패는 ERROR다. `DefaultPassword`와 LSA secret 내용은 증적에 넣을 수 없고, 암호 관련 구성의 존재 여부만 최소 노출로 다룬다.

PC-13은 승인 Adapter로 확인된 활성 백신, 보안 인텔리전스 업데이트 시각, 자동 업데이트와 건강 상태를 기관 최신성 기준과 비교한다. 기관 기준이 없거나 제품 Adapter가 없으면 REVIEW이며 오래된 서명·비활성 제품은 FAIL이다.

PC-14는 현재 보호를 담당하는 활성 백신의 실시간 감시와 서비스 상태를 확인한다. Defender가 수동 모드이면 타사 제품이 보호를 담당할 수 있으므로 임의 FAIL이나 PASS로 추측하지 않고 REVIEW다.

PC-15는 `Get-NetFirewallProfile -PolicyStore ActiveStore`에 해당하는 Domain·Private·Public 유효 정책을 확인한다. 적용 프로필의 Windows 방화벽이 모두 켜져 있거나 승인된 대체 방화벽이 해당 범위를 보호해야 PASS다.

화면은 [http://localhost:18480/ui/endpoint-protection](http://localhost:18480/ui/endpoint-protection), JSON 결과는 [http://localhost:18480/api/v1/demo/endpoint-protection](http://localhost:18480/api/v1/demo/endpoint-protection)에서 확인한다.

실제 Gateway에서 화면 제목 `로그인·백신·방화벽 점검 | Sec_AI`, PC-12·PC-15·DRAFT·ActiveStore 표시와 API 결과 18건을 확인했다. 준비 상태는 `ready`였고 CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` 헤더가 유지됐다. 현재 Codex 실행 환경에는 인앱 브라우저가 제공되지 않아 스크린샷 기반 시각 검증은 수행하지 못했으며, TestClient와 실제 HTTP 응답으로 렌더링 계약을 검증했다.

## 4. Fail-closed 경계

- Pack과 Adapter Catalog의 ID·version·content hash가 정확히 일치해야 한다.
- PC-12 증적에 암호값이나 LSA secret 필드가 있으면 판정을 거부한다.
- 수집 실패는 취약을 뜻하는 FAIL로 바꾸지 않고 ERROR로 유지한다.
- 미지원 제품과 Defender 수동 모드는 PASS로 추측하지 않고 REVIEW다.
- PC-13 기관 최신성 기준이 없으면 REVIEW다.
- PC-15가 `ActiveStore`가 아니거나 프로필 필드가 누락되면 ERROR다.
- 합성 타사 방화벽 Adapter는 운영 자료에서 PASS를 만들 수 없다.
- Pack과 Catalog는 계속 `DRAFT`이며 운영 공식 Finding에 사용할 수 없다.
