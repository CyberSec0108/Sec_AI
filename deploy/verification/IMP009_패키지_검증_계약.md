# IMP-009 Package Archive 보안 계약 검증 기록

| 항목 | 결과 |
|---|---|
| 구현 ID | `IMP-009` |
| Runtime | CPython `3.14.6`, `linux/amd64` |
| 대상 | detached `audit_package` descriptor + `payload.zip` |
| 상태 | `PASS` |
| 실제 증적 | 사용하지 않음, 합성 JSON·임시 ZIP만 사용 |

## 구현 범위

- `contracts.py`: 서버 절대 상한, 안정적인 오류 코드, 검사 결과 dataclass
- `strict_json.py`: UTF-8 strict JSON, 중복 key·BOM·NaN·Infinity·unsafe integer 거부
- `archive_contract.py`: filesystem 추출 없는 ZIP 사전검사, 실제 byte hash와 descriptor 비교
- `test_package_validation_contract.py`: 정상·공격·변조 회귀시험
- `tests/fixtures/packages/imp009_cases.json`: 합성 case ID와 기대 오류 코드

## 고정 Package layout

```text
collector_manifest.json
evidence/<UUID>.json
errors/<UUID>.json
```

그 밖의 path, 절대경로, drive path, `..`, `.`, 빈 segment, backslash, 중첩 archive, directory entry를 거부한다. exact duplicate와 Windows 대소문자 충돌을 모두 거부한다. Unix symlink·special file, Windows reparse-point, 동일 local ZIP header를 재참조하는 entry도 거부한다. ZIP은 `STORED`와 `DEFLATE`만 허용하고 encryption flag가 있으면 member를 읽기 전에 거부한다.

Hardlink는 portable ZIP member type으로 보존되지 않는다. 이 구현은 member를 filesystem에 추출하지 않고 regular member byte만 읽기 때문에 검사 과정에서 hardlink나 reparse point를 생성하지 않는다.

## 서버 절대 상한

| 제한 | 값 |
|---|---:|
| ZIP 전체 크기 | 100 MiB |
| 실제 해제 byte 합계 | 500 MiB |
| member 수 | 1,024 |
| JSON member 크기 | 1 MiB |
| path 길이 | 240자 |
| member·전체 압축률 | 100:1 |
| 최소 파일 수 | 2 (`collector_manifest.json` + evidence/error) |

`PackageLimits`에 더 큰 값을 전달해도 허용하지 않는다. 서명 Manifest·endpoint·조직 정책은 이 상한을 줄일 수만 있다. Central directory의 크기를 먼저 확인하고, member를 64 KiB chunk로 읽으면서 실제 크기와 전체 합계를 다시 제한한다.

## Hash 계약

- `archive_sha256`: exact ZIP 전체 byte hash
- `compressed_bytes`: exact ZIP 전체 byte 길이
- `uncompressed_bytes`: 실제로 읽은 member byte 합계
- `file_inventory`: path·실제 크기·member SHA-256 전수 일치
- `content_set_sha256`: manifest를 제외한 `{evidence_id, evidence_sha256}`를 evidence ID 순으로 정렬한 RFC 8785 JCS array hash

Package 무결성 오류는 PC Control의 `ERROR` Finding으로 바꾸지 않는다. Package 자체를 거부하며 공식 판정을 시작하지 않는다.

## 책임 경계와 다음 단계

이 모듈은 archive byte와 detached descriptor의 구조·무결성 계약만 담당한다. 다음 항목은 별도 Gate다.

- JSON Schema와 remote `$ref` 차단
- Manifest 서명·만료·nonce replay·Job·Asset·organization scope
- Collector certificate와 online authentication
- ClamAV와 금지 secret·과수집 검사
- AIStor staging·quarantine·original 승격

다음 `IMP-010`은 KISA 571~572쪽 PC-07의 평가 volume, EFI/MSR/Recovery 제외, ReFS·VHD·Storage Spaces 처리 기대값을 판정 기록으로 승인한다. 이후 `IMP-013` package validator는 이 IMP-009 모듈을 다시 작성하지 않고 위 Schema·인증·악성코드·저장소 Gate와 조합한다.
