## 1. 사용자 화면의 현재 상태

- 가이드 질의 화면의 본문 폭과 좌우 여백을 다른 제품 화면과 맞췄다.
- 왼쪽 대화 목록은 `220~460px` 범위에서 크기를 조절하며 선택값을 브라우저에 저장한다.
- 대화 제목은 한 줄 말줄임으로 표시하고, 선택하거나 가리킨 대화에만 고정·이름 변경·폴더·보관·삭제 아이콘을 표시한다.
- 이름과 폴더는 별도 관리 창을 열지 않고 목록 안에서 바로 수정한다.
- 긴 대화는 화면 전체가 막히지 않도록 대화 영역 안에서 스크롤한다.
- 사용자가 과거 답변을 읽기 위해 위로 이동하면 강제 자동 스크롤을 멈추고, 아래쪽으로 돌아오면 새 token을 다시 따라간다.
- 질문 입력창, 중단 버튼, 답변 방식 선택과 전송 버튼은 하단에서 유지된다.

## 2. 답변 생성과 표시 기준

```text
사용자 질문
→ 32차원 로컬 해시 임베딩
→ PostgreSQL+pgvector 후보 검색
→ lexical 중심 재정렬
→ 승인된 KISA 문단과 질문을 OpenRouter 시험 경로에 전송
→ model-gateway의 OpenAI 호환 delta
→ Redis DB 2의 제한된 임시 stream buffer
→ 브라우저 SSE token 표시
→ 제한 Markdown AST와 등록된 [n] 출처 렌더링
→ 완료 답변·출처·생성 trace 원자 저장
```

현재 개발 Compose는 사용자가 승인한 `KISA 검색 문단의 OpenRouter 시험 전송`을
`SECAI_GUIDE_AI_REMOTE_TEST_APPROVED=true`로 명시한다. 전송 대상은 질문과 검색된
승인 문단이며 원본 PDF, 계정·조직·자산 식별자, credential과 원본 점검 증적은
포함하지 않는다. 이 승인은 OpenRouter를 운영 모델로 승인하거나 최종 로컬 vLLM
Gate를 완료했다는 뜻이 아니다.

API는 모델의 `.stream()` delta를 받아 Redis DB 2에 최대 100,000자·600초로 임시
보관하고 `answer-token`과 `answer-reset` SSE event로 전달한다. 브라우저는 완성된
답변을 기다렸다가 한 번에 넣지 않고 delta가 도착할 때마다 표시한다.

제한 Markdown은 제목·문단·목록·표·강조·inline code·안전한 링크와 계약에 등록된
출처 `[n]`만 DOM으로 만든다. raw HTML과 위험 URL은 실행하지 않으며, 인라인 출처는
해당 번호에 필요한 폭만 사용하고 선택하면 같은 답변의 한글 출처 카드를 연다.

## 3. 현재 검색 기준선

현재 운영 코드는 대형 모델 임베딩이 아니라 결정론적 한국어 lexical hash를 사용한다.

| 항목 | 현재 값 |
|---|---|
| 구현 | `ApprovedLocalKoreanEmbedder` |
| model ID | `secai-ko-lexical-hash-v1` |
| 차원 | 32 |
| 검색 저장소 | PostgreSQL 18.4 + pgvector 0.8.2 |
| 재정렬 | dense 15% + lexical 85% |
| 적재 | KISA PC 범위 문서 1건, chunk/vector 41건, ACTIVE generation 1건 |

이 방식은 작은 승인 코퍼스의 결정론·재현성과 CPU 이식성을 우선한 현재 기준선이다.
`BGE-M3`와 `bge-reranker-v2-m3`는 아직 image, container, migration 또는 ACTIVE
generation으로 구현하지 않았다.

## 4. BGE-M3 전환 판단

현재 GPU는 `NVIDIA GeForce RTX 3060 Laptop GPU`, VRAM 6,144MiB다. BGE-M3는
다국어·긴 문맥과 dense/sparse/multi-vector 검색 품질을 개선할 수 있어 다음 검색
세대의 우선 평가 후보로 적합하다. 다만 현재 `vector(32)` schema에 바로 끼울 수 없다.

전환할 때는 기존 `0006_imp048` migration을 수정하지 않고 다음 순서를 따른다.

1. 신규 1,024차원 generation schema와 migration을 추가한다.
2. GPU embedding 전용 image를 exact model revision·license·hash로 고정한다.
3. 기존 32차원 generation을 유지한 채 승인 문서 전체를 재임베딩한다.
4. PC-01~18, 근거 없음, 충돌 질문으로 recall·MRR·citation 정확도·p95를 비교한다.
5. 기준을 통과한 generation만 원자적으로 ACTIVE로 전환하고 즉시 rollback할 수 있게 한다.
6. 전용 reranker는 embedding 단독보다 품질 향상이 측정될 때만 별도 image로 추가한다.

한 대의 6GB GPU에서 embedding·reranker·vLLM을 모두 상시 적재하지 않는다. 우선은
embedding batch를 GPU로 실행하고 종료하는 방식으로 평가하며, reranker는 측정 결과가
있을 때 추가한다.

## 5. 검증 기준선

최근 변경 당시 수행한 집중 검증은 다음과 같다.

- 가이드 질의 UI·SSE·Markdown 관련 집중 Pytest: 35 PASS
- 대화 목록 inline 관리·한 줄 제목 관련 집중 Pytest: 14 PASS
- 스크롤·출처 정규화·렌더링 관련 집중 Pytest: 17 PASS
- 변경 JavaScript `node --check`: PASS
- 관련 Ruff·mypy 집중 검사: PASS
- 실제 Chrome token 표시: 서로 다른 렌더 길이 47회, 14자→858자 증가 확인
- 실제 Chrome 최종 Markdown: 제목 4개·목록 3개 렌더 확인
- 실제 Chrome: 내부 스크롤, 패널 resize, inline 이름 변경 확인

이 문서 동기화 시점에는 코드를 다시 변경하지 않았으므로 위 시험을 재실행하지 않았다.
대신 실행 상태를 다시 확인했고 `sec-ai-mvp-dev-api-1`은 `healthy`, container image는
`sha256:6e6c8d121cf7af2994dff89423dbffbef380581f6bd4e71acd8468e657f483cb`로
일치했다. 임시 UI 캡처는 `C:\tmp\secai-guide-chat-ui-check.png`이며 운영 증적이나
배포 artifact가 아니다.
