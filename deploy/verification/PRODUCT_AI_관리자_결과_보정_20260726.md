# 관리자 추가 점검 결과 계약 보정 기록

| 항목 | 결과 |
|---|---|
| 검증일 | 2026-07-26 |
| 상태 | **PASS — 사용자 오해를 만들던 일괄 오류 표시 보정** |
| 대상 | PC-02·04·06·08·10 관리자 권한 수집 결과 |
| 공식 Finding·Audit Pack write | 없음 |

## 1. 확인한 원인

관리자 권한 동의와 UAC 실행 자체는 성공했다. 그러나 Windows Collector가 반환한 실제
필드와 DRAFT 규칙이 기대한 완성형 필드가 달랐다.

- PC-02: 비밀번호 길이는 읽었지만 복잡성 적용 여부가 없었다.
- PC-04: 공유 목록은 읽었지만 승인된 공유·인증 접근 개수는 없었다.
- PC-06: 설치 제품 목록은 읽었지만 조직의 금지·승인 제품 목록은 없었다.
- PC-08: 부팅 가능한 운영체제 항목 수를 읽었다.
- PC-10: Windows version·build·업데이트 이력은 읽었지만 조직 기준선 비교값은 없었다.

기존 코드는 필드가 하나라도 부족하면 예외를 일반 `확인 필요(ERROR)`로 바꾸고, 화면도
모든 항목에 같은 “관리자 권한으로 읽은 실제값을 규칙 기준과 비교했습니다” 문장을
표시했다. 따라서 사용자는 UAC가 실패했는지, 일부 자료만 읽은 것인지 구분할 수 없었다.

## 2. 수정한 동작

관리자 동의는 **읽을 권한을 허용하는 절차**이며, 곧바로 양호 판정을 뜻하지 않도록
분리했다.

| 수집 결과 | 사용자 표시 |
|---|---|
| 필요한 값이 모두 있고 DRAFT 규칙 적용 가능 | 규칙 엔진의 PASS·FAIL·ERROR·REVIEW |
| Windows 값은 읽었지만 조직 기준이나 비교 목록이 더 필요 | `기준 확인 필요(REVIEW)` |
| 자료를 읽지 못했거나 수집기가 지원하지 않음 | `정보 수집 오류(ERROR)`와 실제 실패 이유 |
| PC-08에서 부팅 가능한 운영체제 1개 확인 | `양호(PASS)` |

화면에는 각 항목별로 `자료 수집 상태`, `내 PC에서 확인한 내용`, `KISA 권고 기준`,
`왜 이런 결과가 나왔나요`를 표시한다. 내부 오류 코드와 PowerShell 세부 명령은 일반
사용자 화면에 노출하지 않는다.

## 3. 검증

- 실제 Collector 모양의 PC-02·04·06·08·10 자료로 회귀 시험
- 기대 상태: PC-02 REVIEW, PC-04 REVIEW, PC-06 REVIEW, PC-08 PASS, PC-10 REVIEW
- 자료 수집 실패는 실패 원인에 맞는 자연어 안내로 표시
- 관리자 동의·선택 외 항목 미수집·설정 변경 0·Finding write 0 계약 유지
- 관리자 및 PRODUCT-AI-06 집중 시험: 15 PASS

이 결과는 현재 DRAFT 기준의 개발 PC 시험이며 공식 KISA 점검 결과가 아니다.
