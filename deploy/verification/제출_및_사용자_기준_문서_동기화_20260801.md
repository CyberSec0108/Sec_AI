# 제출 평가·사용자 정의 점검기준 문서 동기화 검증

| 변경 종류 | 문서·ADR·로드맵 동기화 |

| Docker 재빌드 | 불필요 — 실행물 변경 없음 |

## 1. 반영 범위

- 제출 양식의 SBOM, AI 모델 유형·라이선스·데이터, 공개 저장소·시연영상, 결과보고서 요구사항을 현재 산출물과 대조했다.
- 일반 사용자가 명령어·JSON 없이 Template과 6단계 Wizard로 개인 점검기준을 만들고, 조직 검토와 공식 Audit Pack으로 안전하게 승격하는 제안을 작성했다.
- KISA 고정 결과와 사용자 기준 결과를 덮어쓰지 않고 같은 실제값에 대해 병렬 비교하도록 경계를 고정했다.
- Linux·Switch 확장 전에 Criteria Catalog·Profile·Audit Pack v2 계약을 검증하도록 순서를 조정했다.

## 2. 주요 발견

1. `pyproject.toml`은 `LicenseRef-Proprietary`이고 프로젝트 `LICENSE` 파일이 없어 OSI 라이선스 요구 제출에는 책임자 결정이 필요하다.
2. 공개 저장소 URL과 시연영상 URL은 아직 결정되지 않았다.
3. 일부 image·Collector SBOM과 잠금정보는 존재하지만 전체 Software를 한 번에 제출할 통합 SBOM·제3자 고지는 없다.
4. 현재 OpenRouter `openai/gpt-oss-120b` 사용은 추가학습 없는 외부 모델 활용인 유형 1로 정리하는 것이 현재 구현과 맞다.
5. KISA 41쪽 text·chunk·embedding은 검색용 RAG 자료이며 학습 데이터나 새 가중치가 아니다.
6. 기존 `audit_pack_schema`는 KISA/Windows/18 Control을 강하게 고정하므로 직접 느슨하게 변경하지 않고 v2 Profile compiler를 별도로 설계해야 한다.

## 3. 안전 경계

- 일반 사용자는 `PERSONAL_DRAFT`와 자신의 장비에 대한 `PERSONAL_ACTIVE` 참고 기준까지만 직접 관리한다.
- 조직 기준은 관리자·보안 검토와 RLS·append-only 감사를 거친다.
- 공식 결과는 Fixture·100회 결정론·false PASS·서명·승인을 통과한 Audit Pack만 생성한다.
- AI는 자연어를 Schema-valid `DRAFT`로 구조화하고 누락·충돌·Fixture 후보를 제안할 수 있지만 승인·서명·공식 Finding 생성은 하지 않는다.
- raw command, Python expression, SQL, PowerShell, shell, NETCONF/REST payload 자유 입력은 허용하지 않는다.

## 4. 검증 항목

- 새 문서와 기존 문서의 상대 링크 존재 여부
- ADR 번호 문서 개수 20개
- ADR content SHA-256 기준선 갱신
- `LicenseRef-Proprietary`, `SUBMIT-01~06`, `CRITERIA-01~08`, `PERSONAL_ACTIVE`, `Audit Pack v2` 핵심 용어 포함
- 기존 다음 작업 `IMP-055`와 `PRODUCT-AI-01~09` 완료 이력 보존

문서 전용 변경이므로 Python test, Ruff, mypy, Schema test와 Docker 재빌드는 실행하지 않는다. 링크·hash·용어 정합성만 검증한다.
