| 항목 | 결과 |
|---|---|
| 구현 ID | `IMP-014` |

## 1. 구현 결과

검증된 Package의 Collector 원시값을 PC-07 규칙 엔진이 사용할 공통 증적 형태로 바꾸는 pure Normalizer를 구현했다. DB·Queue·network·LLM·동적 코드 실행은 사용하지 않는다.

쉬운 비유로는 제조사마다 다른 표기의 검사지를 같은 양식으로 옮겨 적는 단계다. 이 단계는 표기만 통일하며 합격·불합격을 채점하지 않는다.

현재 허용된 Probe와 version은 다음 세 개뿐이다.

| Probe | version | 정규화 대상 |
|---|---|---|
| `win.storage.disks` | `0.1.0` | 디스크·가상 디스크·Storage Spaces 속성 |
| `win.storage.partitions` | `0.1.0` | 파티션 역할·GPT type·system/boot 속성 |
| `win.storage.volumes` | `0.1.0` | 파일시스템·마운트·상태·BitLocker 속성 |

ID 또는 version이 정확히 일치하지 않으면 `NORMALIZER_NOT_ALLOWED`로 중단한다. `eval`, `exec`, dynamic import로 임의 Normalizer를 추가하지 않는다.

## 2. 신뢰 연결과 fail-closed 처리

- IMP-013은 성공 결과에 descriptor canonical SHA-256을 포함한다.
- IMP-014는 전달받은 descriptor의 canonical SHA-256이 그 값과 같은지 다시 확인한다.
- Package·Manifest·Job·Asset ID와 archive SHA-256·content-set SHA-256·file count도 검증 결과와 다시 묶는다.
- 검증 실패 Package, 바뀐 descriptor, 다른 scope 또는 archive facts는 정규화하지 않는다.
- 원시 필드는 Probe별 exact allowlist와 type으로 검사한다. 예상하지 않은 필드는 거부한다.
- 모든 출력은 local-only catalog의 `normalized_evidence.schema.json`으로 재검증한다.

이 연결은 “검사에 통과한 봉투”와 “정규화할 내용물”을 바꿔치기하지 못하게 하는 장치다.

## 3. 상태 보존과 결정론

- `COLLECTED`만 `normalized_value`로 변환한다.
- `ERROR`와 `SKIPPED`는 원래 `collection_status`와 `error_code`를 보존한다.
- 수집 실패·권한 부족·미지원 값을 PC-07 `FAIL`로 만들지 않는다.
- 알 수 없는 파일시스템 이름은 거짓 `FAIL`을 피하도록 `null`로 정규화한다. 후속 판정 단계에서 `ERROR` 근거가 된다.
- 결과 ID는 Package ID·원본 evidence ID·Normalizer 이름/version을 입력으로 한 UUIDv5다.
- 입력 순서와 무관하게 subject·Probe·ID 기준으로 정렬한다.
- 호출자가 전달한 timezone-aware `normalized_at`을 사용하며, 수집 시각보다 이른 정규화 시각은 거부한다.
- redacted 원시값은 출력에 다시 싣지 않고 `OMITTED`로 표시한다.

Normalizer는 `PASS`, `FAIL`, `REVIEW`, `ERROR`, `N/A` Finding을 생성하지 않는다. 공식 판정은 후속 IMP-015와 IMP-016의 승인된 규칙 경로에서만 가능하다.
