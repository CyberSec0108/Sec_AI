| 항목 | 결과 |
|---|---|

## 1. 구현 범위

- Windows 실행 파일의 기본 동작과 `launch` 명령이 제품 화면을 열고 loopback 런처 연결을 유지하도록 했다.
- 제품 화면의 실제 `<button>`인 `내 PC 점검하기`를 누르면 기존에 검증된 일반 권한 읽기 전용 Collector 15개만 정확히 한 번 실행한다.
- 완료 뒤 원본 설정값이 아닌 `전체·수집 완료·확인 필요` 개수만 loopback 제품 화면에 전달한다.
- 제품 첫 화면을 `PC 점검`, `점검 결과`, `KISA 가이드에 질문`, `대화 기록`, `도움말` 중심으로 재구성했다.
- 기존 PC-07 개발 화면은 `/ui/storage`로 이동해 사용자 첫 화면과 분리했다.

## 2. 기능 상태 계약

공통 registry는 네 상태만 허용한다.

| 상태 | 구현 결과 |
|---|---|
| `LIVE` | 실제로 검증된 내 PC 점검·도움말·개발 기술정보 |
| `PREVIEW` | 점검 결과·KISA 질문·대화 기록의 비식별 고정 예시 |
| `BLOCKED` | 관리자 추가 점검, 직접 URL도 HTTP 423 |
| `HIDDEN` | 내부 점검 기준 작성 보조, 일반 registry/API/UI에 미노출 |

`PREVIEW`에는 form·submit·실행 endpoint가 없다. 수집·저장·제출·판정·Finding 호출을 각각 0회로 고정했다.

### 로컬 버튼 연결 보안

- 런처는 `127.0.0.1:18481`에만 bind한다.
- `secrets.token_urlsafe(32)`로 만든 256-bit 임시 토큰을 URL fragment로 브라우저에 전달하므로 제품 서버·접속 로그에는 토큰이 전송되지 않는다.
- `http://127.0.0.1:18480`과 `http://localhost:18480` Origin만 허용한다.
- 정확한 `X-SecAI-Launcher-Token`이 없는 요청과 다른 웹사이트의 요청은 HTTP 403으로 거부한다.
- 한 런처 process에서 점검은 한 번만 시작하며 두 번째 요청은 HTTP 409로 거부한다.
- 점검 응답을 보낸 뒤 로컬 런처 연결과 실행 파일 process가 자동 종료된다.

## 3. 실제 Windows 확인

기존 검증된 `run_standard_host_collection`을 현재 Windows 11에서 일반 권한으로 실행했다.

```text
전체 15
수집 완료 9
확인 필요 6
설정 변경 0
```

권한 부족·미지원·자료 없음은 `확인 필요`로 유지하며 `양호`로 바꾸지 않았다. 원시 레코드, SID, 호스트 이름과 설정값은 출력하거나 파일로 저장하지 않았다.

같은 실제 수집기를 새 loopback 버튼 endpoint `POST http://127.0.0.1:18481/v1/scan`으로 다시 호출해 `COMPLETED`, 전체 15·수집 완료 9·확인 필요 6을 확인했다. 설정 변경·공식 Finding·원본값 저장은 모두 false였고 응답 후 런처가 자동 종료됐다.

## 7. 남은 경계와 다음 작업

- 브라우저는 Windows 설정을 직접 읽지 않는다. 실제 점검 시작 주체는 Windows 실행 파일이다.
- IMP-040 완료 화면은 수집 개수 요약이며 상세 공식 판정 화면이 아니다.
- 실행 중 진행률·취소·재시도·연속 클릭 방지는 `IMP-041`에서 구현한다.
- 실제 결과·조치 안내·재점검은 `IMP-042`, 관리자 다섯 항목과 명시적 동의는 `IMP-043`에서 구현한다.
- 운영 조직 서명·다운로드·공식 Finding·자동 설정 변경은 계속 비활성이다.

## 8. 2026-07-25 연결 차단 hotfix

실제 인증 적용 화면에서 실행 파일은 살아 있지만 `내 PC 점검하기`가 비활성인 문제를 재현했다.

- API와 Gateway의 CSP `connect-src 'self'`가 로컬 브리지 `http://127.0.0.1:18481` 요청을 차단했다.
- Launcher가 `127.0.0.1:18480`을 열어 로그인 기준 주소 `localhost:18480`의 cookie·CSRF 출처와 달랐다.
- 인증 전 redirect에서는 URL fragment의 일회용 토큰이 서버에 전달되지 않아 로그인 뒤 사라졌다.
- UI가 첫 연결 실패에서 토큰을 바로 삭제해 일시 지연도 복구하지 못했다.

수정 후 CSP는 정확한 단일 브리지 주소만 추가하고 wildcard를 허용하지 않는다. 인증 예외인 `/ui/launcher-connect`는 원문·사용자 자료를 표시하지 않고 fragment 토큰을 같은 origin의 `sessionStorage`에 보관한 뒤 `/`로 이동한다. Launcher 제품 주소는 `http://localhost:18480`으로 통일했고 UI는 최대 10초 동안 자동 재연결한다.

최신 EXE, 컨테이너, 전체 검증 결과는 [`IMP054_실행기_연결_긴급수정_검증.md`](IMP054_실행기_연결_긴급수정_검증.md)를 따른다.
