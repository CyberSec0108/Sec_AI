## 1. 구현 결과

- `rule_result.input_sha256`를 논리 멱등 key로 사용한다.
- 첫 key는 `CREATE`, 이미 존재하는 동일 identity는 `RETURN_EXISTING`으로 결정한다.
- replay에서는 candidate 실행 시각이 아니라 기존 Finding ID·output hash를 반환한다.
- 동일 key의 output hash 또는 Finding ID가 다르면 `IDEMPOTENCY_CONFLICT`로 거부한다.
- 다른 key의 기존 row가 전달되면 `IDEMPOTENCY_SCOPE_MISMATCH`로 overwrite를 막는다.
- 선언된 output hash와 canonical decision payload가 다르면 replay 결정 전에 거부한다.
- Finding ID가 canonical input/output hash의 UUIDv5와 다르면 거부한다.

## 3. Repository 계약

IMP-017은 DB 없이 실행하는 pure resolver다. 운영 repository는 IMP-018에서 다음 순서를
하나의 PostgreSQL transaction과 unique constraint로 강제해야 한다.

1. `rule_result.input_sha256`로 기존 Finding을 조회하거나 원자적 insert를 시도한다.
2. 미존재하면 exact candidate를 append-only로 `CREATE`한다.
3. unique 충돌이면 기존 row를 읽고 `resolve_finding_replay`로 비교한다.
4. 동일 fingerprint면 기존 Finding ID·output hash를 반환한다.
5. 같은 key의 다른 output/ID면 overwrite하지 않고 결정론 충돌을 기록한다.

현재 in-memory cache나 process-local registry를 운영 보장으로 사용하지 않는다. Celery 재전달과
동시 Worker race의 최종 중복 방지는 PostgreSQL unique constraint가 담당한다.
