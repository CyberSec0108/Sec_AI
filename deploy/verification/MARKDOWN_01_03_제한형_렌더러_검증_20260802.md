## 1. MARKDOWN-01 출력 계약

계약 version은 `secai.restricted-markdown.v1`이다.

허용 범위:

- `##`~`######` 제목
- 일반 문단
- `-`, `+`, `*` 글머리 목록과 번호 목록
- `**굵게**`, `*기울임*`, inline code
- `/`로 시작하는 same-origin 링크
- 호출자가 exact origin allowlist로 승인한 HTTPS 링크

차단·비활성 범위:

- raw HTML, image, table, fenced code
- `javascript:`, `data:`, `vbscript:`, protocol-relative URL
- control character, 역슬래시·공백이 섞인 URL
- 현재 AI 결과 화면에서 별도로 승인하지 않은 외부 HTTPS origin

금지된 문법은 실행 가능한 DOM으로 만들지 않는다. 위험 링크는 anchor를 만들지 않고 label만 일반 텍스트로 표시한다.

## 2. MARKDOWN-02 streaming renderer

구현 파일:

- `apps/web/static/app/restricted-markdown.js`
- `apps/web/static/app/result-ai-analysis.js`
- `apps/web/templates/pages/result_ai_analysis.html`
- `apps/web/static/app/app.css`

처리 흐름:

```text
OpenRouter/vLLM 호환 token delta
→ 문자열 buffer 누적
→ 75ms throttle
→ 전체 buffer를 고정 AST로 재해석
→ AST type·길이·링크 재검증
→ createElement/createTextNode/replaceChildren로 DOM 생성
→ CONTROL_COMPLETED/SUMMARY_COMPLETED 최종 flush
```

`innerHTML = modelOutput` 같은 HTML 문자열 sink는 사용하지 않는다. parser 오류나 100KB 상한 초과 시 현재 buffer를 `textContent`로 전환하고 `data-markdown-fallback="true"`를 남긴다.

부분 token의 닫히지 않은 `**`는 일반 텍스트로 보이고 닫는 token이 들어오면 다음 flush에서 `strong` AST로 바뀐다. stream 중에도 실행 가능한 중간 HTML은 만들지 않는다.

## 4. CSP와 배포 검증

API와 Gateway 모두 다음 정책을 유지·추가했다.

```text
script-src 'self'
object-src 'none'
trusted-types 'none'
require-trusted-types-for 'script'
```

`unsafe-inline`, `unsafe-eval`은 추가하지 않았다. 실제 `http://localhost:18480/ui/ai-analysis` 응답은 인증 전 `303`이면서 위 CSP를 포함했고, `/static/app/restricted-markdown.js`는 `200`, 16,361 bytes로 제공됐다.

변경 서비스만 재빌드·교체했다.

| 서비스 | image ID | 상태 |
|---|---|---|
| `sec-ai-mvp-dev-api-1` | `sha256:ddbe34f21ad6db4d51dda8593eb022fdb8d909fa6e386897a133365ee3855770` | healthy |
| `sec-ai-mvp-dev-gateway-1` | `sha256:8eada772d0f2c033f3147390eee4882410c62f6cf805f1c282f4755f345f8df3` | healthy |

API `py_compile`은 read-only container의 `/tmp` pycache를 사용해 PASS했고, `nginx -t`도 PASS했다. PostgreSQL·Redis·worker·model-gateway는 재빌드하거나 재시작하지 않았다.
