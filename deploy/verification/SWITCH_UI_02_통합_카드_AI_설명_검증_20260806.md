## 1. 사용자 화면

- 스위치 결과 카드도 Windows PC·Linux 서버와 같은 통합 카드 CSS와 정보 순서를 사용한다.
- 각 카드는 `무엇을 확인했나요`, `내 스위치에서 확인한 값`, `적용된 안전 기준`, `판정 이유`, `AI 상세 설명`, `출처 보기` 순서로 표시한다.
- 전체·양호·취약·확인 필요·해당 없음 필터와 통합 보기·점검 결과만·AI 설명만 전환을 연결했다.
- AI는 전체 요약 뒤 SW-01부터 SW-06까지 순서대로 token delta를 표시하며 항목별 실패가 다음 항목을 막지 않는다.
- 모델 출력은 `secai.restricted-markdown.v3` 제한형 renderer를 사용한다. raw HTML·위험 URL·미등록 인용을 실행 가능한 DOM으로 만들지 않는다.
- 모델 처리는 자동 시작하지 않는다. 사용자가 `AI 설명 생성하기`를 눌러 비식별 결과 문맥 처리를 명시적으로 승인해야 API가 `result_context_processing_approved=true`를 받는다.

## 2. AI 근거와 판정 경계

현재 스위치 기준은 공식 KISA 기준이나 운영 승인 Audit Pack이 아니다. 따라서 Linux·Windows의 시각적 형식은 재사용하되 출처 의미를 허위로 승격하지 않는다.

| 번호 | 스위치 AI 직접 출처 | 경계 |
|---|---|---|
| `[1]` | 실제 스위치 비식별 확인값 | 인증서 고정 REST GET 수집 시점 값 |
| `[2]` | Sec_AI 스위치 `0.1.0-DRAFT` 개발 기준 | 공식 KISA 기준·운영 승인 Pack 아님 |
| `[3]` | AI 일반 보안지식 | 설명 보조이며 공식 판정 근거 아님 |

- 공식 상태는 계속 `RULE_ENGINE`만 결정한다.
- AI 입력에는 내부 `result_code`, credential, cookie, REST 원문, 전체 running-config를 포함하지 않는다.
- Aruba AOS-CX와 Cisco IOS 명령·개념을 섞지 않도록 system prompt를 분리했다.
- AI 실패·중단·출력 한도 도달은 기존 규칙 판정과 저장 결과를 바꾸지 않는다.

## 3. 저장·권한

- 신규 순차 migration: `0026_switch_audit_ai_outputs`
- `switch_audit_ai_outputs`는 `(run_id, output_key)` 기본키와 `ON CONFLICT DO NOTHING`으로 완성된 설명만 append-only 저장한다.
- output key는 `V1:SUMMARY`, `V1:SW-01`~`V1:SW-06`만 허용한다.
- organization·owner user RLS와 `FORCE ROW LEVEL SECURITY`를 적용했다.
- runtime role에는 `SELECT`, `INSERT`만 부여하고 `UPDATE`, `DELETE`는 부여하지 않았다.
- 실제 개발 DB head와 RLS 확인 결과:

```text
0026_switch_audit_ai_outputs
switch_audit_ai_outputs | RLS true | FORCE RLS true
credential 성격 column 0
```

## 6. 항목별 확인값·판정 이유 후속 보완

초기 통합 카드에서는 SW-01~06 수집 조건이 서로 다른데도 `observed_summary`와 화면의
판정 이유가 상태별 공통 문장으로 표시됐다. 후속 보완은 판정 상태와 저장 결과 hash를
임의 변경하지 않고 다음 경계를 적용했다.

- 신규 AOS-CX REST projection은 관리자 인증 성공, 관리 VRF SSH 활성 여부, SNMPv3 전용
  모드와 인증·암호화 사용자 수, 활성 syslog 서버 수, NTP client와 관리 VRF 서버 수,
  CLI·HTTPS 유휴 제한 시간을 서로 다른 비식별 확인값으로 보존한다.
- 사용자 이름, SNMP 사용자 이름, 서버 주소, credential, cookie와 REST 원문은 확인값에
  포함하지 않는다.
- 과거 공통 문장 저장 결과는 원본 JSON과 `result_sha256`을 수정하지 않고 UI·AI 공개 입력
  계층에서 항목별 확인값과 판정 이유로 변환한다.
- 과거 공통 확인값으로 생성됐을 수 있는 V1 AI cache는 해당 legacy 결과에서 재사용하지
  않고 보정된 항목별 입력으로 설명을 다시 생성한다.
- 실제 로그인·MFA 뒤 최신 저장 결과 페이지는 HTTP 200, 카드 6개, 확인값 6개·고유값
  6개, 판정 이유 6개·고유값 6개였고 기존 공통 문장과 인증정보 노출은 0건이었다.
- 관련 집중시험 45건, 변경 Ruff와 mypy strict 4개 source file을 통과했다.
