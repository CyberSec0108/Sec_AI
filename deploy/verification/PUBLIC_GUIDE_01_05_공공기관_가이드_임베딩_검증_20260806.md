# PUBLIC-GUIDE-01~05 공공기관 가이드 반입·임베딩·질의 설명 검증

## 1. 결론

- 공공기관 원본 PDF 7개를 `data/public_guides/`에 원본 파일명으로 보관했습니다.
- 총 원본은 56,815,470 bytes·997쪽이며 SHA-256과 공식 게시물 계보를 고정했습니다.
- ClamAV 7/7 CLEAN, 전체 Page Map 997쪽, 색인 가능한 966쪽을 확인했습니다.
- PostgreSQL에 문서 7개·chunk 966개를 적재했고 32차원과 BGE-M3 1,024차원 embedding이 각각 966개입니다.
- 7개 문서 모두 `SUPPLEMENTAL_EXPLANATION`, `decision_authority=false`입니다. 기존 KISA 상세가이드와 Audit Pack 판정은 변경하지 않았습니다.
- 가이드 질의 화면은 문서별 선택 목록 대신 `통합 보안 가이드 검색 (8종)` 한 범위만 제공합니다.
- 질문 임베딩 한 번으로 승인된 KISA 1종과 보완 문서 7종을 검색하고, 관련도가 높은 서로 다른 문서를 종합합니다.
- 검색된 복수 문서 근거는 기존 KISA 가이드 질의의 LLM 시스템 프롬프트·stream·출력 검증 경로로 전달합니다.
- 실제 로그인 HTTP E2E에서 `AI 프롬프트 취약점이 무엇인가요?` 답변 `COMPLETED`, OpenRouter `openai/gpt-oss-120b`, 서로 다른 문서 인용 3건, 정확한 출처 PDF 열기를 확인했습니다.
- 현재 개발 Runtime은 승인된 OpenRouter 시험 경로여서 `external_data_transfer=true`입니다. 질문과 검색된 공개 문서 문단만 전송하며 원본 PDF 전체·사용자 증적·Finding·자산 식별자는 보내지 않습니다.

Windows·Linux·Switch 결과 설명에 보완 문서를 자동 혼합하는 주제 라우팅과 대량 검색 benchmark는 아직 완료하지 않았습니다. 현재 완료 범위는 문서를 고르지 않는 통합 가이드 질의 설명입니다.

## 3. 판정 분리

```text
기존 KISA 상세가이드 + 승인 Audit Pack -> 공식 점검 판정과 직접 근거
공공기관 보완 문서 7종              -> 질문 답변의 추가 설명과 페이지 인용
```

- migration `0028_public_guide_roles`는 문서에 검색 역할과 `decision_authority=false` 제약을 추가합니다.
- 보완 문서 적재 도구는 Finding·Rule Engine·Audit Pack 저장소를 호출하지 않습니다.
- 통합 채팅의 가상 범위는 출처가 될 수 없으며, 각 인용은 승인 문서·조직·guide/version/scope·청크·쪽이 DB와 정확히 일치할 때만 저장합니다.
- 채팅 생성 요청은 기존 `GroundedAIService`의 시스템 프롬프트·인용·stream·실행형 출력 차단을 그대로 사용합니다. 모델 장애 때만 로컬 결정론 요약으로 대체합니다.
- 인증된 원본 PDF 확인은 읽기 전용 mount, exact hash, 승인 문서 ID, 페이지 범위, `private, no-store`로 제한합니다.

## 5. 발견·수정한 결함

1. N2SF 본문 2쪽의 손상 text layer가 글자 수만으로 색인 대상으로 잡혔습니다. 검색 토큰이 없으면 `NO_SEARCHABLE_TOKEN`으로 제외하도록 보정했습니다.
2. API가 PDF 추출 모듈을 import하면서 runtime image에 없는 PyMuPDF를 요구했습니다. 추출 의존성은 적재 도구에만 두고 API는 strict JSON manifest만 읽도록 분리했습니다.
3. 기존 로컬 KISA 요약기가 `PC-01~18`만 허용해 `GUIDE-PAGE`를 거부했습니다. 보완 문서 전용 문서명·페이지 인용과 판정 불변 문구를 추가했습니다.
4. 문서별 선택창은 사용자가 어느 문서에 답이 있는지 먼저 알아야 하는 문제가 있었습니다. UI를 하나의 통합 범위로 바꾸고 8종을 자동 검색하도록 수정했습니다.
5. 기존 채팅 저장 계약은 한 대화에 한 문서의 인용만 허용했습니다. 통합 대화에 한해서만 실제 승인 문서와 청크 계보를 DB에서 다시 확인한 뒤 복수 문서 인용을 저장하도록 확장했습니다.
6. 최초 통합 답변은 검색 문장을 그대로 나열해 기존 LLM 설명 품질이 사라졌습니다. 검색만 통합하고 답변 생성은 기존 `GroundedAIService`의 LLM 시스템 프롬프트·stream·출력 검증을 재사용하도록 수정했습니다.
7. 프롬프트 인젝션 설명 문서의 공격 예시가 실제 명령으로 감지돼 전체 답변이 차단됐습니다. 보안 필터를 끄지 않고 위험한 문단만 모델 입력에서 제외한 뒤 남은 안전한 승인 근거로 계속 답하도록 수정했습니다.

각 결함은 DB 부분 적재 없이 fail-closed로 중단됐고, 수정 후 전체 집중 검증과 실제 HTTP를 다시 통과했습니다.
