## 1. 사용자 기능

KISA 질문 기능을 고정 예시 `PREVIEW`에서 인증된 실제 기능 `LIVE`로
전환했다.

- 새 대화와 최근 대화 계속하기
- 질문 전송과 Enter 전송
- PostgreSQL+pgvector 근거 검색 상태 SSE
- 답변 생성 중단
- 사용자 질문 편집과 원본 이력 보존
- 답변 다시 생성
- 기존 답변에서 새 대화 분기
- 가이드 version·PDF 쪽·절·문단 출처 표시
- 원문 위치 열기
- 생성 방식·모델·input/output 확인값 접기

사용자 질문과 KISA 원문은 현재 OpenRouter로 보내지 않는다. LIVE 화면은
Completion 계약을 따르는 결정론적 `LocalGroundedSummaryModel`로 선택된 승인
문단을 쉽게 설명한다. 향후 local vLLM은 같은 계약에서 주소·모델을 바꾸어
연결할 수 있다.

## 2. 저장·보안 계약

migration `0010_imp053`은 완료된 생성 시도에 다음 추적값을 추가했다.

- `answer_mode`
- `model_id`
- `prompt_sha256`
- `input_sha256`
- `output_sha256`
- `external_data_transfer`

PostgreSQL trigger는 `COMPLETED` 전환 시 이 값이 하나라도 없으면 원자적으로
거부한다. Runtime은 조직·대화 소유자 FORCE RLS와 CSRF 검사를 계속 적용한다.
브라우저 렌더링은 `textContent`와 생성한 DOM node만 사용하고 모델 답변을
`innerHTML`로 실행하지 않는다.

기본 환경은 `SECAI_CHAT_LIVE_ENABLED=false`다. 개발 Compose만 검증된 API에
`true`를 설정하며 인증이 꺼져 있으면 저장 API는 계속 거부한다.

## 4. UI·버튼 검증

페이지 계약은 `guide-chat-live-v1`이다. 다음 버튼은 모두 실제 동작에
연결했다.

| 버튼 | 연결 |
|---|---|
| 새 대화 | 현재 입력 상태 초기화 |
| 질문 보내기 | Thread/Message 생성 후 generation 실행 |
| 답변 중단 | 현재 요청 취소와 `/stop` |
| 수정 취소 | 편집 상태 해제 |
| 질문 수정 | append-only edit 후 새 generation |
| 다시 답변 | `/retry` 후 새 generation |
| 여기서 새 대화 | `/branch`로 기존 이력을 보존한 새 Thread |
| 출처 보기 | 저장된 exact Citation 표시 |

미리 보기 URL `/ui/preview/guide_chat`은 더 이상 화면을 열지 않으며 `404`다.
기능 registry와 상단 탐색은 `/ui/guide-chat` 및 `#history`를 사용한다.

## 6. 남은 경계와 다음 단계

- 현재 답변은 LLM 자유 생성이 아니라 외부 전송 없는 로컬 근거 요약이다.
- local vLLM image·CUDA·model weight는 아직 없다.
- OpenRouter에 KISA 원문·사용자 질문을 보내려면 별도 외부 전송 승인이 필요하다.
- 운영 OIDC, 조직 TLS, 운영 배포와 clean Windows VM 인수는 완료되지 않았다.
- 이동 묶음은 생성하지 않았다.

다음 `IMP-054`에서는 초보 사용자가 별도 설명 없이 질문하고 출처를 열며,
점검 결과와 AI 설명을 구분하는지 확인한다. 키보드 탐색, screen reader label,
반응형과 기술정보 기본 접힘도 함께 인수한다.
