## 1. 사용자가 얻게 될 기능의 기반

사용자가 질문을 멈추고 다시 답받거나, 질문을 고쳐 새 분기에서 계속하고,
이전 대화를 다시 여는 데 필요한 저장·상태 계약을 구현했다.

```text
Thread
  └─ User Message
       ├─ Assistant Message + exact Citation
       ├─ Retry Generation
       └─ Edited User Message → 새 branch
```

- 질문 편집은 기존 본문을 수정하지 않고 새 메시지 version으로 추가한다.
- 답변 재시도는 이전 답변 ID를 보존한 새 generation으로 기록한다.
- 같은 idempotency key를 반복하면 기존 메시지·generation을 반환한다.
- 중단된 generation은 완료·실패 등 다른 terminal 상태로 다시 바뀌지 않는다.
- 실제 답변 Citation은 guide·version·scope·chunk·PDF page·절·문단 hash를
  함께 보존한다.
- 물리 삭제는 구현하지 않았다. 보존기간 승인 전에는 `TOMBSTONED` 상태로
  조회만 차단한다.

## 2. PostgreSQL 보안·불변 계약

신규 테이블:

- `chat_threads`
- `chat_messages`
- `chat_generation_runs`
- `chat_citations`

조직 ID와 대화 소유자 ID를 transaction-local PostgreSQL 설정으로 전달하고,
네 테이블 모두 `FORCE ROW LEVEL SECURITY`를 적용했다. 두 값이 모두 일치하지
않으면 runtime role에서 행을 볼 수 없고 새 행도 추가할 수 없다.

`secai_runtime`에는 `DELETE`를 주지 않았다. 메시지 본문·hash·인용은 INSERT
뒤 변경할 수 없고 상태 전이에 필요한 열만 제한적으로 UPDATE할 수 있다.

streaming delta는 영구 대화 정본으로 저장하지 않는다. PostgreSQL에는
generation의 `QUEUED/STREAMING/COMPLETED/STOPPED/FAILED` 상태와 최종 Message만
기록하며, 짧은 delta 상태는 후속 Worker·Redis 연결 단계에서 사용한다.

## 3. API 경계

다음 계약을 FastAPI에 등록했다.

- 새 대화와 최근 대화 목록
- 대화 메시지 기록 조회
- 질문 추가
- 질문 편집
- 답변 재시도
- 이전 메시지에서 새 대화 분기
- 생성 중단
- SSE generation 상태 확인

기본 설정은 `SECAI_CHAT_LIVE_ENABLED=false`다. 로그인·CSRF·소유자 검사와
후속 KISA Q&A 보안시험이 끝나기 전에 `PREVIEW` 직접 URL이나 변조 요청이
실제 대화를 저장하지 않도록 HTTP 409 `CHAT_PREVIEW_NOT_LIVE`로 차단한다.

현재 model-gateway는 token streaming을 활성화하지 않았다. 이번 단계의
streaming 범위는 순서가 있는 delta·중단·terminal 상태·SSE 상태 계약이며,
실제 모델 답변 결합은 `IMP-052`, 사용자 화면 연결은 `IMP-053` 범위다.
