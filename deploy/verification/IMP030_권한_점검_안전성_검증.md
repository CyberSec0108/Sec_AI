# IMP-030 권한 분리·Probe 안전성 검증

## 1. 완료 범위

| 항목 | 결과 |
|---|---|
| 구현 단계 | `IMP-030` |
| 대상 | Windows One-shot Collector 실행 경계 |
| 일반 권한 실행 | PC-07 Probe 3개를 일반 사용자 프로세스로만 실행 |
| 관리자 권한 실행 | 별도 계획·별도 프로세스 계약, 항목·이유 안내와 명시적 동의 필수 |
| 자동 UAC·자동 상승 | 없음 |
| 실행 제한 | Probe 최대 30초, stdout·stderr 각각 최대 65,536 bytes |
| 비정상 프로세스 정리 | timeout·출력 초과 시 해당 자식 process tree 종료 |
| 설정 무변경 확인 | 실행 전·후 5개 설정 표면 Snapshot 일치, 차이 0건 |
| 공식 Finding | 생성하지 않음 |
| 다음 단계 | `IMP-031` PC-01~18 Probe·Adapter 확대 |

IMP-030은 관리자 권한이 필요할 수 있다는 이유로 전체 Collector를 처음부터 관리자로 실행하지 않는다. 일반 작업과 관리자 작업을 서로 다른 실행 계획으로 나누고, 관리자 대상이 있을 때만 사용자에게 대상과 이유를 보여준 뒤 별도 동의를 받도록 계약을 고정한다.

## 3. 권한 분리 규칙

```text
검증된 실행 계획
├─ STANDARD_USER Probe → 일반 사용자 전용 프로세스
└─ ADMINISTRATOR Probe → 항목·이유 사전 안내
                         → 사용자 명시적 동의
                         → 별도 관리자 프로세스
```

- 일반 계획에 관리자 Probe가 섞이면 실행 전에 거부한다.
- 일반 프로세스가 관리자 토큰으로 시작되면 과도한 권한으로 간주해 거부한다.
- 관리자 계획은 함수 호출만으로 자동 시작되지 않으며 명시적 동의가 없으면 거부한다.
- 권한 부족·실행 불가·timeout·출력 초과는 보안 취약 `FAIL`로 바꾸지 않는다.
- 현재 PC-07 세 Probe는 모두 `STANDARD_USER`라서 관리자 프로세스와 UAC를 실제로 시작하지 않았다.
- 향후 관리자 Probe가 추가되는 경우의 분리·안내·동의 거부 동작은 합성 실행 계획으로 시험했다.

## 4. 실행 안전장치

| 위험 | 안전 처리 |
|---|---|
| Probe가 끝나지 않음 | 30초 상한에서 해당 process tree 종료, `PROBE_TIMEOUT` |
| stdout 또는 stderr가 지나치게 큼 | stream을 읽는 동안 65,536 bytes에서 즉시 종료, `OUTPUT_TOO_LARGE` |
| 자식 프로세스가 남음 | Windows에서는 방금 만든 정확한 PID에만 `taskkill /T /F` 적용 |
| 설정이 실행 중 바뀜 | 전후 Snapshot 불일치로 수집 결과를 거부, Finding 생성 안 함 |
| Snapshot 자체가 실패함 | 수집 안전성을 입증할 수 없으므로 fail-closed |
| PowerShell source 변조 | hash 불일치로 PowerShell 시작 전 거부 |

출력 상한은 실행이 끝난 뒤 한 번만 검사하지 않는다. stdout·stderr를 읽는 동안 byte 수를 감시하므로 무한 출력도 메모리를 계속 사용하지 못한다.

## 5. 설정 Snapshot 범위

실행 전후 다음 읽기 전용 표면을 같은 방법으로 정규화·정렬·hash 처리한다.

1. PowerShell execution policy
2. 디스크 online·offline·read-only flag
3. partition layout과 주요 flag
4. volume filesystem·type·size
5. 확인 가능한 BitLocker lock·protection 상태

Snapshot은 설정을 쓰지 않으며 사용자명·호스트명·volume label·파일 경로를 출력하지 않는다. 이 단계의 차이 0건은 “PC가 안전하다”는 뜻이 아니라 “이번 읽기 작업이 감시한 설정을 바꾸지 않았다”는 뜻이다.

2026-07-23 다른 개발 PC에서 일반 사용자 `Get-Disk` 접근이 거부되는 차이를 확인했다. 자동 권한 상승 없이 시험을 계속할 수 있도록 디스크·파티션·볼륨 표면별 접근 실패는 원시 오류 대신 고정된 `UNAVAILABLE` 상태로 snapshot에 포함한다. 전후 모두 접근 불가인 경우에도 같은 상태를 비교하되, 실제 값을 확인한 것으로 표시하지 않는다.

## 8. 보류 범위

다음 항목은 IMP-030 완료로 간주하지 않는다.

- PC-01~18 전체 native Probe와 실제 제품 Adapter
- 실제 관리자 Probe의 clean Windows VM 권한 matrix
- 온라인 제출 credential·nonce·replay 처리
- 오프라인 signed Package
- PyInstaller Windows x64 artifact·SBOM·악성코드 검사
- Authenticode 서명·인증서 chain·폐기 시험
- Audit Pack 운영 승인과 공식 Finding 생성
- 자동 설정 변경 또는 자동 보안 조치

다음 구현은 `IMP-031` 하나만 진행한다. 이 단계에서 만든 권한·process·Snapshot 경계를 약화하지 않고 Control별 Probe와 승인 제품 Adapter를 확대한다.
