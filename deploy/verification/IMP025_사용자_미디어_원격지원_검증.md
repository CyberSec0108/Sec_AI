## 1. 구현 결과

PC-16은 사용자 범위 Control이다. 평가 사용자마다 `ScreenSaveActive=1`, `ScreenSaveTimeOut=1~600초`, `ScreenSaverIsSecure=1`을 요구한다. 선택된 화면보호기 실행 파일은 보조 증적이며 결과를 단독으로 바꾸지 않는다. 현재 사용자 설정이 양호해도 자산에서 평가해야 할 다른 사용자가 남으면 REVIEW다. 이미 확인된 사용자가 기준을 위반하면 Coverage 부족으로 약화하지 않고 FAIL을 유지한다.

PC-17은 기술 설정과 조직 절차를 분리한다. 모든 드라이브에서 AutoPlay를 끄고, AutoRun 명령을 실행하지 않으며, 비볼륨 장치의 AutoPlay도 차단해야 한다. 기술 설정이 양호해도 승인된 CD·DVD·USB·이동식 미디어 관리 절차가 없으면 REVIEW다. 기술 설정 위반은 조직 절차 유무와 관계없이 FAIL이다.

PC-18은 Windows Remote Assistance의 요청형 `fAllowToGetHelp`와 제공형 `fAllowUnsolicited`를 모두 명시적 `0`으로 설정해야 PASS다. 하나라도 `1`이면 FAIL, 정책 미설정은 REVIEW, 수집 실패는 ERROR다. Quick Assist와 원격 데스크톱은 서로 다른 기능이므로 이 Control의 입력과 판정에서 제외한다.

화면은 [http://localhost:18480/ui/user-media-remote](http://localhost:18480/ui/user-media-remote), JSON 결과는 [http://localhost:18480/api/v1/demo/user-media-remote](http://localhost:18480/api/v1/demo/user-media-remote)에서 확인한다.

## 4. Fail-closed 경계

- exact Pack ID·version·content hash와 exact rule parameter만 실행한다.
- PC-16 사용자 subject가 아니거나 필수값이 누락되면 판정을 거부한다.
- 알려진 화면보호기 위반은 사용자 Coverage 부족으로 REVIEW에 숨기지 않는다.
- PC-17 기술 설정 위반은 조직 절차 누락보다 먼저 FAIL로 판정한다.
- PC-17 기술 설정만 양호하고 승인 절차가 없으면 PASS를 만들지 않는다.
- PC-18 정책 미설정은 Windows 기본값을 추측하지 않고 REVIEW다.
- Quick Assist와 원격 데스크톱 상태는 PC-18 결과를 변경하지 않는다.
- 수집 실패는 취약을 뜻하는 FAIL이 아니라 ERROR다.
- Pack은 계속 `DRAFT`이며 운영 공식 Finding에 사용할 수 없다.
