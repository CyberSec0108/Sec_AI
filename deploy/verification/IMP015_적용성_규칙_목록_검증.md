## 1. 구현 결과

정규화된 PC-07 증적에서 평가 volume과 승인된 제외 volume을 결정하고, 정적으로 등록된 규칙만 실행하는 pure engine을 구현했다.

허용된 규칙은 다음 두 개뿐이다.

| 역할 | Rule ID | version |
|---|---|---|
| 적용성·제외 | `pc07.applicability` | `0.1.0` |
| NTFS 판정 | `pc07.ntfs` | `0.1.0` |

ID·version이 다르거나 동일 version의 parameter가 승인된 Pack 값과 다르면 각각 `RULE_NOT_ALLOWED`, `RULE_PARAMETERS_INVALID`로 평가 시작을 거부한다. runtime 등록 API, `eval`, `exec`, dynamic import, filesystem·network·DB·LLM 접근은 사용하지 않는다.

## 2. 적용성·완전성 처리

- Windows OS, local fixed data, mounted folder, attached VHD, Storage Spaces logical, BitLocker volume을 평가 후보로 포함한다.
- EFI·MSR·Recovery·OEM utility는 신뢰 가능한 partition role이 확인된 경우에만 제외한다.
- detached disk image와 광학·이동식·network·RAM disk도 승인된 식별값이 확인된 경우에만 제외한다.
- 이름·drive letter 부재·USB bus 같은 단일 휴리스틱으로 제외하지 않는다.
- 평가 후보의 disk·partition·volume 세 Probe 중 하나라도 누락되거나 오류이면 부분 증적으로 `PASS`하지 않는다.
- 분류 불능, 평가 volume 0개, filesystem 불명과 BitLocker locked는 `ERROR` decision candidate로 보존한다.
- Package·Control scope가 다른 증적, 미허용 Probe/version과 동일 subject·Probe 중복은 fail-closed로 거부한다.

## 3. PC-07 decision candidate

17개 승인 Fixture의 다음 projection을 모두 재현한다.

- `PASS` 8개, `FAIL` 5개, `ERROR` 4개
- candidate·evaluated·excluded·violating volume ID와 제외 reason
- 일반 비-NTFS, ReFS, 수집 실패, filesystem 불명과 평가 volume 없음 result code
- `pc07:evaluated-volume-set` aggregate subject

ReFS `FAIL`은 `REFS_KISA_NTFS_CONDITION_MISMATCH` rationale을 유지하며 ReFS 자체를 취약하다고 표현하지 않는다. 입력 evidence 순서를 뒤집어도 동일한 immutable candidate를 반환하고 입력 문서를 변경하지 않는다.

## 4. 책임 경계

현재 PC-07 Pack `0.1.0`은 개발용 `DRAFT`다. 이 단계의 `DecisionCandidate`는 Fixture 검증용 pure engine 결과이며 운영 `APPROVED` Pack 기반의 공식 Finding이 아니다.

다음 기능은 구현하지 않았다.

- Finding Schema 문서와 canonical input/output hash
- Pack 서명·승인·활성화 검증과 Evaluation Worker
- PostgreSQL·AIStor·Redis 저장 또는 Queue 처리
- API·Windows Collector·실제 기관 증적
- Finding append-only 저장·멱등 key
