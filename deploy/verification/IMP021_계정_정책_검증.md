## 1. 구현 결과

| 항목 | KISA 위치 | 테스트 판정 기준 |

| PC-01 비밀번호 변경 주기 | 555~556쪽 | 1~90일이면 양호, 제한 없음·90일 초과면 취약 |

수집 실패나 권한 부족은 보안 위반으로 단정하지 않고 `확인 필요(ERROR)`로 유지한다. PC-02의 조직 기준 누락도 `양호`로 처리하지 않는다.

## 2. 테스트 사례

총 10개 사례를 고정했다.

| 결과 | 수 | 의미 |
|---|---:|---|
| 양호 `(PASS)` | 3 | KISA·조직 기준 충족 |
| 취약 `(FAIL)` | 3 | 기준 불충족 |
| 확인 필요 `(ERROR)` | 3 | 설정 수집 실패 |
| 기준 확인 필요 `(REVIEW)` | 1 | PC-02 조직 기준 미등록 |

같은 입력을 100회 평가해 결과가 하나로 유지되는지도 자동시험으로 확인한다.

## 3. 화면 용어

일반 사용자가 먼저 보는 화면에서는 내부 개발 용어를 다음처럼 바꿨다.

| 이전·내부 용어 | 화면 표시 |
|---|---|
| Audit Pack | 점검 기준 묶음 |
| Fixture | 테스트 사례 |
| Effective policy | 실제로 적용된 설정 |
| Policy source | 설정 적용 위치 |
| Finding | 점검 결과 |
| REVIEW | 기준 확인 필요 `(REVIEW)` |
| ERROR | 확인 필요 `(ERROR)` |
| DRAFT | 검토 중 `(DRAFT)` |

영문 상태값과 버전·코드는 작은 보조 정보 또는 기술 정보 영역에만 표시한다.

### 공통 화면 표준 `audit-overview-v1`

PC-07과 PC-01~03이 다른 제품 화면처럼 보이지 않도록 다음 순서를 공통 규격으로 고정했다.

1. 점검 결과 요약
2. `무엇을 확인하나요?` KISA 기준 요약
3. 테스트 사례
4. 결과 목록
5. 접힌 기술 정보

두 화면은 같은 Jinja 구성요소로 머리글과 상태 요약을 만든다. 상태 영역은 `양호·취약·확인 필요·기준 확인 필요·해당 없음`을 항상 같은 순서로 표시하며, 해당 결과가 없으면 `0`으로 표시한다.

`무엇을 확인하나요?`는 삭제하지 않는다. 설명은 KISA 원문 점검항목과 양호 기준을 우선 사용하고, 화면이 길어질 때만 의미를 바꾸지 않는 범위에서 요약한다. 각 항목에는 KISA 페이지를 함께 표시한다.

### 공통 조작 표준 `audit-actions-v1`

PC-07과 PC-01~03은 다음 버튼과 이동 방식을 동일하게 사용한다.

1. 테스트 사례마다 `테스트 실행` 버튼을 표시한다.
2. 실행 요청은 CSRF와 동일 출처를 확인한 뒤 `303`으로 상세 결과 화면에 이동한다.
3. 결과 목록은 `점검 결과·점검 항목·확인된 내용·점검 기록·상세 보기`의 같은 5개 열을 사용한다.
4. 모든 결과 행의 마지막에는 `상세 보기`를 표시한다.
5. 상세 화면은 공통 `audit-result-v1` 템플릿을 사용하며 `판정 요약·확인 결과·조치 안내·점검 처리 단계·KISA 가이드·기술 정보` 순서로 표시한다.

목록 하단의 `기술 정보 보기`에는 두 화면 모두 `점검 기준 묶음 버전·판정 규칙 버전·사용 자료·결과 저장 방식`을 같은 순서로 표시한다. PC-07은 PostgreSQL에 결과를 저장하고 PC-01~03은 메모리에서만 판정하므로 저장 방식의 값만 다르다.

## 4. 보안 경계

- 테스트 데이터만 사용하며 실제 PC 자료를 읽거나 저장하지 않는다.
- 기존 PC-07 `0.1.0` 자료는 변경하지 않고 PC-01~03이 추가된 새 `0.2.0` 파일을 만들었다.
- 새 기준 묶음은 여전히 검토 중이며 운영 승인·서명 상태가 아니다.
- 유효 설정 출처는 허용된 로컬·도메인·기기 관리·Windows 기본값만 받는다.
- 승인되지 않은 규칙 ID·버전·매개변수는 실행하지 않는다.

## 6. 남은 범위

IMP-021은 테스트 데이터 기반 규칙과 화면만 완성했다. 실제 Windows 정책 수집 경로, 일반 사용자·관리자 권한 차이와 도메인·기기 관리 우선순위는 단계 H Collector와 단계 I VMware 시험에서 확인해야 한다.
