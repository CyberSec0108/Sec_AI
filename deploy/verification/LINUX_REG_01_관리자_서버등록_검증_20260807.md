# Linux 관리자 서버 등록 검증 — 2026-08-07

## 결과

계정정보의 `관리자 운영 기능`에 `Linux 서버 관리` 카드를 추가하고 다음 개발 흐름을
연결했다.

```text
관리자 서버 등록
→ 서버별 Ed25519 SSH 공개키 자동 발급
→ 서버 authorized_keys에 restrict 공개키 설치
→ 관리자가 별도 경로로 확인한 Ed25519 host key 입력
→ 고정 명령 2개로 SSH 연결·OS·architecture 확인
→ exact Support Catalog 일치 시 ACTIVE
→ 일반 사용자의 Linux 점검 서버 목록에 표시
```

사용자는 Ubuntu/Rocky 종류를 입력하지 않는다. 자동 확인 결과가 Ubuntu 24.04 또는 Rocky
Linux 9의 현재 지원 Catalog와 정확히 일치하지 않으면 `ACTIVE`로 전환하지 않는다.

## 보안 경계

- 관리 화면과 등록·활성화·중지 요청은 `ADMIN` 역할을 서버에서 다시 확인한다.
- 모든 변경 요청은 인증 세션 CSRF 검증을 통과해야 한다.
- 대상은 `SECAI_LINUX_ASSET_ALLOWED_CIDRS`의 IPv4 리터럴과
  `SECAI_LINUX_ASSET_ALLOWED_PORTS`로 제한한다.
- loopback, link-local, metadata 주소, multicast, unspecified와 DNS 입력을 거부한다.
- host key를 자동 수집·신뢰하지 않고 관리자가 서버 콘솔/담당자와 별도로 확인한
  Ed25519 키만 고정한다.
- 서버별 SSH 키 자료는 Git에서 제외된 `/run/secai-linux-asset-keys`에 저장한다.
- DB에는 공개키와 `credential_ref`만 저장하며 개인키 컬럼과 runtime DELETE 권한이 없다.
- 등록 이벤트는 append-only이며 조직 RLS를 강제한다.
- SSH 사전 확인은 `/usr/bin/cat /etc/os-release`, `/usr/bin/uname -m`만 실행한다.

## 남은 Gate

- 실제 Ubuntu 24.04와 Rocky 9 VM의 등록→활성화→U-01~U-67 반복 점검
- 공개키 미설치, 잘못된 계정, sudo 부족, host key 변조, CIDR 밖 주소 공격 회귀
- 운영 KMS/HSM Secret Provider와 서버 키·host key 회전/폐기
- 조직별 허용망 설정 관리자 UI와 다단계 승인
- 서버 재설치 시 과거 결과를 보존하는 host key 재승인 흐름

따라서 이 기능은 개발 환경 `LIVE`이며 운영 자산 등록 완료를 의미하지 않는다.
