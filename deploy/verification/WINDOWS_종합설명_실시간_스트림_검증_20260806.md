# Windows 종합설명 실시간 스트림 검증

## 1. 목적

Windows 점검 결과의 PC-01~PC-18 항목 설명은 순차 표시되지만, 상단 `AI 종합 설명`만 모델 응답이 끝난 뒤 한 번에 표시되는 문제를 수정한다.

## 2. 원인

`ResultAITokenStreamService.stream_summary()`가 model gateway의 delta를 `"".join(...)`으로 모두 소비한 후 하나의 `SUMMARY_DELTA`로 반환했다. API와 Web 화면은 이미 SSE delta를 즉시 전달·렌더링하고 있었으므로 병목은 UI가 아니라 application service의 전체 버퍼링이었다.

## 3. 변경

- 규칙 엔진이 계산한 canonical 상태 개수를 첫 `SUMMARY_DELTA`로 즉시 전송한다.
- 모델은 `먼저 확인할 항목`부터 작성하며, 완성된 Markdown 줄마다 후속 delta를 전송한다.
- 모델이 공식 판정 개수를 임의로 다시 작성한 줄은 화면으로 보내지 않는다.
- PC-01~PC-18 개별 설명의 기존 token stream 순서와 계약은 변경하지 않는다.
- 모델이 예상한 제목 형식을 지키지 않은 경우에도 기존 호환 경로를 유지한다.

## 4. TDD 및 검증 결과

### 실패 확인

구현 전 `test_summary_yields_before_model_stream_is_fully_consumed`는 첫 출력 전에 모델 delta 3개가 모두 소비되어 실패했다. 이는 종합설명이 invoke 방식처럼 동작한다는 결함을 재현한다.

## 5. 사용자 화면 동작

1. `AI 종합 설명`에서 공식 전체 상태가 먼저 표시된다.
2. 모델이 생성하는 `먼저 확인할 항목`, `사용자 조치`, `관리자에게 요청할 사항`이 생성되는 순서대로 이어진다.
3. 종합설명이 끝나면 기존과 같이 PC-01부터 항목별 설명이 진행된다.
4. 공식 판정과 개수는 모델 출력이 아니라 규칙 엔진 결과를 계속 사용한다.

## 6. 남은 범위

delta 소비 순서는 잠긴 Docker 개발 image의 합성 streaming model로 결정론적으로 확인하고, 변경 source를 포함한 API image를 다시 빌드해 실행 container와 digest 일치 및 Core ready를 확인했다. 실제 OpenRouter의 네트워크 속도는 실행 시점에 따라 달라질 수 있지만, application service가 전체 응답을 기다리는 버퍼링 경로는 제거됐다.
