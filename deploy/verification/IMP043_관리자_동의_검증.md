## 1. 구현 범위

일반 권한 점검이 완료된 뒤에만 다음 다섯 항목을 사용자가 필요한 만큼 선택할 수 있다.

| Control | 확인 항목 | 관리자 권한이 필요한 이유 |
|---|---|---|
| PC-02 | 비밀번호 관리정책 | 컴퓨터 전체 암호 정책을 읽어야 함 |
| PC-04 | 공유 폴더와 접근 권한 | 전체 공유와 권한을 빠짐없이 확인해야 함 |
| PC-06 | 설치된 메신저 제품 | 컴퓨터 전체 사용자 범위 제품 목록이 필요함 |
| PC-08 | Windows 부팅 항목 | 부팅 구성 저장소 접근에 관리자 권한이 필요함 |
| PC-10 | Windows 업데이트 이력 | 전체 업데이트 기록과 재시작 대기 상태를 확인해야 함 |

화면은 각 항목의 수집 이유와 수집 자료를 실행 전에 보여준다. 항목 체크와 별도의 동의 체크를 모두 마친 경우에만 실행 버튼이 활성화된다.

정본 계약은 [`collectors/one_shot/contracts/imp043_administrator_consent_policy.json`](../../collectors/one_shot/contracts/imp043_administrator_consent_policy.json)이다.

## 2. 권한 상승 경계

```text
일반 점검 완료
  → 관리자 항목 선택
  → 별도 동의 체크
  → 실행 버튼
  → Windows UAC 확인
  → 별도 관리자 프로세스에서 선택 항목만 읽기
  → 비식별 결과 결합
```

- 실행 파일 시작이나 일반 점검만으로 UAC를 띄우지 않는다.
- PowerShell Probe 자체는 `Start-Process`나 `runas`를 사용하지 않는다.
- 제품 화면의 명시적 요청을 받은 부모 실행 파일만 Windows `runas` 동작을 요청한다.
- 상승 프로세스에는 고정 allowlist 중 선택한 Probe ID만 전달한다.
- 선택하지 않은 Probe는 PowerShell 진입점에서도 다시 제외한다.
- UAC 취소·거부는 보안 취약 `FAIL`이나 공식 Finding이 아니다.
- UAC를 취소해도 기존 일반 점검 결과와 비식별 이력은 유지되며 다시 시도할 수 있다.

## 3. 결과 결합·비밀 보호

관리자 프로세스는 별도 loopback `127.0.0.1:18482`에서 최대 10분 동안 비식별 결과만 제공한다. 256-bit 임시 token, 정확한 제품 Origin과 전용 header가 모두 일치해야 읽을 수 있다. Token은 URL query가 아닌 fragment로 전달한다.

결과 화면에는 다음 값만 결합한다.

- Control ID, 쉬운 제목과 확인 자료 설명
- `관리자 자료 확인 완료` 또는 `추가 확인 필요`
- 선택·완료·추가 확인 개수
- 비식별 점검 시각

레지스트리 값, 공유 이름, 제품 원문 목록, 부팅 항목, 업데이트 원문, SID·사용자명·호스트명은 브리지 결과나 이력에 저장하지 않는다. `자료 확인 완료`는 공식 `PASS`가 아니며, 수집 오류도 공식 `FAIL`로 바꾸지 않는다.

새 시험은 다음을 검증한다.

- 일반 점검 완료 전 관리자 실행 거부

- 원본 값·설정 변경·공식 Finding·자동 상승 없음

재실행:

```powershell

  -File .\tools\verify-imp043-administrator-consent.ps1
```
