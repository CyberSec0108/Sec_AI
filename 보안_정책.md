# Sec_AI Security Policy

## Supported scope

The current supported development baseline is the approved `R0-WALKING-SKELETON` on
CPython 3.14.6 and `linux/amd64` containers. Real institutional evidence is not allowed until
the Pilot security gates in `13.MVP_구현_시작_계획.md` are complete.

## Never commit or bundle

- passwords, session cookies, API tokens, private keys, unseal shares, AIStor license files;
- real `.env` files, database dumps, container volumes, backups, or original evidence;
- production hostnames, personal contact lists, or recovery-custodian records;
- unsigned production Audit Packs or unapproved Collector binaries.

Use `.env.example` only for variable names and safe development defaults. Runtime secrets must
be provisioned from OpenBao or an approved Vault as short-lived read-only files or memory values.

## Reporting a vulnerability

Do not open a public issue containing exploit details, credentials, evidence, or personal data.
Report privately to the designated `SECURITY_OFFICER`. Record a minimal incident ID, affected
version/hash, reproduction conditions, impact, and containment status. Do not paste secrets or
raw evidence into tickets, chat, traces, screenshots, or logs.

## Required handling

1. Stop the affected deployment or isolate the component when evidence integrity, authorization,
   authentication, or secret exposure may be affected.
2. Preserve relevant immutable audit records and hashes.
3. Rotate compromised credentials through the approved requester/approver/executor workflow.
4. Add a regression test before closing the issue.
5. Update the affected ADR, lock, Schema, SBOM, and image digest when the security baseline changes.
