# Sec_AI 초보자 사용 안내

## 1. Sec_AI가 하는 일

Sec_AI는 Windows PC, Linux 서버와 Aruba 스위치의 보안 설정을 읽기 전용으로 확인하고 결과와 공식 기준, AI 설명을 한 화면에서 보여 주는 개발용 보안 점검 서비스입니다.

시스템이 하는 일은 세 가지입니다.

1. 장비에서 허용된 자료만 읽습니다.
2. 개발용 점검 기준으로 `양호`, `취약`, `확인 필요`, `수집 오류`, `해당 없음`을 구분합니다.
3. 사용자가 원할 때 AI가 결과를 쉬운 한국어로 설명합니다.

AI가 점검 결과를 다시 판정하거나 장비 설정을 자동으로 바꾸지는 않습니다.

## 2. 가장 쉬운 사용 순서

1. Sec_AI에 로그인하고 두 번째 인증을 마칩니다.
2. 홈에서 `Windows PC 점검`, `리눅스 서버 점검` 또는 `네트워크 스위치 점검`을 선택합니다.
3. 화면 안내에 따라 장비 연결 또는 등록된 장비 선택을 완료합니다.
4. 점검을 시작하고 진행이 끝날 때까지 기다립니다.
5. `점검 결과`에서 실제 확인값, 판정 이유와 기준을 확인합니다.
6. 필요한 경우 `AI 설명 생성`을 누릅니다.
7. 설정을 수정한 뒤 `다시 점검`하여 결과가 바뀌었는지 확인합니다.

이미 생성한 AI 설명은 저장된 결과와 함께 다시 불러옵니다. 화면에 들어갔다는 이유만으로 새 설명을 만들지 않으며, 사용자가 재생성 버튼을 눌러야 다시 생성합니다.

## 3. 장비별 차이

| 장비 | 사용자가 준비할 것 | 종류 선택 |
|---|---|---|
| Windows | 점검 EXE를 내려받아 실행하고 웹과 연결 | Windows 10·11 x64를 시스템이 확인 |
| 회사 Linux | 관리자가 미리 등록·활성화한 서버 | 배포판·버전은 SSH 사전 확인으로 자동 식별 |
| 개인 Linux | Linux 공용 실행파일을 서버 안에서 실행 | Ubuntu·Debian·Rocky·RHEL·AlmaLinux를 자동 식별 |
| Aruba 스위치 | 등록 장비와 인증서 고정 REST 접속정보 | 현재 AOS-CX 10.13 exact 지원만 실행 |

미지원·불완전·서로 충돌하는 식별 결과는 비슷한 기준으로 임의 실행하지 않고 차단합니다.
현재 Linux 지원 범위는 Ubuntu 22.04·24.04, Debian 12, Rocky Linux 9, AlmaLinux 9
x86_64이며 RHEL 9는 공식 이미지 시험이 남은 시험 지원입니다.

## 4. Windows 점검

1. 홈의 `Windows PC 점검`을 누릅니다.
2. Launcher가 연결되지 않았으면 `점검 프로그램 다운로드`를 누릅니다.
3. 받은 EXE는 설치 프로그램이 아니므로 직접 실행합니다. 브라우저가 자동으로 실행하지 않습니다.
4. 일반 권한 PC-01~PC-18 점검을 먼저 완료합니다.
5. 관리자 권한이 필요한 다섯 항목은 결과 화면에서 별도 설명과 동의를 확인한 뒤 선택 실행합니다.

관리자 점검을 하지 못한 항목은 취약으로 바꾸지 않고 별도 상태로 남습니다.

## 5. Linux 중앙 점검

일반 사용자는 IP, SSH 계정이나 key를 입력하지 않습니다. 관리자가 `계정정보 → 관리자 운영 기능 → Linux 서버 관리`에서 등록하고 활성화한 서버만 목록에 나타납니다.

1. `리눅스 서버 점검`을 엽니다.
2. 서버 별칭을 선택합니다. 이 화면은 Ubuntu/Rocky 선택 화면이 아닙니다.
3. 필요한 경우 숫자 기준과 승인 목록을 확인합니다.
4. `Linux 서버 자동 확인 및 점검 시작`을 누릅니다.
5. 시스템이 OS와 CPU를 먼저 확인한 뒤 지원 대상이면 U-01~U-67을 진행합니다.

SSH 화면을 사용자가 계속 열어 둘 필요는 없습니다. 중앙 서비스가 등록된 key로 접속합니다. 단, 중앙 서비스·Worker·서버 사이 네트워크가 점검 중 유지되어야 합니다.

## 6. Linux 원샷 자가 점검

회사 등록 서버가 아닌 자신의 Linux 서버는 `Linux 원샷 자가 점검`을 사용합니다.

1. 자가 점검 화면에서 새 점검을 만듭니다.
2. 다운로드 화면에서 Linux 공용 파일을 받습니다.
3. 서버에서 `chmod +x secai-linux-check-x86_64`를 실행합니다.
4. `./secai-linux-check-x86_64`를 실행하고 화면에 표시된 일회용 코드를 입력합니다.
5. 일반 권한으로 확인할 수 없는 자료가 있으면 추가 권한 목록을 읽고 동의합니다. 비밀번호는 Linux의 `sudo`가 직접 처리하며 Sec_AI는 저장하지 않습니다.
6. 자동 제출이 안 되면 생성된 ZIP과 descriptor JSON을 자가 점검 화면에서 올립니다.

오프라인 업로드 결과는 서버 신원을 자동으로 보증하지 못하므로 신뢰 수준이 낮게 표시됩니다.

## 7. 스위치 점검

현재 실제 연결 대상은 Aruba AOS-CX 10.13입니다. 시스템은 인증서가 일치하는 HTTPS REST GET만 사용합니다.

1. `네트워크 스위치 점검`을 엽니다.
2. 등록된 장비와 필요한 연결정보를 확인합니다.
3. 점검을 시작합니다.
4. N-01~N-38 결과에서 `REVIEW`와 `N/A`를 `FAIL`과 구분합니다.

장비 밖 조직 정책이 필요한 N-12·N-17은 관리자가 입력한 조직 기준과 장비 수집값을 분리해 표시합니다. 현재 결과는 공식 KISA 판정서가 아닌 `DRAFT`입니다.

## 8. 결과 상태 읽기

| 화면 표현 | 뜻 |
|---|---|
| 양호 | 수집한 자료가 이번 실행에 고정한 개발 기준과 일치 |
| 취약 | 수집한 자료가 개발 기준과 불일치 |
| 확인 필요 | 자료만으로 결론을 낼 수 없거나 조직 확인 필요 |
| 수집 오류 | 권한·연결·형식 문제로 필요한 자료를 읽지 못함 |
| 해당 없음 | 해당 장비나 구성에 적용되지 않음 |

`수집 오류`와 `확인 필요`를 `취약` 또는 `양호`로 추정하지 않습니다.

## 9. AI 설명과 가이드 질의

- 결과 AI는 실제 확인값과 규칙 판정을 입력으로 받아 설명만 만듭니다.
- Windows·Linux·Switch 설명은 token stream으로 표시되고 완성 결과가 저장됩니다.
- 모델이 실패해도 점검 결과와 기존 설명은 유지됩니다.
- 가이드 질의는 문서를 직접 선택하지 않고 승인된 8종을 통합 검색합니다.
- 답변에는 실제 사용한 문서명과 쪽을 표시합니다.
- 가이드 검색 결과도 공식 판정을 변경하지 않습니다.

## 10. 현재 개발 한계

- 운영용 조직 서명, KMS/HSM, 키 회전과 폐기는 아직 최종 인수 전입니다.
- Windows 알려진 취약점은 NVD·OSV 공개 자료와 일치한 후보이며 제조사 확정 결과가 아닙니다.
- Linux 추가 배포판은 Catalog에 있어도 실제 VM 인수를 통과하기 전에는 Pilot입니다.
- Cisco와 다른 스위치 제조사는 아직 실제 지원 대상이 아닙니다.
- 로컬 vLLM은 준비 상태이며 현재 승인된 개발 연결은 모델 게이트웨이를 통한 원격 시험 경로입니다.
