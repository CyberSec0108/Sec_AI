# Windows 알려진 취약점 점검 안내

## 이 기능의 의미

이 화면은 최근 Windows 점검에서 확인한 OS·업데이트·설치 프로그램·Python·Node.js·Java 구성요소를 NIST NVD와 OSV.dev 공개 자료와 비교합니다.

결과는 `영향 가능성 후보`입니다. 공식 취약 판정, 제조사 확인서 또는 패치 적용 판정이 아닙니다. 후보가 없다고 안전을 보장하지도 않습니다.

## 사용 순서

1. Windows PC 점검을 먼저 완료합니다.
2. 홈에서 `알려진 취약점 점검`을 엽니다.
3. 최근 Windows 인벤토리가 표시되는지 확인합니다.
4. 필요하면 `requirements.txt`, `package-lock.json`, `pom.xml` 같은 의존성 파일을 추가합니다.
5. `알려진 문제 확인`을 누릅니다.
6. 구성요소 종류, `높음 이상`, 구성요소명 또는 CVE로 결과를 좁힙니다.

업로드한 의존성 파일에서는 패키지 이름과 버전만 읽으며 원문 전체를 결과로 저장하지 않습니다.

## 숫자 읽는 법

| 표시 | 뜻 |
|---|---|
| 영향 가능 구성요소 | 공개 취약점 후보가 하나 이상 연결된 구성요소 수 |
| 공개 취약점 참고자료 | NVD·OSV에서 연결된 전체 후보 자료 수 |
| 자동 비교 완료 | 제품 이름과 버전을 안전하게 비교할 수 있었던 항목 수 |
| 자동 비교 제외 | 정확한 자동 비교 계약이 없어 제외한 인벤토리 항목 수 |
| 최고 영향도 점수 | 연결된 공개 자료 중 가장 높은 점수 |

한 구성요소에 여러 CVE·GHSA·PYSEC가 연결될 수 있으므로 구성요소 수와 참고자료 수는 다릅니다.

## 자동 비교 제외 이유

자동 비교 제외는 취약점 발견 수가 아닙니다. 다음과 같은 경우입니다.

- Windows 일반 프로그램 이름을 정확한 CPE 또는 제조사 제품으로 확정하지 못함
- Windows KB가 취약 패키지가 아니라 수정 적용성 증적으로 사용됨
- 이름 또는 버전이 없거나 공개 자료 형식이 비교 계약과 맞지 않음
- 지원하지 않는 package ecosystem 또는 범위

이 값을 줄이려면 수집한 제품 정보를 임의 문자열 비교로 연결하지 말고, 검토된 공급자·제품 매핑과 test fixture를 추가해야 합니다.

## 후보 상세 읽기

구성요소 카드를 펼치면 후보별로 다음 순서가 보입니다.

1. 자료 출처: `NIST NVD · CVE` 또는 `OSV.dev · source record ID`
2. 공식 원문 링크: 허용된 NVD 또는 OSV HTTPS 주소
3. 공식 취약점 설명(한글): 공식 원문의 사실을 추가·삭제하지 않는 한국어 번역

한국어 설명은 원기관이 발행한 공식 한국어 번역이 아닙니다. Sec_AI의 별도 번역 계약으로 생성하며, 조치 방법이나 새 판단을 덧붙이지 않습니다.

`AI로 쉽게 설명`은 위 번역과 다른 선택형 기능입니다. 일반 사용자가 이해하기 쉬운 보충 설명을 만들지만 공식 출처를 대체하지 않습니다.

## 오프라인 사용

인터넷 연결이 없으면 마지막으로 저장한 append-only 공개 Feed cache와 비교하며 자료 기준 시각을 표시합니다. cache가 오래됐거나 없으면 `취약점 없음`으로 표시하지 않습니다.

## 실제 조치 전 확인

- Microsoft 보안 업데이트 안내 또는 해당 제조사 advisory를 확인합니다.
- 후보가 실제 실행 경로에 포함되는지 확인합니다.
- 제조사가 제시한 영향 버전과 수정 버전을 확인합니다.
- 조직의 변경 승인·backup·rollback 절차를 적용합니다.
- 수정 후 Windows 점검과 알려진 취약점 비교를 새로 실행합니다.

현재 미완료 범위는 일반 프로그램 CPE/제조사 확정, 검증된 수정 버전 계산, 서명 Offline Feed Bundle, Linux와 Switch 확장입니다.
