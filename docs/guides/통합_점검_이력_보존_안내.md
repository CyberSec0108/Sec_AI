# Windows·Linux·Switch 결과 이력·보존 안내

## 사용자가 보는 범위

상단 `점검 결과`에서 Windows·Linux·Switch의 완료 결과를 플랫폼과 날짜로 찾을 수 있습니다. 현재 로그인 아이디와 조직이 모두 같은 결과만 보입니다.

다른 브라우저나 PC에서 같은 계정으로 로그인해도 DB에 저장된 결과와 완성된 AI 설명을 다시 볼 수 있습니다. 브라우저 `localStorage`는 Windows의 보조 fallback일 뿐 정본이 아닙니다.

## 저장되는 내용

| 플랫폼 | 저장 내용 |
|---|---|
| Windows | PC-01~PC-18 snapshot, 공식 표시 설명, AI 입력, 관리자 점검 presentation, AI 종합·항목 완성본 |
| Linux | 중앙·one-shot 결과, 기준 snapshot/hash, 공식 설명·AI 입력, 완료된 AI output |
| Switch | N-01~N-38 결과, 조직 보완 판정 분리값, 기준/hash, 공식 설명·AI 입력, 완료된 AI output |

원본 credential, 비밀번호, private key와 전체 원본 secret은 이력 조회 DTO에 포함하지 않습니다.

## append-only 의미

- 완료 결과를 `UPDATE` 또는 `DELETE`로 고치지 않습니다.
- 같은 결과를 다시 저장해도 결과 hash와 멱등키로 중복을 방지합니다.
- 늦게 만들어진 Windows 관리자 화면과 AI 화면은 새 presentation version으로 추가합니다.
- 정책 변경은 새 version으로 추가하며 과거 결과를 다시 쓰지 않습니다.
- 설정을 수정한 뒤에는 새 점검을 실행합니다.

## AI 설명 복원

완료된 AI 설명이 있으면 결과 화면 진입 시 저장본을 불러옵니다. 자동으로 새 모델 호출을 시작하지 않습니다. 새 설명은 사용자가 명시적으로 재생성했을 때만 만들며, 모델 실패 시 기존 결과와 설명을 유지합니다.

## 접근 통제

- API가 organization과 owner를 확인합니다.
- PostgreSQL RLS가 같은 조건을 다시 적용합니다.
- 다른 사용자의 run ID를 추측해도 결과를 볼 수 없어야 합니다.
- 기술 검증용 증적과 PDF는 별도 권한이 필요합니다.

## 보존과 삭제

현재 개발 기본 보존정책은 365일, Backup 필수, 법적·조사 보존은 `HOLD`로 분리합니다. 이는 정책 계약이며 운영 Backup·복구 승인과 보존 만료 tombstone 실행은 아직 최종 인수 전입니다.

운영 삭제를 구현할 때도 DB row를 임의 삭제하지 않고 다음을 남겨야 합니다.

- 정책 version과 승인자
- 보존 만료 대상 식별자
- tombstone과 실행 시각
- 증적 저장소 삭제·잠금 상태
- backup·legal hold 충돌 확인

운영자가 SQL로 결과를 직접 수정하거나 삭제하는 방식은 허용하지 않습니다.
