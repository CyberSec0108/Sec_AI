# 점검 기준 확인·수정 안내

## 현재 가능한 범위

Sec_AI는 사용자가 자유롭게 명령이나 규칙을 만드는 범용 Builder를 아직 제공하지 않습니다. 현재는 안전하게 제한한 값과 승인 목록만 수정할 수 있습니다.

| 플랫폼 | 현재 수정 가능한 것 | 수정할 수 없는 것 |
|---|---|---|
| Windows | 개인/조직 Profile 선택, 허용된 정책값, KISA 기본값 복원 | Probe 명령, 판정 코드, 공식 Pack 승인 상태 |
| Linux | 비밀번호 기간·최소 길이, 계정 잠금 횟수, 세션 timeout, 승인 관리자·포트·SUID 경로 | SSH 명령, shell, 정규식, U-01~U-67 실행 코드 |
| Switch | KISA 기반 26개 안전 기준값, N-12·N-17 조직 보완 판정 | 임의 REST path, CLI 명령, N-01~N-38 판정 코드 |

## 일반 사용자 사용법

1. 점검 시작 화면의 `이번 점검 기준`을 펼칩니다.
2. 허용된 숫자 또는 승인 목록만 수정합니다.
3. 잘못 바꿨다면 `기본 점검값으로 되돌리기`를 누릅니다.
4. 점검을 시작합니다.
5. 시스템은 그 시점의 기준 snapshot과 SHA-256을 결과에 고정합니다.

이후 조직 기본값이 바뀌어도 이미 완료된 결과의 기준은 바뀌지 않습니다.

## 관리자 사용법

관리자는 `계정정보 → 관리자 운영 기능 → 조직 기본 기준`에서 다음 실행에 사용할 조직 기본값을 버전으로 추가합니다. 기존 결과나 기존 버전을 덮어쓰지 않습니다.

관리자도 shell, PowerShell, SQL, 정규식이나 임의 API 경로를 입력할 수 없습니다. 이것은 입력 실수와 명령 주입을 막고 수집기 allowlist를 유지하기 위한 제한입니다.

## 조직 입력과 장비 수집값의 차이

Switch의 N-12·N-17처럼 장비만 읽어서는 판단할 수 없는 항목은 조직 담당자가 보완값을 입력할 수 있습니다. 화면과 결과에는 다음을 분리해 표시합니다.

- 장비에서 실제로 읽은 값
- 조직 담당자가 입력한 값
- 개발용 판정 결과

조직 입력을 장비가 직접 입증한 값처럼 합치지 않습니다.

## 아직 제공하지 않는 기능

- 자연어로 새 점검 항목 만들기
- 사용자가 수집 명령이나 판정식을 직접 작성하기
- AI가 만든 규칙을 즉시 운영 Pack으로 적용하기
- 검토 없이 `DRAFT`를 `APPROVED`로 승격하기
- 기준 변경으로 과거 결과를 다시 판정하기

향후 무코드 Builder를 추가하더라도 `작성 → Schema 검증 → 합성 Fixture → 보안시험 → 승인 → 서명 → 새 version 게시` 순서를 거쳐야 합니다. AI 출력은 실행 불가능한 제안으로만 사용합니다.
