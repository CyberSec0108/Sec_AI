# 회사 내부망 Linux SSH 점검 운영 안내

## 1. 현재 동작

Linux 중앙 점검은 일반 사용자가 IP·계정·SSH key를 입력하는 방식이 아닙니다. 관리자만 서버를 등록하고 연결 신원을 확인합니다. 일반 사용자는 활성화된 서버 별칭을 선택해 U-01~U-67 점검을 시작합니다.

```text
관리자 등록
→ 시스템이 서버별 Ed25519 키 생성
→ 관리자가 공개키를 서버에 설치
→ 관리자가 별도 경로로 host key 확인·등록
→ 시스템이 OS·CPU 자동 확인
→ 지원 서버만 ACTIVE
→ 일반 사용자가 별칭을 선택해 점검
```

## 2. 역할

| 역할 | 하는 일 |
|---|---|
| 일반 사용자 | 활성 서버 선택, 점검 실행, 본인 결과 확인 |
| 서버 관리자 | 점검 전용 Linux 계정 생성, 공개키 설치, 필요한 읽기 권한 준비 |
| Sec_AI 관리자 | 자산 등록, host key 확인값 등록, 활성화·중지, 감사 확인 |
| 승인 담당자 | 운영망·CIDR·key 수명·권한·Audit Pack·조직 서명 승인 |
| 시스템 | key 생성, exact host key 검증, OS 자동 식별, allowlist 명령 실행, 결과 저장 |

등록 담당자가 서버 사용자가 아니어도 확인할 수 있는 정보는 자산대장·서버 관리자 확인·CMDB·방화벽 승인·별도 관리 채널에서 받습니다. 추측한 IP나 host key를 등록하지 않습니다.

## 3. 관리자 등록 절차

1. 로그인 후 `계정정보`를 엽니다.
2. `관리자 운영 기능`에서 `Linux 서버 관리`를 선택합니다.
3. 서버 별칭, 승인된 IPv4, SSH 포트와 점검 전용 계정을 입력합니다.
4. 등록을 완료하면 시스템이 서버별 Ed25519 키 쌍을 생성합니다.
5. 화면의 공개키를 서버 관리자에게 전달합니다.
6. 서버 관리자는 공개키를 점검 계정의 `authorized_keys`에 설치합니다.
7. 관리자는 SSH 접속 자체와 다른 신뢰 경로로 서버의 Ed25519 host key를 확인합니다.
8. 확인한 host key를 등록하고 `활성화`를 누릅니다.
9. 시스템이 `/etc/os-release`와 `uname -m`을 읽어 Catalog와 비교합니다.
10. 정확히 지원되는 서버만 일반 사용자 점검 목록에 나타납니다.

현재 중앙 등록 활성 범위는 Ubuntu 22.04·24.04, Debian 12, Rocky Linux 9,
AlmaLinux 9 x86_64입니다. RHEL 9는 Adapter 연결은 완료됐지만 공식 구독 이미지 실제
인수가 남아 `PILOT`이며 일반 지원 대상으로 승격하지 않습니다. 모든 Linux 결과의 Audit
Pack은 계속 개발용 `DRAFT`입니다.

## 4. SSH 키는 누가 만드나요?

사람이 개인키 파일을 직접 만들어 업로드하지 않습니다. 서버 등록 시 시스템이 서버별 Ed25519 키를 자동 생성합니다.

- 공개키: 관리자가 대상 서버에 설치하도록 전달할 수 있습니다.
- 개인키: DB 컬럼에 저장하지 않고 개발 runtime key store에서만 사용합니다.
- host key: 시스템이 자동 신뢰하지 않으며 관리자가 별도 경로로 확인한 값을 등록합니다.

현재 방식은 개발 환경용입니다. 운영 전에는 KMS/HSM, key 접근 감사, 회전·폐기, 백업 금지, 비상 복구와 담당자 승인이 필요합니다.

## 5. 점검 계정 권한

권장 계정은 로그인 목적이 아닌 점검 전용 서비스 계정입니다.

- 대화형 shell과 임의 명령을 허용하지 않습니다.
- Sec_AI allowlist의 읽기 전용 명령만 실행할 수 있게 제한합니다.
- `sudo`가 필요하면 exact 명령 목록만 허용하고 설정 변경 명령을 포함하지 않습니다.
- 비밀번호, private key, 전체 환경 변수와 원본 secret을 결과·로그에 남기지 않습니다.
- 계정 잠금·키 폐기·담당자 변경 절차를 문서화합니다.

## 6. 네트워크

- 사용자의 브라우저가 Linux 서버에 직접 SSH 접속하지 않습니다.
- 중앙 API 또는 승인된 Worker가 관리망을 통해 대상 서버의 승인 IP·포트로 연결합니다.
- DNS 이름을 등록하더라도 최종 연결 IP가 허용 CIDR인지 다시 확인해야 합니다.
- redirect, proxy, 임의 포트와 사용자 입력 command를 허용하지 않습니다.
- 점검 중 연결이 끊기면 읽지 못한 항목을 양호로 만들지 않습니다.

사용자는 SSH 터미널 화면을 열어 둘 필요가 없습니다. 중앙 서비스와 Worker가 실행 중이고 방화벽 경로가 유지되어야 합니다.

## 7. 일반 사용자 점검

1. `리눅스 서버 점검`을 엽니다.
2. 활성화된 서버 별칭을 선택합니다.
3. 이번 기준값을 확인합니다.
4. `Linux 서버 자동 확인 및 점검 시작`을 누릅니다.
5. 자동 식별 결과와 67개 진행 상태를 확인합니다.
6. 결과·PDF·AI 설명을 확인합니다.

서버 목록은 Linux 종류 선택 화면이 아닙니다. Ubuntu/Rocky 같은 배포판 정보는 접속 후 시스템이 확인합니다.

## 8. 활성화가 차단되는 경우

- host key가 없거나 Ed25519 형식이 아님
- 연결 시 받은 host key가 등록값과 다름
- IP가 승인 CIDR 밖이거나 변경됨
- `/etc/os-release` 또는 architecture를 읽지 못함
- 미지원·불완전·충돌 플랫폼 식별
- 권한 부족, timeout 또는 출력 형식 위반

관리자는 원인을 해결한 뒤 다시 사전 확인합니다. 비슷한 OS 기준으로 자동 fallback하지 않습니다.

## 9. 현재 남은 운영 Gate

- 지원 배포판의 정상·취약·권한 부족 VM 등록 반복 E2E와 RHEL 9 공식 이미지 인수
- host key 변조·CIDR 우회·DNS rebinding 공격 회귀
- 운영 KMS/HSM·key rotation·폐기·감사
- 망 구간별 Worker와 고가용성
- 조직 SSO·운영 TLS·책임자 승인
- Linux Audit Pack 운영 승인과 조직 서명
