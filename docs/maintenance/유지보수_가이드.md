## 2. 실행 구조

```text
Browser / Windows Launcher / Linux one-shot
        ↓ 127.0.0.1:18480
Gateway
        ↓
FastAPI API ── PostgreSQL + pgvector
        │              └─ 업무 정본·대화·결과·Guide 검색 projection
        ├─ Redis → Worker / Maintenance Worker / Scheduler
        ├─ ClamAV
        ├─ AIStor(라이선스가 있는 개발 환경만)
        └─ Model Gateway → 승인된 OpenAI 호환 시험 upstream

Windows Collector / Linux SSH·one-shot / Aruba REST Adapter
        ↓ 검증된 최소 Evidence
Normalizer → 승인 allowlist Rule Engine → append-only Finding
                                      └→ KISA 근거 + AI 설명
```

공식 상태를 만들 수 있는 주체는 승인·서명된 Audit Pack과 결정론 규칙 엔진뿐입니다. Collector, UI, LLM, Agent와 MCP는 공식 상태를 만들거나 변경하지 않습니다.

## 4. 변경 유형별 절차

### 4.1 API·SSE

1. 외부 입력 DTO와 상태 전이를 먼저 확인합니다.
2. 조직·소유자·자산 범위를 서버에서 다시 검증합니다.
3. 인증·RBAC·RLS·CSRF·IDOR와 안전한 오류 응답을 유지합니다.
4. SSE 재연결·중단·timeout·중복 요청의 멱등성을 시험합니다.
5. 관련 단위·실제 HTTP 시험, Ruff와 mypy를 실행합니다.

### 4.2 Web UI

1. 공통 component·CSS·JavaScript가 있는지 먼저 확인합니다.
2. `textContent` 또는 제한 AST/DOM renderer를 사용하고 모델·검색 결과를 `innerHTML`에 넣지 않습니다.
3. keyboard, focus, label, desktop/mobile, 주야간 theme을 확인합니다.
4. 버튼에 연결된 API가 없으면 `LIVE`로 표시하지 않습니다.

### 4.3 Schema·DB

1. JSON·DB 계약과 Fixture를 구현 코드보다 먼저 변경합니다.
2. 기존 migration은 수정하지 않고 새 revision을 추가합니다.
3. append-only, unique key, RLS, transaction과 replay 의미를 확인합니다.
4. migration 적용 순서와 구버전 application 공존 가능성을 검토합니다.
5. Schema 예제와 관련 DB 통합시험을 실행합니다.

### 4.4 Collector·플랫폼 Adapter

1. Probe ID·version·고정 argv와 parser를 allowlist에 둡니다.
2. 일반 권한을 우선하고 관리자·sudo는 사용자 동의와 exact 범위만 허용합니다.
3. timeout, stdout/stderr 상한, process tree 종료와 locale을 고정합니다.
4. 사용자 입력 명령·경로·정규식·SQL·NETCONF/REST payload를 실행하지 않습니다.
5. 수집 실패·권한 부족·미지원을 `FAIL`이나 부분 `PASS`로 바꾸지 않습니다.
6. 설정 diff 0과 원본 상태 보존을 확인합니다.

### 4.5 Audit Pack·규칙

1. Guide Catalog의 `APPROVED`와 Audit Pack의 `APPROVED`를 분리합니다.
2. LLM 산출물은 실행 불가능한 `DRAFT` 제안으로만 취급합니다.
3. 합성 Fixture, edge case, 동일 입력 100회 hash, false PASS 0을 확인합니다.
4. 승인·서명·폐기 Gate 전에는 운영 Finding을 만들지 않습니다.
5. 과거 Finding이 참조하는 Pack version과 hash를 삭제하거나 덮어쓰지 않습니다.

### 4.6 검색·AI 설명

1. 원본 PDF exact hash와 page/control mapping을 확인합니다.
2. 조직·문서 범위와 citation page·section·paragraph를 고정합니다.
3. 모델에는 비식별 결과 projection과 승인된 검색 근거만 전달합니다.
4. 모델 출력은 불신 입력이며 공식 상태·실제값·KISA 문구를 만들 수 없습니다.
5. timeout·중단·근거 없음·upstream 장애에서도 Core 결과를 보존합니다.
6. OpenRouter 시험 대역을 로컬 vLLM 완료로 표시하거나 자동 fallback으로 연결하지 않습니다.

### 4.7 의존성·Container

1. 표준 라이브러리와 기존 잠긴 의존성을 먼저 사용합니다.
2. 신규 production 의존성은 추가 이유·대안·license·취약점·유지보수성을 검토합니다.
3. `requirements/*.in` 변경 뒤 플랫폼 lock·hash·SBOM을 갱신합니다.
4. Container는 잠긴 `tag@digest`, non-root·read-only·capability drop 원칙을 유지합니다.
5. Compose·Dockerfile·network·secret 변경은 사용자 승인과 재빌드·통합시험이 필요합니다.

### 4.8 알려진 취약점 점검

1. 인벤토리, 공개 Feed 후보, 공급자 확정, VEX와 조직 Finding을 분리합니다.
2. 자동 비교 제외를 취약점 수로 세거나 이름 유사도만으로 제품을 연결하지 않습니다.
3. Feed 없음·오래됨·오류를 `취약점 없음`으로 표시하지 않습니다.
4. 공식 원문 번역은 원문 사실을 추가·삭제하지 않고 선택형 AI 쉬운 설명과 분리합니다.
5. cache append-only, organization/owner 범위와 허용된 공식 링크를 시험합니다.

## 5. 표준 검증

문서·주석만 바꾼 경우에는 링크·catalog 생성·PowerShell 문법 검사를 우선합니다. 제품 로직을 바꾼 경우 위험도에 맞는 관련 시험을 추가합니다.

```powershell
# 파일 카탈로그 재생성
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\generate-repository-catalog.ps1

# Docker 기반 전체 표준 Gate
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\dev.ps1 -Action All

# 실행 서비스 상태
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\core.ps1 -Action Status
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\core.ps1 -Action Health
```

전체 Gate가 현재 작업 밖 기존 불일치로 실패하면 기대값을 약화하거나 시험을 숨기지 않고 관련 여부와 로그를 기록합니다.

## 6. 장애 확인 순서

| 현상 | 먼저 확인 | 다음 확인 |
|---|---|---|
| `docker compose` 실패 | Docker Desktop Linux container mode, `docker compose version` | `.env`, secret file 존재, port 충돌 |
| API `live` 실패 | `core.ps1 -Action Status` | `core.ps1 -Action Logs`, migration·DB health |
| `ready`만 503 | AIStor license·의존 서비스 상태 | 의도한 `UpWithoutAIStor`인지 확인 |
| 로그인 실패 | DEV secret 파일과 bootstrap 수행 여부 | session·CSRF·canonical origin |
| AI만 실패 | Model Gateway 상태·승인 API key | timeout·egress·model ID; Core 결과는 보존 |
| Guide 검색 실패 | PDF hash·Catalog·mapping | PostgreSQL generation·embedding/reranker mode |
| Linux 점검 실패 | 등록 자산·ACTIVE 상태·SSH host key | 자동 OS 식별·권한·고정 Probe 오류 |
| Linux 원샷 실패 | artifact hash·일회용 코드·Package 서명 | tunnel·online/offline 제출·descriptor |
| Switch 점검 실패 | AOS-CX version·인증서 지문·REST 권한 | 허용 GET path·timeout·조직 보완값 |
| 취약점 비교 실패 | 최근 Windows 인벤토리·Feed 기준 시각 | NVD/OSV cache·package ecosystem·모델 번역 연결 |
| Windows Launcher 실패 | 기존 18481/18482 process·중복 실행 | Collector build hash·loopback callback |

로그에는 token, cookie, password, private key, 실제 사용자·조직·호스트 식별자와 원본 증적을 복사하지 않습니다.

## 7. 문서·ADR 관리

- 현재 상태는 `구현_현황.md`, 구조·실행은 루트 `README.md`, 역할별 목차는 `docs/README.md`가 정본입니다.
- 의사결정 의미가 바뀌면 기존 ADR 본문을 조용히 덮지 않고 version·후속 상태·영향·승인 기록을 남깁니다.
- ADR을 수정하면 `docs/adr/README.md`의 기준일·상태·SHA-256을 다시 계산합니다.
- `deploy/verification`은 과거 실행 주장과 공급망 근거이므로 현재와 다르다는 이유로 삭제하지 않습니다.
- 현재 정본과 충돌하는 임시 메모는 참조 0, 대체 문서 존재, hash·복구 가능성을 확인한 뒤 삭제 Manifest에 기록합니다.
- 문서를 추가·삭제하면 `docs/README.md`와 해당 하위 `README.md`의 링크를 함께 갱신합니다.

## 9. 다른 PC 이전

새 PC 설치와 source-only·offline image bundle 절차는 [`다른 PC 설치·이전 안내`](../guides/다른_PC_설치_및_이전_안내.md)를 따릅니다. 실제 `.env`, Secret, AIStor license, 원본 증적, DB volume과 VM은 일반 source 묶음에 포함하지 않고 승인된 별도 경로로 이전합니다.
