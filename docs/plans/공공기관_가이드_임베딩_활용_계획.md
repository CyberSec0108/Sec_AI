# 공공기관 보안 가이드 반입·활용 현황

## 현재 반입 범위

KISA 주요정보통신기반시설 가이드를 직접 점검 근거로 사용하고, 다음 공공기관 문서를 보완 설명과 질문 응답에 사용합니다.

- N2SF 보안가이드라인 1.0
- N2SF 보안통제 항목 해설서
- 제로트러스트 가이드라인 2.0
- SW 공급망 보안 가이드라인 1.0
- AI 보안 안내서 정오 수정본
- AI 보안 위협 대응 매뉴얼
- AI 보안 레드티밍 가이드

승인 원본 PDF는 `data/`에 두고 Guide Catalog의 기관·제목·version·원문 hash·쪽수·이용조건·검색 상태와 연결합니다. PDF 파일이 있다는 이유만으로 자동 검색하거나 공식 판정 근거로 승격하지 않습니다.

## 활용 방법

| 용도 | 사용 문서 | 결과에 미치는 영향 |
|---|---|---|
| Windows·Linux·Switch 공식 판정 | 승인 Audit Pack과 직접 KISA Control Source | 상태 결정 가능 |
| 점검 결과 쉬운 설명 | 직접 근거를 우선하고 공공 가이드를 보완 | 설명만 보완 |
| 가이드 질의 | 질문과 관련된 승인 문서를 통합 검색 | 답변·citation 생성 |
| AI·제로트러스트·공급망 질문 | 주제별 공공 가이드 우선 검색 | 일반 보안 설명 |
| 새 규칙 제안 | 문서 근거를 사용한 `DRAFT` 제안 | 즉시 실행 불가 |

예를 들어 Linux U-01 상태는 KISA 기반 규칙이 결정하고, 제로트러스트 문서는 최소권한·인증·접근통제의 보완 설명에만 사용합니다.

## 현재 처리 흐름

```text
원본 PDF hash·Catalog 승인
→ 쪽별 text·Page Map
→ chunk와 metadata
→ BGE-M3 embedding
→ 질문별 hybrid 검색·rerank
→ 승인된 문단만 LLM 입력
→ 문서명·쪽 citation
```

metadata에는 guide ID/version, 기관, 문서명, 쪽, section, chunk ID, 원문 hash, 조직 scope, 승인 상태와 embedding generation이 포함됩니다.
