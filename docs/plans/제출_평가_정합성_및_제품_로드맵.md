# 제출 평가 정합성·제품 로드맵

## 제출 시 현재 기능을 표현하는 방법

| 영역 | 안전한 표현 | 쓰지 말아야 할 표현 |
|---|---|---|
| 점검 결과 | 개발용 DRAFT 규칙 판정 | 공식 인증·완전한 취약점 진단 |
| AI | 결과 설명·가이드 근거 종합 | AI가 공식 판정·자동 조치 |
| 취약점 | NVD·OSV 영향 가능성 후보 | 제조사 확정 취약 판정 |
| Linux·Switch | 지원 Catalog에 일치한 읽기 전용 점검 | 모든 Linux·모든 스위치 지원 |
| 다운로드 | DEV-SIGNED-TEST 개발 체계 | 조직 운영 코드서명 완료 |
| 모델 | 현재 승인 개발 연결과 로컬 vLLM 준비 | 완전한 온프레미스 운영 완료 |

## 제출 전에 필요한 산출물

- 제품 범위·제외 범위와 아키텍처
- 지원 OS·배포판·장비·version matrix
- SBOM, image digest, 의존성 취약점·악성코드 검사
- Audit Pack·Guide Catalog·AI 권한 분리 설명
- 정상·취약·권한 부족·변조·타 조직 공격 시험
- 개인정보·비밀정보·외부 모델 projection 설명
- 결과 예시와 공식 판정이 아닌 항목의 명확한 표시
- 모델명·provider·context·embedding·reranker 명세
- backup·restore·RPO/RTO·보존정책
- 조직 서명·KMS·승인자와 미완료 Gate

## 제출 준비 순서

1. 범위와 지원 matrix를 현재 code에 맞춰 동결합니다.
2. 잠긴 source·image·Pack·Guide·모델 manifest를 생성합니다.
3. 전체 Gate와 실제 장비/VM 시험을 실행합니다.
4. 실패·미완료·제한 사항을 숨기지 않고 표로 정리합니다.
5. 사용자 시나리오별 화면·PDF·로그·hash 증거를 묶습니다.
6. 라이선스·원문 이용조건·재배포 범위를 검토합니다.
7. 제출본과 실제 실행 artifact SHA-256을 연결합니다.

## 정량 지표

- 점검 항목 coverage와 false PASS 회귀 수
- 실제 장비/VM 반복 재현율
- 수집·판정·AI 설명 latency와 중단 성공률
- Guide citation precision·recall@k
- 권한·IDOR·RLS 공격 차단율
- offline Feed freshness와 후보 재현성
- backup·restore 성공 시간

문서의 완료 주장보다 [`../../deploy/verification/`](../../deploy/verification/)의 실제 실행 증거를 우선합니다.
