# 저장소·Runtime 정리 계획

## 목적

source, 승인 문서와 재현에 필요한 fixture는 보존하고, 재생성 가능한 cache·build 산출물·임시 로그가 저장소 정본처럼 쌓이지 않게 합니다.

## 분류

| 분류 | 예 | 처리 |
|---|---|---|
| 정본 | source, Schema, migration, Pack source, fixture, ADR | 보존 |
| 승인 입력 | `data/` 원본 PDF와 Catalog metadata | hash·이용조건과 함께 보존 |
| 검증 기록 | `deploy/verification` | 과거 기록 보존, 덮어쓰기 금지 |
| 생성 가능 | build, cache, 임시 PDF, coverage, local log | 재생성 확인 후 정리 가능 |
| Runtime 상태 | DB volume, AIStor, Redis, key store | source와 분리, 임의 삭제 금지 |
| 비밀정보 | `.env`, token, private key, 인증서 | 저장소·문서에 복제 금지 |

## 정리 순서

1. `rg --files`와 생성 도구 문서로 source/fixture/runtime을 분류합니다.
2. 삭제 후보의 생성 명령과 출력 위치를 확인합니다.
3. 관련 기능 집중시험을 실행합니다.
4. backup 또는 재생성 가능성을 확인합니다.
5. exact 파일 목록을 검토한 뒤 정리합니다.
6. 같은 build·시험으로 다시 생성되는지 확인합니다.
7. 문서 카탈로그를 재생성합니다.

## 삭제 금지

- 기존 migration
- Pack source·signature·fixture
- Guide Catalog·Page Map·승인 원본
- 검증 기록
- 운영 또는 개발 DB·AIStor volume
- 사용자 결과와 append-only 감사
- 현재 동작하는 build script와 잠긴 dependency input

## 현재 후속 작업

- `runtime`, `.runtime`, `downloads`, `tmp`의 owner와 retention 명시
- Windows/Linux artifact build output 표준화
- 오래된 test report·browser screenshot의 보존 기준
- source tree에 남은 실제 secret 자동 탐지 Gate
- catalog 생성 제외 규칙 회귀

정리는 기능 변경과 분리해 수행하고, 사용자가 만든 파일이나 현재 작업 중 변경을 임의로 삭제하지 않습니다.
