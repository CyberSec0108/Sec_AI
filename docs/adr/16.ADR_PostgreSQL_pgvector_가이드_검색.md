# ADR-016: PostgreSQL+pgvector 기반 가이드 근거 검색

## 현재 구현 상태 (2026-08-07 검토)

- 승인 문서 8종의 통합 검색, PostgreSQL+pgvector, BGE-M3 1024차원 embedding과 전용 reranker가 개발 환경에서 동작한다.
- 32차원 legacy generation은 rollback용으로 보존하고 현재 mode는 `BGE_M3_WITH_LEGACY_FALLBACK`이다.
- 화면의 문서 선택·질문 범위 UI는 제거했지만 Catalog 승인·조직 scope·citation page 필터는 유지한다.
- 관리자 PDF 반입 UI와 정식 검색 품질 benchmark는 남아 있다. 검색 성공을 공식 판정 승인으로 해석하지 않는다.

| 항목 | 내용 |
|---|---|
| 상태 | **승인** — 2026-07-24 사용자 기술 방향 반영 |
| 결정 대상 | IMP-048 이후 KISA 가이드 근거 검색 저장소와 운영 경계 |
| 대체 결정 | Milvus·etcd·Milvus 전용 object store 도입 계획 |
| 참고 ADR | `renew_v4/docs/adr`의 ADR-014, ADR-016, ADR-017, ADR-019, ADR-025 |

## 1. 결정

Sec_AI의 가이드 검색은 별도 Milvus cluster를 도입하지 않고 기존 PostgreSQL 18.4에 pgvector 0.8.2를 결합해 구현한다.

```text
AIStor
└─ 승인된 가이드 원본·추출 artifact

PostgreSQL
├─ guide_content — 문서 version·chunk·페이지·hash 정본
└─ vector_store  — pgvector embedding·검색 세대·활성 pointer

Redis
└─ 반입·embedding 작업의 짧은 Queue 상태
```

Milvus, PyMilvus, Attu, Milvus용 etcd와 전용 object store는 Sec_AI 운영 구성에 추가하지 않는다. 향후 pgvector가 승인된 규모·지연·검색 정확도 기준을 충족하지 못할 때만 별도 ADR로 재검토한다.

## 2. 선택 근거

- 문서 version, 조직 권한, 검색 범위와 활성 vector 세대를 하나의 PostgreSQL transaction 경계에서 관리할 수 있다.
- 별도 vector control plane·etcd·object store를 줄여 MVP 운영과 복구 복잡도를 낮춘다.
- PostgreSQL RLS, 최소권한 role, backup·PITR과 기존 관측 체계를 재사용할 수 있다.
- vector는 정본이 아니라 승인 문서에서 다시 만들 수 있는 projection으로 유지한다.
- 질문에 사용한 chunk·페이지·source hash를 PostgreSQL 정본으로 역추적할 수 있다.

## 3. 저장 책임

### `guide_content`

- 승인된 Guide ID·version·source SHA-256·조회 scope
- chunk의 page·Control·순서·text SHA-256
- 검색에서 표시할 승인 text
- 문서·chunk 상태와 보존·폐기 상태

### `vector_store`

- `vector_generation_id`
- embedding model ID·dimension·distance metric
- chunk ID·변경 탐지 fingerprint·embedding
- 조직·가이드·version·scope별 단 하나의 ACTIVE generation

vector row에는 원문, 제목, 사용자 질문, 사용자·조직 표시명과 비밀값을 복제하지 않는다.

## 4. 보안과 권한

- PostgreSQL runtime 계정은 DDL을 실행할 수 없다.
- `guide_content`와 `vector_store`는 조직 ID 기준 RLS와 `FORCE ROW LEVEL SECURITY`를 사용한다.
- 검색 전 서버가 transaction-local 조직 context를 설정한다.
- runtime 계정은 raw embedding을 직접 `SELECT`할 수 없다.
- 검색은 고정 `search_path`를 가진 검토된 함수로 chunk ID와 score만 반환한다.
- 함수 결과는 canonical chunk를 다시 조직·가이드·version·scope로 확인한 뒤 hydrate한다.
- vector, 질문, chunk 전문을 로그·trace·일반 API에 출력하지 않는다.
- 일반 사용자는 제품의 안전 조회 API만 사용하고 raw vector·DB URL·비밀번호를 볼 수 없다.
- 개발 관리자는 digest로 잠근 pgAdmin을 `127.0.0.1:18490`에서만 사용한다.
- `secai_db_admin`은 슈퍼유저·DB/Role 생성·복제 권한 없이 DEV 조직의 Guide DML과 관찰 권한만 가진다.
- PostgreSQL `5432`는 host에 publish하지 않으며 pgAdmin에서도 RLS와 DB 제약을 우회하지 않는다.

## 5. 반입 Gate

실제 가이드 text는 다음 조건이 모두 참일 때만 저장한다.

1. exact source hash와 페이지 map 확인
2. 로컬 내부 저장·가공·검색 이용 조건 승인
3. 파생 text 저장 허용
4. ClamAV 등 승인 scanner 검사 `CLEAN`
5. OCR·text 추출 품질 승인
6. 조직·Guide·version·scope 조회 범위 승인

하나라도 미완료면 `BLOCKED`이며 vector generation을 만들지 않는다. 합성자료는 `SYNTHETIC_TEST_ONLY`로 분리하고 실제 KISA 원문 승인 우회에 사용할 수 없다.

## 6. 검색과 세대 전환

```text
PLANNED → BUILDING → VALIDATING → READY → ACTIVE
                    ↘ FAILED
ACTIVE → RETIRED
```

- chunk와 embedding은 immutable generation으로 만든다.
- dimension은 generation manifest와 DB constraint에서 고정한다.
- 완성 전 generation은 검색하지 않는다.
- 조직·Guide·version·scope별 ACTIVE pointer를 원자적으로 전환한다.
- HNSW cosine 검색 후 승인된 reranker가 순서를 조정한다.
- dense·lexical·rerank score는 서로 구분해 보존한다.
- 검색 결과가 없으면 `NO_EVIDENCE`, schema·세대가 없으면 `UNAVAILABLE`로 구분한다.

## 7. IMP-048 적용 상태

- PostgreSQL 18.4 + pgvector 0.8.2 고정 digest
- Alembic `0006_imp048` 검색 schema + `0007~0008_imp048` 실제 반입 조회·관리 경계
- `guide_content`·`vector_store` schema
- HNSW cosine index와 active generation
- 조직·Guide·version·scope 필터
- raw vector runtime read 차단
- 합성자료 chunk·embedding·검색·rerank 실제 DB 검증
- exact KISA PDF: ClamAV `CLEAN`, PC 41쪽 text hash·글자 수·페이지 연결 일치
- 실제 KISA 원문: 문서 1건·chunk 41건·embedding 41건·ACTIVE generation 1건
- 일반 조회 UI `/ui/guide-store`, 관리자 pgAdmin `127.0.0.1:18490`

현재 KISA Catalog는 프로젝트 내부 검색용 `APPROVED`이며 파생 text·chunk·embedding 저장을 허용한다. 외부 재배포는 금지한다. Guide 승인은 Mapping·Audit Pack 승인이 아니므로 LLM 답변과 공식 판정 활성화는 계속 차단한다.

## 8. 완료·재검토 기준

- 실제 KISA 반입 승인과 악성코드·추출 품질 검사: **완료**
- PC 41쪽의 chunk 수·page hash·source hash 대조: **완료**
- IMP-049 검색·인용 평가에서 정확도와 근거 부족 기준을 통과한다.
- backup/restore 후 ACTIVE generation과 검색 결과가 재현된다.
- 조직·범위 우회와 raw vector export가 0건이다.

별도 vector DB 재도입은 corpus 규모, pgvector p95/p99, recall@k, 운영비용과 복구시간을 측정해 위 기준을 충족하지 못한 경우에만 새 ADR로 결정한다.

## 9. 복수 기준 출처 확장 경계

`guide_content`는 향후 KISA뿐 아니라 이용 허가와 품질 검사를 통과한 조직 정책·제조사 문서·다른 보안 가이드를 별도 source/version/generation으로 보관할 수 있다. 검색 승인은 해당 문서를 내부에서 찾고 인용할 수 있다는 의미일 뿐, 조직 기준이나 공식 Audit Pack 승인이 아니다.

사용자가 입력한 한두 문장의 개인 기준은 원문 Guide 전체와 동일하게 취급하지 않는다. `criteria_source`에 작성자·조직·적용범위·version·effective date·상태를 기록하고, 원문 파일을 반입할 때만 악성코드·OCR·페이지 연결 Gate를 적용한다. 검색 답변은 출처 유형과 기준 Profile을 표시하고 KISA·조직·개인·모델 일반지식을 섞어 하나의 공식 근거처럼 보이지 않게 한다. Profile·승격·Pack compile은 ADR 20에서 결정한다.

## 10. 2026-08-03 BGE-M3 병렬 세대 구현 상태

기존 32차원 generation을 수정하거나 폐기하지 않고 1,024차원 BGE-M3 generation을
신규 migration과 별도 table/column 경계로 추가했다. 현재 개발 Runtime은 다음과 같다.

| 항목 | 현재 값 |
|---|---|
| 검색 mode | `BGE_M3_WITH_LEGACY_FALLBACK` |
| rollback model | `secai-ko-lexical-hash-v1`, 32차원 |
| embedding model | `BAAI/bge-m3`, revision `5617a9f61b028005a4858fdac845db406aefb181`, 1,024차원, MIT |
| reranker | `BAAI/bge-reranker-v2-m3`, revision `953dc6f6f85a1b2db5ca4e4448582d29648a52bb`, Apache-2.0 |
| Runtime image | `ghcr.io/huggingface/text-embeddings-inference:86-1.8` |
| model cache | embedding·reranker 각각 전용 Docker volume |
| DB 확인 | 32차원·1,024차원 ACTIVE generation 병렬 보존, BGE vector 908건 |
| 자원 정책 | RTX 3060 6GB에서 embedding·reranker·vLLM 동시 상주 금지 |

질문은 lexical candidate와 model embedding candidate를 결합하고 환경 변수로 top-k,
candidate 수, RRF, dense/lexical/base/reranker 가중치와 최소 score를 조정한다. 모델
service가 실패하면 기존 32차원 검색으로 되돌리되 공식 판정이나 저장된 결과는 바꾸지
않는다.

다만 이 상태는 **운영 전환 승인**이 아니다. PC·UNIX/Linux·Switch·Network·Web의
대표/복합/비교/모호 질문에 대해 recall@k, MRR, 인용 정확도, p95와 조직 격리를 기존
32차원 기준선과 비교하고 품질 Gate를 통과해야 한다. model revision·license·weight
hash와 image digest는 `deploy/locks/search-models.lock.yml`을 정본으로 사용한다.
