# ADR-017 — vLLM 호환 모델 게이트웨이와 단계적 로컬 전환

## 현재 구현 상태 (2026-08-07 검토)

- API는 내부 Model Gateway만 호출하며 현재 승인된 개발 upstream은 OpenRouter 호환 시험 경로다.
- 로컬 vLLM image·connector 계약은 준비됐지만 승인 모델·GPU·image 취약점·egress 0·품질 인수를 통과하지 않아 운영 Runtime이 아니다.
- upstream을 바꿔도 결과 DTO·stream·중단·출력 검증과 공식 판정 불변 계약을 유지해야 한다.
- 모델 장애 시 규칙 결과·저장 결과·기존 AI cache를 보존하며 임의 외부 endpoint로 자동 fallback하지 않는다.

## 1. 배경

Sec_AI는 KISA 검색 근거와 실제 PC 점검 결과를 설명하는 LLM이 필요하지만, 현재 PC에는 vLLM용 모델·GPU/CUDA·driver 기준이 준비되지 않았다. 그렇다고 OpenRouter 전용 코드를 Core API에 직접 결합하면 나중에 로컬 vLLM으로 바꿀 때 API·비밀정보·오류 처리까지 다시 작성해야 한다.

vLLM과 OpenRouter는 모두 OpenAI 호환 `/v1/models`와 `/v1/chat/completions` 계약을 제공한다. 따라서 모델 실행 엔진과 Sec_AI Core 사이에 작은 내부 연결 게이트웨이를 둔다.

OpenRouter를 vLLM 자체로 간주하지는 않는다. 현재 OpenRouter는 요청·응답·SSE·오류·모델 설정 전환이라는 **OpenAI 호환 연결 계약만 미리 시험하는 대역**이다. 개인정보 보호, 폐쇄망, 지연시간, GPU 용량, 실제 모델 동작, 모델 파일 공급망과 라이선스 Gate는 로컬 vLLM에서 별도로 통과해야 한다.

## 2. 결정

### 2.1 지금 구현하는 것

- 프로젝트 image `sec-ai-mvp/model-gateway:0.1.0`
- 내부 container `model-gateway`
- `OPENAI_CHAT_COMPLETIONS` 단일 연결 계약
- 현재 OpenRouter 주소·모델과 runtime-only API key를 사용한 비식별 호환성 시험
- 사용자가 승인한 현재 시험 환경의 정규화된 점검 결과와 KISA 근거를 이용한 결과 설명 시험
- `FAST`·`PRECISE` profile과 안전한 오류 분류
- 모델 목록 조회와 비민감 생성 연결 시험
- 로그인 사용자가 볼 수 있는 `AI 연결 상태` 화면

### 2.2 지금 구현하지 않는 것

- vLLM GPU 추론 실행과 모델 weight 적재
- GPU/CPU 추론 성능 승인
- 실제 사용자 PC 원본 증적·식별자·전체 KISA 원문을 OpenRouter에 전송
- 자동 모델 변경이나 다른 유료 모델 fallback
- LLM의 Finding·Audit Pack·Rule write

`model-gateway`는 vLLM 자체가 아니다. 현재는 OpenRouter를 `VLLM_COMPATIBILITY_TEST_DOUBLE`로 사용하는 OpenAI 호환 connector다. `PRODUCT-AI-09`에서는 공식 NVIDIA GPU vLLM image를 exact digest로 잠근 얇은 wrapper와 자동 시작되지 않는 container까지만 준비한다. GPU·driver·CUDA·승인 모델이 없는 현재 PC에서는 container를 실행하지 않고, 실제 설명은 계속 OpenRouter를 사용한다.

### 2.3 시험 대역으로 확인할 수 있는 것과 없는 것

| 구분 | OpenRouter 시험에서 확인 | 로컬 vLLM에서만 최종 확인 |
|---|---|---|
| API | `/models`, `/chat/completions`, 인증 header, timeout, 오류 변환 | 동일 endpoint의 실제 로컬 배치 주소·접근통제 |
| Streaming | SSE 순서·중단·재시도·완료 저장 | 로컬 모델의 TTFT·token 속도·동시성·메모리 |
| 계약 | 입력/출력 Schema, citation, canonical hash, 모델 설정 변경 | 실제 모델 revision별 출력 품질·결정성 |
| 보안 | 합성 입력과 승인된 시험 환경의 비식별·정규화 점검 결과, secret 비노출, 자동 fallback 금지 | 외부 egress 0, 원본 PC 결과의 로컬 처리, 폐쇄망 |
| 공급망 | OpenRouter 서비스·선택 모델 정보 기록 | vLLM image digest·SBOM과 weight hash·출처·license·악성 파일 검사 |

OpenRouter 시험 통과를 “로컬 vLLM 운영 준비 완료” 또는 “데이터가 외부로 나가지 않음”으로 표시하지 않는다.

## 3. 전환 계약

현재 호환성 시험:

```text
Sec_AI API
→ internal model-gateway
→ https://openrouter.ai/api/v1
→ openai/gpt-oss-120b
```

최종 제품:

```text
Sec_AI API
→ 같은 internal model-gateway
→ http://vllm:8000/v1
→ 승인된 local served model name
```

Connector 계약에서는 다음 두 비밀정보가 아닌 설정을 바꿔 로컬 endpoint와 served model을 선택한다.

```text
SECAI_LLM_API_BASE
SECAI_LLM_MODEL
```

로컬 vLLM은 기존 gateway가 보내는 Bearer key를 받도록 `--api-key`를 설정할 수 있으므로 connector·Core API·화면 계약은 바꾸지 않는다. 다만 주소·모델 변경만으로 **연결**하는 것과 최종 **제품 인수**는 다르다. 제품 인수에는 제6절의 Runtime·보안·성능·공급망 Gate가 추가로 필요하다.

## 4. 보안 경계

- OpenRouter API key는 `runtime/dev-secrets/llm_api_key`에만 두며 source·image·Compose 환경값·문서·로그에 넣지 않는다.
- API container에는 OpenRouter key를 주지 않는다.
- API와 model-gateway 사이에는 별도 256-bit 내부 token을 사용한다.
- model-gateway는 host port를 publish하지 않는다.
- model-gateway만 외부 통신이 가능한 `frontend_net`과 Core 접근용 `app_net`에 함께 연결한다.
- OpenRouter 시험 입력은 합성 입력 또는 사용자가 승인한 현재 시험 환경의 비식별·정규화 점검 결과로 제한한다.
- `PRODUCT-AI-04`에서는 실제 시험 점검의 `control_id`, 규칙 상태, 사용자용 실제값·기준값·확인 방법과 검색된 KISA 관련 문단만 모델 입력으로 사용한다. 원시 증적은 포함하지 않는다.
- 실제 PC 원본 증적, 사용자·조직·Asset 식별자, SID·hostname, 전체 레지스트리 dump와 KISA 원문 전체는 보내지 않는다.
- 호출자가 보낸 model·base URL·추가 provider parameter는 받지 않고 서버 설정으로 고정한다.
- 역할·본문 길이·메시지 수·출력 token·temperature를 제한한다.
- upstream 오류 본문과 내부 reasoning은 사용자 응답·검증 기록에 포함하지 않는다.
- remote HTTP는 거부하고 HTTPS만 허용한다. HTTP는 loopback·사설 IP·Docker 내부 이름의 로컬 vLLM에만 허용한다.
- 모델 장애는 `AI_UNAVAILABLE_CORE_CONTINUES`로 처리한다. PC 점검과 공식 Finding은 계속 동작한다.
- 자동 모델 fallback은 금지한다. 비용·license·출력 특성이 다른 모델로 조용히 전환하지 않는다.
- 최종 로컬 vLLM profile에서 OpenRouter로 자동·수동 우회하는 숨은 fallback을 두지 않는다.

## 5. 모델·서비스 조건

`gpt-oss-120b` weight의 라이선스는 Apache 2.0이다. OpenRouter를 통한 현재 사용에는 모델 라이선스와 별도로 OpenRouter의 서비스 이용조건·개인정보 처리조건이 적용된다.

현재 개발 연결은 OpenAI 호환 transport와 현재 시험 환경의 비식별 점검 결과 설명 시험용으로 사용자가 명시적으로 승인했다. 이 승인은 OpenRouter를 제품 운영 모델로 승인하거나 원본 증적·식별정보·운영 PC 결과의 외부 전송을 승인한 것이 아니다. 현재 시험 기록에는 provider·model·목적·입력 필드·비식별 여부·외부 전송 여부를 남긴다.

## 6. CPU/GPU·로컬 vLLM Gate

| 항목 | 현재 상태 | 로컬 전환 전 Gate |
|---|---|---|
| CPU-only vLLM | 빌드하지 않음·현재 범위 제외 | 별도 요구와 장비 기준 승인 전 도입 금지 |
| GPU | 미구성 | GPU model·VRAM·driver·CUDA 호환표 |
| `gpt-oss-120b` | 원격 API 사용 | 단일 80GB GPU급 공식 참고조건과 실제 장비 시험 |
| vLLM image | NVIDIA GPU v0.23.0 exact digest wrapper·중지 container 준비 | 취약점 Gate 실패 해소 후 다시 SBOM·취약점·provenance 확인 |
| model weight | 미반입 | exact hash·출처·license·사용정책·악성 파일 검사 |
| 성능 | 원격 연결만 검증 | 빠른/정밀 TTFT·throughput·timeout·동시성 |
| 데이터 경로 | OpenRouter 비식별 시험 | 실제 설명·후속 질문·보고서 입력의 외부 egress 0 |
| 모델 등록정보 | 시험 provider·model 기록 | served model·revision·base model·license·weight hash·배치 위치 기록 |

현재 연결용 gateway image에 `vllm` package나 모델 weight를 넣지 않는다.

Connector 자체는 CPython 3.14.6 Alpine 3.23 기반으로 잠갔다. OpenSSL 3.5.7을
사용하며 CPython `html.parser` 보안 수정은 upstream 3.14 commit
`07efb08123ba9367a7107325adb9d5626dca1ca9`를 exact hash로 backport한다.
이는 vLLM runtime 선택과 무관한 connector 공급망 보완이다.

## 7. 완료 기준

### 7.1 현재 환경 PRODUCT-AI-09

- OpenRouter가 실제 설명 경로로 유지된다.
- `sec-ai-mvp/vllm-openai-gpu:0.23.0` image를 공식 `linux/amd64` digest에 고정한다.
- project image digest는 `sha256:48f9f370497eee3748a693c01030c82dbcee87a0db52f5e7901c9744787f4a00`이다.
- `local-vllm` profile container는 host port 없이 전용 internal network와 read-only 모델 volume만 사용한다.
- 승인 모델이 없을 때 `/models/NOT_CONFIGURED`로 fail-closed하며 container는 `Created` 상태로 둔다.
- UI·PDF 명세에는 `PREPARED_NOT_ACTIVE`, NVIDIA GPU, 모델 미적재·추론 미실행을 사실대로 표시한다.
- SBOM은 생성했지만 수정 가능한 항목만 집계해도 Critical 13·High 181건이 확인되어 `FAIL-RUNTIME-USE-BLOCKED`다. 이 image는 준비 자산일 뿐 실행 승인 자산이 아니다.

### 7.2 OpenAI 호환 Connector

- OpenRouter `/v1/models`에서 설정 model을 확인한다.
- 고정된 비민감 연결 시험이 성공한다.
- API key·gateway token·upstream 오류 원문·reasoning이 출력되지 않는다.
- 잘못된 key, 사용량 제한, rate limit과 모델 장애가 안전한 범주로 변환된다.
- model-gateway 중단이 Core `/health/ready`와 공식 점검을 실패시키지 않는다.
- 사용자 상태 화면이 원격 전송과 로컬 vLLM 미실행 상태를 분명히 표시한다.
- 주소·모델만 바꾼 local vLLM 설정 계약이 자동시험을 통과한다.

위 기준 중 OpenAI 호환 connector 시험은 `IMP-050`에서 충족했다. 다만 “로컬 AI
연결 완료”는 로컬 vLLM 추론이 실행 중이거나 최종 제품 Gate가 통과했다는 뜻이
아니다. 지금 완료한 범위는 OpenRouter 시험 대역을 통한 transport 계약이며,
`LOCAL_VLLM_FULL_CONTEXT`는 별도 `LOCAL-VLLM-RUNTIME-GATE`에서 GPU·driver·CUDA,
승인 모델 weight, 로컬 endpoint·성능·공급망·외부 egress 0을 실제로 검증한 뒤에만
완료 처리한다. 현재 환경의 PRODUCT-AI-09 완료와 로컬 추론 완료를 같은 의미로
표시하지 않는다.

## 8. 공식 근거

- OpenRouter는 OpenAI 호환 `/api/v1/chat/completions`와 `/api/v1/models`를 제공한다.
- vLLM은 OpenAI 호환 `/v1/chat/completions`, `/v1/models`와 `--api-key`를 제공한다.
- OpenAI는 `gpt-oss-120b`를 Apache 2.0으로 공개했고 단일 H100급 GPU에 맞는 모델로 설명한다.

정확한 URL과 확인일은 `deploy/verification/IMP050_OpenAI_호환_모델_게이트웨이_검증.md`에 기록한다.

## 9. 지식 보강과 Agent/MCP 연결 경계

`KNOWLEDGE-01~03`에서 모델 gateway 입력·출력에 `secai.result-knowledge.v1` 출처 계약을 적용했다. 실제 확인값 `E1`, 공식 규칙 `R1`, KISA 원문 `G1`, 제조사 문서 `G2`, 승인 공개자료 `G3`, 모델 일반지식 `A1`을 구분하며 공식 판정 권한은 `R1`에만 있다. 현재 결과 설명 prompt는 비식별 실제값·공식 규칙·KISA 근거를 우선하고 모델 일반지식은 배경·용어·주의점 보충에만 사용할 수 있다.

화면과 사용자 PDF의 인라인 인용은 `[1]` 형식을 사용하고 각 항목 아래에 출처를 모아 표시한다. 사용자 출처명은 영문 내부 식별자가 아니라 `KISA PC 보안 가이드 2026 · 555쪽 · PC-01 비밀번호의 주기적 변경`처럼 한글 문서명·쪽수·세부 항목으로 짧게 표시한다. 내부 guide·chunk ID와 hash는 기술 추적 데이터에만 유지한다. 자세한 계약과 검증은 [`KNOWLEDGE_01_03_지식_출처_분리_검증_20260802.md`](../../deploy/verification/KNOWLEDGE_01_03_지식_출처_분리_검증_20260802.md)를 따른다.

MCP access token, 장비 credential, sudo/UAC 권한과 remediation signing key는 모델 gateway에 전달하지 않는다. 모델이 생성한 조치 계획은 구조화된 제안일 뿐이며 별도 정책 계층·사용자 승인·전용 실행기가 검증한다. OpenRouter 시험 대역과 최종 로컬 vLLM 모두 같은 경계를 지킨다.
