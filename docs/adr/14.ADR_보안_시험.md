# ADR-14: 보안시험 전략과 승인 Gate

## 현재 구현 상태 (2026-08-07 검토)

- 단위·계약·RLS·IDOR·변조·timeout·복구·실제 VM/장비 집중시험이 기능별로 추가됐지만 이 ADR 자체의 보안시험 승인은 여전히 운영 Gate다.
- `Pytest 통과`, 개발 VM 통과와 운영 침투·공급망·복구·서명 인수는 서로 다른 결과다.
- 현재 우선 보안시험은 Linux 등록의 host key·CIDR·권한 공격, 조직 서명·KMS, Windows clean VM, Aruba 제품 E2E와 RAG 품질·prompt injection이다.
- 과거 시험 개수는 현재 품질 수치로 재사용하지 않고 최신 `deploy/verification`과 실제 실행 결과를 따른다.

## 1. 결론

Sec_AI의 보안시험은 단순히 “Pytest 숫자가 많다”는 이유로 통과하지 않는다. 다음 세 가지를 모두 만족해야 한다.

1. 승인된 공격·오류·경계조건 시험이 예상 결과를 반환한다.
2. 해당 Release에 필요한 보안 Gate에서 `FAIL`, `BLOCKED`, 승인되지 않은 `SKIPPED`가 없다.
3. 시험한 source revision, dependency lock, container image, Schema, Audit Pack과 실행환경을 다시 확인할 수 있다.

`PASS`는 시험한 조건에서 예상대로 동작했다는 의미다. “취약점이 전혀 없다”, “운영 승인이 끝났다”, “침해가 절대 불가능하다”는 의미가 아니다.

## 2. 이 문서를 별도로 두는 이유

기존 문서에도 보안시험은 존재한다.

- ADR 5: Collector allowlist·권한·서명·실행 제한
- ADR 7: Queue 변조·중복·재시도·Redis ACL
- ADR 8: Schema·JSON·archive·hash 계약
- ADR 9: AIStor·Object Lock·KMS·backup·복구
- ADR 11: RBAC·IDOR·업무분리
- ADR 12: 로그인·MFA·session·CSRF·OIDC
- 구현계획 13: Test pyramid와 Release Gate

그러나 시험의 공통 의미, 결과 상태, 증빙 방식과 “몇 개 통과”의 해석이 한 문서에 모여 있지 않았다. 이 ADR은 각 영역의 상세 기준을 대체하지 않고 공통 시험 규칙과 Release 승인 방식을 연결한다.

## 3. 쉬운 비유

Sec_AI를 보안검진센터라고 보면 시험 종류는 다음과 같다.

| 시험 | 쉬운 비유 |
|---|---|
| Unit | 자물쇠 하나가 제대로 잠기는지 확인 |
| Contract | 서류 양식과 봉인 번호가 약속과 같은지 확인 |
| Integration | 접수대·금고·전달시스템이 서로 제대로 연결되는지 확인 |
| E2E | 접수부터 공식 결과 조회까지 전체 모의훈련 |
| Security | 위조 신분증·변조 상자·권한 탈취를 실제로 시도 |
| Recovery | 전원·서버·디스크가 고장난 상황에서 복구훈련 |
| VMware | 실제 Windows 11 PC에서 수집과 판정이 맞는지 확인 |

한 종류만 통과해서는 충분하지 않다. 자물쇠 시험을 통과해도 접수 담당자가 다른 조직의 금고를 열 수 있다면 전체 보안은 실패다.

## 4. `Pytest 58개 통과`의 정확한 의미

2026-07-22의 구현 기준선은 다음과 같다.

```text
전체 Pytest 58개
├─ IMP-009 package archive 보안·변조 시험 43개
├─ RFC 8785 Canonical JSON·SHA-256 시험 9개
├─ API Health·Readiness 시험 3개
├─ Schema catalog 연결 시험 2개
└─ Python package import smoke 시험 1개
```

따라서:

- `43개 통과`는 package 보안검사에 집중한 시험이 모두 성공했다는 뜻이다.
- `58개 통과`는 위 43개를 포함한 현재 전체 Python 자동시험이 성공했다는 뜻이다.
- JSON Schema 8종과 valid/invalid example 14건 검증은 별도 Schema 명령 결과다.
- Ruff는 문법·코드 품질 검사이고 mypy는 type 검사다. 둘 다 중요하지만 단독으로 보안시험 통과를 의미하지 않는다.
- Container `healthy`는 process와 dependency 응답 확인이다. 인증·권한·데이터 무결성 보안시험을 대신하지 않는다.

아직 로그인, MFA, RBAC 업무 API, 실제 Collector, Audit Pack PC-07 판정, Object Lock·KMS·backup 복구가 구현되지 않았으므로 해당 보안시험은 58개에 포함되지 않는다.

## 5. 시험 결과 상태

| 상태 | 의미 | Gate 처리 |
|---|---|---|
| `PASS` | 실제 결과가 승인된 기대값과 같음 | 통과 후보 |
| `FAIL` | 기대값과 다르거나 보안 우회 재현 | 해당 Gate 실패 |
| `BLOCKED` | 환경·인증서·license·도구 부족으로 필수시험을 실행하지 못함 | PASS로 계산 금지 |
| `SKIPPED` | 범위 밖 또는 명시적으로 보류 | 사유·owner·기한 승인 필요 |
| `NOT-IMPLEMENTED` | 기능이 없어 아직 시험 대상이 아님 | 해당 기능 Release 진입 금지 |
| `FLAKY` | 같은 입력에서 결과가 비결정적 | FAIL과 동일하게 처리 |

실패한 보안시험을 재실행해 한 번 성공한 것만 남기지 않는다. 최초 실패, 원인, 수정 revision과 재시험 결과를 함께 보존한다.

## 6. Test pyramid

| 계층 | 목적 | 대표 대상 | 실행 시점 |
|---|---|---|---|
| Unit | 작은 함수의 경계와 오류 확인 | canonicalization, strict JSON, archive, rule | 모든 변경 |
| Contract | producer·consumer 약속 확인 | JSON Schema, Audit Pack, API DTO | 모든 변경 |
| Integration | 실제 제품 연결과 장애 확인 | PostgreSQL, AIStor, Redis, ClamAV | 관련 변경·Release |
| E2E | 전체 업무 흐름 확인 | package→검증→Finding→조회 | Release Gate |
| Security regression | 알려진 공격의 재발 방지 | traversal, IDOR, CSRF, replay | 모든 보안 변경 |
| Manual adversarial | 자동시험 밖의 우회 탐색 | 권한 조합, parser 차이, race | Pilot·RC |
| Recovery | 손실·장애 후 정합성 확인 | DB·object·key·queue 복구 | Pilot·정기훈련 |
| VMware | 실제 Windows 차이 확인 | Probe·권한상승·PC-01~18 | Collector Release |

Unit 시험 수가 많아도 Integration·E2E·권한·복구시험을 생략할 수 없다.

## 7. 보안 영역별 필수시험

### 7.1 Package·Upload

- 절대경로, drive path, `..`, backslash와 빈 path segment 거부
- duplicate path와 Windows 대소문자 충돌 거부
- symlink, special file, reparse point, directory entry 거부
- 암호화 ZIP, 중첩 archive, 비승인 compression 거부
- ZIP 전체·member·file count·해제 byte·compression ratio 제한
- UTF-8 외 encoding, BOM, duplicate JSON key, NaN·Infinity 거부
- Manifest 누락, 미등록 file, 누락 file, size·SHA-256 불일치 거부
- 무결성 실패 package에서 공식 Finding이 생성되지 않음
- ClamAV unavailable·timeout·malware에서 original 승격 금지
- request 중단·multipart 잔여·동시 upload의 정리와 용량 제한

### 7.2 인증·Session

- 정상 login, 잘못된 password, 존재하지 않는 account의 외부 오류가 일반화됨
- rate limit·lockout·credential stuffing 방어
- MFA 등록·검증·재등록·복구와 step-up
- session ID rotation, logout, revoke, 비밀번호 변경 후 기존 session 폐기
- 미사용 만료 30분과 최대 session 수명
- cookie `Secure`, `HttpOnly`, `SameSite`, scope와 cache-control
- CSRF token 누락·변조·다른 session token 재사용 거부
- WebAuthn RP ID·origin·challenge·counter 검증
- OIDC state·nonce·PKCE·issuer·audience·redirect URI 검증

인증 기능이 구현되기 전에는 이 항목을 PASS로 표시하지 않는다.

### 7.3 RBAC·업무분리

- 사용자·보안담당자·승인자·관리자의 허용 작업 확인
- 다른 organization·asset·job·finding UUID를 사용한 IDOR 거부
- URL, JSON API, HTMX fragment, SSE, download에 동일 권한 적용
- UI button을 숨기지 않아도 server가 권한 없는 요청을 거부
- 역할 변경·회수 즉시 session과 authorization에 반영
- 작성자와 승인자의 maker-checker 분리
- 관리자도 승인 없이 원본 증적을 열람·삭제하지 못함
- service identity가 자기 queue·bucket·DB 범위를 벗어나지 못함

### 7.4 Audit Pack·공식 판정

- 승인되지 않았거나 만료·폐기된 Pack 실행 거부
- Pack signature·hash·version·assignment 불일치 거부
- 허용 operator 외 DSL, code injection, dynamic import 거부
- 동일 input·Pack을 100회 실행해 동일 result hash 확인
- 부분 증적이 `PASS`로 바뀌지 않음
- 수집 실패는 `FAIL`이 아니라 승인된 `ERROR/REVIEW` 경계로 처리
- 사람·AI·관리자가 append-only Finding을 직접 덮어쓰지 못함
- AI 설명 변경이 공식 상태를 변경하지 못함

### 7.5 AIStor·증적

- public·anonymous list/get/put 거부와 host port 비공개
- service account별 최소권한과 cross-organization key 접근 거부
- original versioning·COMPLIANCE 1,095일과 파생자료 정책 확인
- root·일반 계정 모두 잠긴 version의 조기 삭제·변경 거부
- KMS/OpenBao seal·장애 시 평문 저장으로 우회하지 않음
- object exact version·size·SHA-256·retention과 PostgreSQL row 일치
- audit webhook 민감 header 제거와 장애 후 replay
- node·volume 손실 후 RPO 1시간·RTO 8시간 안의 복구
- 원본과 복구본 SHA-256 전수 일치

현재 AIStor license 기동과 합성 S3 PUT·GET·STAT·DELETE는 통과했지만 Object Lock·KMS·backup·CVE Gate는 아직 완료되지 않았다.

### 7.6 Queue·Worker

- Redis default user 비활성·named ACL·외부 port 차단
- Pickle·YAML·알 수 없는 content type과 미등록 task 거부
- message에는 ID와 version만 두고 secret·원본 증적을 넣지 않음
- scope가 다른 ID, 변조된 schema version과 replay message 거부
- 중복 delivery·Worker 종료·ACK 경계에서 Finding 중복 없음
- PostgreSQL Outbox와 업무상 멱등성 key로 상태가 수렴
- Redis 전체 손실 후 PostgreSQL 정본으로 reconciliation
- poison task와 최대 재시도 초과의 격리

### 7.7 Windows Collector

- 승인 Probe allowlist만 실행하고 임의 command·script 거부
- `shell=False`, timeout, output·process tree 제한
- 관리자 권한이 필요 없는 Probe는 표준 사용자로 실행
- 상승 단계·이유·수집 항목을 PC 사용자에게 사전 표시
- signed manifest의 asset·nonce·expiry·Probe version 검증
- Collector EXE·Probe bundle code signing과 tamper 거부
- secret·password·token·불필요한 개인정보 미수집
- offline package의 서명·제출자·replay 경계 검증
- clean Windows 11 VMware에서 PASS/FAIL/ERROR/REVIEW/N/A Fixture 재현

### 7.8 Web·API

- TLS, security header, CSP, frame·MIME·referrer 정책
- Host header, request size, content type, method와 rate 제한
- XSS, template injection, SQL injection, command injection 거부
- 민감 응답 `Cache-Control: no-store`
- 오류 응답에 stack trace, DB URL, path, secret이 없음
- upload/download filename과 content disposition 안전성
- OpenAPI·docs endpoint의 운영 공개 정책
- audit log에 credential·cookie·token·원본 증적을 기록하지 않음

### 7.9 공급망·Container

- Python dependency exact version·artifact hash·license 검토
- `pip-audit` 또는 승인 scanner 결과와 예외 승인
- container exact tag@digest, SBOM, provenance와 vulnerability scan
- project image 이름과 source revision·lock hash 연결
- non-root 가능 여부, read-only rootfs, capability drop, no-new-privileges
- secret이 image layer, build log, Git, SBOM, 이동 묶음에 없음
- base image·dependency 변경 후 전체 보안 회귀시험

Scanner가 로그인이나 network 문제로 실행되지 않으면 `BLOCKED`이며 “취약점 0건”으로 기록하지 않는다.

## 8. Test case ID

시험에는 변경되지 않는 ID를 사용한다.

```text
TC-PKG-001      package·archive
TC-AUTH-001     인증·MFA·session
TC-RBAC-001     권한·업무분리
TC-RULE-001     Audit Pack·공식 판정
TC-STORE-001    AIStor·KMS·보존
TC-QUEUE-001    Redis·Celery·Outbox
TC-COLLECT-001  Windows Collector
TC-API-001      Web·API
TC-SUPPLY-001   dependency·image 공급망
TC-RECOVERY-001 backup·restore·재해복구
```

시험 이름이나 구현 file이 변경돼도 같은 위험을 검증한다면 ID를 유지한다. 기대 결과의 의미가 바뀌면 test version과 관련 ADR을 함께 변경한다.

## 9. 시험 기록에 반드시 남길 정보

- Test case ID·version과 목적
- 연결된 위험·ADR·Control
- source revision 또는 source snapshot SHA-256
- Python lock SHA-256, container image tag·digest
- Schema·Audit Pack·migration version
- 실행 OS·architecture·Python·Docker·시험도구 version
- 합성 Fixture ID·hash와 민감도 분류
- 사전조건과 실행 명령
- 기대 결과와 실제 결과
- `PASS/FAIL/BLOCKED/SKIPPED` 상태
- 시작·종료 UTC와 실행자
- 민감정보가 제거된 log·report hash
- 실패 원인, 수정 revision, 재시험 연결
- 검토자·승인자

실제 password, token, cookie, private key, license 내용과 원본 증적 byte는 시험 보고서에 넣지 않는다.

## 10. Release별 최소 Gate

| Release | 최소 보안시험 Gate |
|---|---|
| `R0-WALKING-SKELETON` | Schema, canonical hash, package archive, Core health, 합성 data만 사용 |
| `R1-CORE-SERVICE` | local MFA, session, CSRF, RBAC, DB·AIStor·Queue integration, upload E2E |
| `R2-PC18-RULES` | PC-01~18 상태 Fixture, determinism, 부분 증적·적용성·Pack 승인 |
| `R3-WINDOWS-COLLECTOR-DEV` | EXE·개발 signing, privilege, tamper, offline replay와 현재 OS smoke |
| `R4-HOST-AI-UX-RC` | 현재 OS E2E·IDOR·recovery·prompt injection·인용·공식 상태 불변·사용성 |
| `R5-PILOT-RC` | clean VM·조직 signing·SmartScreen·Object Lock·KMS·backup·manual adversarial |

낮은 Release의 시험을 통과했다고 높은 Release의 기능을 운영에 공개하지 않는다.

## 11. 차단 기준

다음 중 하나라도 재현되면 관련 Release를 중단한다.

- 권한 없는 다른 조직·자산·원본 접근
- 인증·MFA·session revoke 우회
- package·Manifest·Pack hash·signature 우회
- 부분·오류 증적의 false `PASS`
- 공식 Finding 덮어쓰기 또는 AI의 공식 상태 변경
- credential·token·private key·원본 증적의 log·image·Git 유출
- COMPLIANCE retention·KMS fail-closed 우회
- 같은 입력의 비결정적 판정
- backup 복구 후 hash·version·DB 관계 불일치
- 필수 보안시험의 미승인 `BLOCKED/SKIPPED`

## 12. 자동화와 수동시험의 관계

자동시험은 반복 가능하고 빠르지만 설계자가 예상한 공격에 강하다. 수동 보안검토와 침투시험은 예상하지 못한 조합·업무흐름·race condition을 찾는 데 필요하다.

- 모든 수정: unit·contract·Ruff·mypy·secret·dependency 영향 확인
- 보안 기능 수정: 관련 negative regression 필수
- Release Candidate: integration·E2E·manual adversarial
- Pilot 전: 인증·RBAC·upload·저장·복구 중심 독립 검토
- 운영 중: 분기 복구훈련, 정기 vulnerability·권한·감사 검토

수동 침투시험 결과도 재현 가능한 항목은 자동 regression으로 전환한다.

## 13. 합성자료 원칙

- R0~초기 R1은 실제 기관 증적 대신 비식별 합성자료를 사용한다.
- malware 시험은 승인된 무해 test signature를 사용하고 실제 악성코드를 source에 보관하지 않는다.
- secret 탐지시험은 실제 credential과 형태가 다른 명시적 dummy marker를 사용한다.
- Object Lock 시험은 삭제할 수 없는 장기 test object를 불필요하게 만들지 않도록 전용 환경·bucket·용량 승인을 먼저 받는다.
- 실제 증적 시험은 retention·KMS·RBAC·감사·backup Gate를 통과한 격리된 Pilot에서만 수행한다.

## 15. 실행 명령

현재 공통 자동시험은 잠긴 개발 container에서 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\dev.ps1 -Action All
```

이 명령은 Python version, Pytest, Schema example, Ruff와 mypy를 실행한다. 향후 secret scan, dependency scan, container scan, integration·E2E는 별도 명령과 Release pipeline으로 추가한다. 한 명령이 모든 보안 Gate를 대신한다고 표시하지 않는다.

## 19. 플랫폼·Markdown·Agent/MCP 확장 시 추가 시험

향후 확장 기능은 다음 Gate를 기존 시험에 추가한다.

- Linux: Ubuntu/RHEL별 정상·취약·권한 부족·미지원 Fixture, sudo 최소권한, 명령 인자 주입, locale·timeout·출력 상한, 설정 diff 0
- Switch: Cisco/Aruba mock·lab 장비, read-only 권한, NETCONF/RESTCONF/REST schema 변조, paging·timeout·인증 실패, secret redaction, 구성 diff 0
- Markdown: Stored/Reflected/DOM XSS, raw HTML, 위험 URL scheme, event handler, broken stream block, CSP·Trusted Types, sanitizer fail-safe plain text
- Agent/MCP: prompt injection, confused deputy, tool scope 위조, replay·중복 실행, 승인 만료, TOCTOU, timeout, 부분 실패, rollback, 사후 재점검과 감사 누락
- AI 지식 보강: 실제값·공식 상태 불변, KISA/제조사/모델 일반지식 출처 등급, 충돌·근거 없음, 잘못된 citation과 비식별 경계

각 플랫폼은 false PASS 0, 승인 없는 변경 0, secret 노출 0과 재현 가능한 증적 hash를 Release Gate로 둔다. 상세 matrix는 제안 ADR 19와 발전 계획에서 관리한다.
